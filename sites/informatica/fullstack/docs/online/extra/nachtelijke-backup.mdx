# Online zetten: elke nacht een back-up

<Voorkennis items={[{site: 'linux', to: '/docs/terminal/zoeken', label: 'Uitvoer doorgeven met een pipe'}]} />

De back-up uit [les 34](site:fullstack/docs/online/server/backup) maak je met de hand, en dat vergeet je. Zet de stappen in een script, en laat de server dat elke nacht draaien.

## Het script

Maak op de server een map voor de back-ups, en een script:

```bash
mkdir ~/backups
nano ~/backup.sh
```

```bash
MAP=~/backups/$(date +%F)

mkdir -p "$MAP"
cd ~/gastenboek
docker compose stop
docker compose cp gastenboek:/app/data "$MAP/data"
docker compose start

cp ~/gastenboek/.env "$MAP"
cp -r ~/traefik "$MAP"
tar -czf "$MAP.tar.gz" -C ~/backups "$(basename "$MAP")"
rm -r "$MAP"

ls -1t ~/backups/*.tar.gz | tail -n +8 | xargs -r rm
```

Het middelste stuk ken je uit les 34. Nieuw is wat eromheen staat:

| Regel | Wat hij doet |
|:---|:---|
| `MAP=~/backups/$(date +%F)` | een variabele `MAP` met een map per dag: `date +%F` geeft de datum, zoals `2026-11-03` |
| `"$MAP"` | de waarde van `MAP`; de aanhalingstekens houden hem bij elkaar als er ooit een spatie in staat |
| `tar -czf "$MAP.tar.gz" …` | maakt van de map één ingepakt bestand, `2026-11-03.tar.gz` |
| `ls -1t … \| tail -n +8 \| xargs -r rm` | zet de back-ups op een rij, nieuwste eerst, slaat er zeven over, en gooit de rest weg |

Zo blijven de laatste zeven nachten bewaard, en loopt de schijf niet vol. Probeer het script zelf:

```bash
bash ~/backup.sh
ls ~/backups
```

Je site stopt een paar seconden, en daarna staat er een bestand met de datum van vandaag erin.

## Elke nacht met cron

**cron** is een dienst op elke Ubuntu-server die commando's op vaste tijden draait. Elke gebruiker heeft een eigen lijst, de *crontab*. Open de jouwe:

```bash
crontab -e
```

De eerste keer vraagt hij welke editor je wilt:

```text
Select an editor.  To change later, run 'select-editor'.
  1. /bin/nano        <---- easiest
  2. /usr/bin/vim.basic
```

Druk op Enter voor nano. Onder de regels met een `#` zet je één regel:

```text
30 3 * * * bash /home/sam/backup.sh >> /home/sam/backups/log.txt 2>&1
```

De eerste vijf velden zeggen wanneer:

| Veld | Hier | Betekenis |
|:---|:---|:---|
| minuut | `30` | op minuut 30 |
| uur | `3` | van 3 uur 's nachts |
| dag van de maand | `*` | elke dag |
| maand | `*` | elke maand |
| dag van de week | `*` | elke dag van de week |

Daarna komt het commando. Schrijf hele paden, met `/home/sam` en niet `~`. `>> …/log.txt 2>&1` zet alles wat het script zegt, ook de fouten, achter elkaar in `log.txt`. Daar lees je achteraf wat er 's nachts gebeurde.

Sla op en sluit nano; cron zegt `crontab: installing new crontab`. `crontab -l` toont je lijst.

## Nog steeds naar je laptop

De back-ups staan op dezelfde server als je site, en verdwijnen met hem. Haal ze daarom af en toe naar je laptop, in WSL:

```bash
mkdir -p ~/backup-gastenboek
scp 'sam@gastenboek.voorbeeld.nl:backups/*.tar.gz' ~/backup-gastenboek/
```

De aanhalingstekens zorgen dat de server de `*` invult, en niet je laptop. Uitpakken doe je met `tar -xzf` en de naam van het bestand.

<Gelukt>

De ochtend na de afgesproken tijd staat er in `~/backups` een bestand met de datum van die nacht, zoals `2026-11-03.tar.gz`, en eindigt `log.txt` met `Container gastenboek-gastenboek-1 Started`.

</Gelukt>

## Er gaat iets mis

### Er komt geen back-up, en geen log.txt

**Oorzaak:** de map `~/backups` bestaat niet. Cron kan `log.txt` dan niet maken, en start het script niet eens.

**Oplossing:** maak de map met `mkdir ~/backups`. De volgende nacht werkt het.

### De back-up komt op een ander uur

**Oorzaak:** de server rekent in UTC, de tijd van Greenwich, en niet in de tijd van Nederland. Typ `date`: staat er `UTC` achter, dan loopt de klok van de server een of twee uur achter op die van jou.

**Oplossing:** reken de tijd om, of laat hem staan: 3:30 UTC is in Nederland ook midden in de nacht.

### permission denied in log.txt

```text
permission denied while trying to connect to the docker API at unix:///var/run/docker.sock
```

**Oorzaak:** `sam` zit niet in de groep `docker`. Bij het inloggen met ssh merk je dat meteen, maar cron draait ook als jij er niet bij bent.

**Oplossing:** zet `sam` in de groep zoals in [les 28](site:fullstack/docs/online/server/docker), en probeer het script met de hand.

### No such file or directory in log.txt

```text
/home/sam/backup.sh: line 4: cd: /root/gastenboek: No such file or directory
```

**Oorzaak:** je zette de regel met `sudo crontab -e` in de lijst van `root`. Het script draait dan als `root`, en voor `root` is `~` de map `/root`.

**Oplossing:** haal de regel daar weg met `sudo crontab -e`, en zet hem in je eigen lijst met `crontab -e`, zonder `sudo`.

## Opdrachten

### Opdracht 1: Run - Elke nacht een back-up

Maak het script, probeer het met de hand, en zet het in je crontab. Wil je niet tot morgen wachten, zet de tijd dan eerst op twee minuten vanaf nu (kijk met `date` hoe laat de server het vindt), en zet hem daarna terug op 3:30. Wat staat er in `log.txt`?

<details>
<summary>Antwoord</summary>

Na de afgesproken minuut staat er een nieuw bestand in `~/backups`, en in `log.txt` staat wat `docker compose` zei:

```text
 Container gastenboek-gastenboek-1 Stopping
 Container gastenboek-gastenboek-1 Stopped
 gastenboek-gastenboek-1 Copying gastenboek-gastenboek-1:/app/data to /home/sam/backups/2026-11-03/data
 gastenboek-gastenboek-1 Copied gastenboek-gastenboek-1:/app/data to /home/sam/backups/2026-11-03/data
 Container gastenboek-gastenboek-1 Starting
 Container gastenboek-gastenboek-1 Started
```

Staat er een fout in, dan zie je hem hier.

</details>

### Opdracht 2: Modify - Portainer erbij

Heb je Portainer uit [les 37](site:fullstack/docs/online/extra/portainer), dan hoort `~/portainer` ook in de back-up. Pas het script aan.

<details>
<summary>Antwoord</summary>

Zet onder de regel voor `~/traefik`:

```bash
cp -r ~/portainer "$MAP"
```

</details>

### Opdracht 3: Investigate - Hoeveel ruimte?

Hoeveel ruimte nemen je back-ups in? Gebruik `du -sh ~/backups`. Hoeveel zou het zijn zonder de regel die er zeven bewaart, na een jaar?

<details>
<summary>Antwoord</summary>

Een gastenboek met een paar accounts en berichten is ingepakt een paar kilobyte, dus zeven back-ups zijn samen minder dan een megabyte. Na een jaar zonder opruimen zijn het er 365, en dat is voor een klein gastenboek nog steeds weinig. Maar je databases groeien, en een schijf die vol raakt, stopt je site. De regel kost niets, en je hoeft er nooit meer aan te denken.

</details>

Je site staat online en hij zorgt voor zichzelf. Loop met de controlelijst van [Beveilig je eigen project](site:fullstack/docs/veiligheid/eigen-project) nog een keer je code na: dat is nu code op internet.
