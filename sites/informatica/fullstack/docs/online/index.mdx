# Online zetten: zo werkt deze route

Je gastenboek draait op je eigen laptop, met `fastapi dev`. Alleen jij kunt erbij, en als je laptop dichtgaat, is hij weg. In deze route zet je hem op een server op internet, waar een klasgenoot hem vanaf zijn telefoon kan openen. Op een veilige manier: in een container die niet als `root` draait, achter een voordeur met HTTPS, en met alleen de deuren open die nodig zijn.

## Wat je al moet kunnen

- **De FastAPI-route**, minstens de basis. Je hebt een project in git, met een `.gitignore` die je databases en `.venv` buiten git houdt (uit [Een .gitignore en een nette zip](site:fullstack/docs/veiligheid/zichtbaar/gitignore)).
- **De route Veiligheid.** Een site op internet krijgt binnen een paar minuten bezoek van programma's die naar zwakke plekken zoeken. Wachtwoorden in gewone tekst, of een handleiding op `/docs` die iedereen alles laat proberen: los dat op voordat je online gaat.
- **Git en GitHub.** Je project reist als repository: je maakt commits, pusht ze naar GitHub, en haalt het op een andere computer op met `git clone` en `git pull`. Dat staat in de [git-lessen van de editor-cursus](site:editor/git). Elke les die een git-commando voor het eerst gebruikt, linkt naar de les waar het staat.
- **Linux.** Deze route legt geen Linux uit. Alles over de terminal, rechten, `sudo apt`, `nano`, diensten en `ssh` staat in de [Linux-cursus](site:linux/docs). Elke les zegt welke Linux-les je nodig hebt.

## Waar je werkt

| Deel | Waar | Wat je doet |
|:---|:---|:---|
| Op Windows | je laptop, in VS Code | `fastapi run`, `requirements.txt`, een README, en je project in een verse map |
| In Linux | Ubuntu in WSL op je laptop, en vanaf hier alleen nog daar | git en je project in Ubuntu, en je site met `fastapi run` in Linux |
| In een container | Ubuntu in WSL | Docker: een image, een container, een volume, Compose, en Traefik als voordeur |
| Op een echte server | een server op internet | inloggen, de deuren dicht, je site erop, HTTPS, een nieuwe versie uitrollen, een back-up, bijwerken |
| Extra | de server, en via een tunnel | je containers bekijken met Portainer, en elke nacht een back-up |

Vanaf het tweede deel heb je Ubuntu in WSL nodig ([WSL installeren](site:linux/docs/wsl/installeren)). Daar kan niets stuk en kost het niets. In les 9 haal je je project naar Ubuntu, en daarna werk je alleen nog daar: in VS Code vanuit Ubuntu, met git en Docker in Ubuntu. Wat in WSL werkt, werkt op de server ook: daar draait dezelfde Linux en dezelfde Docker, met dezelfde bestanden.

Elke les is één stap, en eindigt met een groen blok: **Gelukt als je dit ziet**. Zie je dat, vink dan **Het werkt** aan. Op de kaart hieronder staat dan een vinkje achter die stap, zodat je ziet hoe ver je bent. Lukt het niet, dan staat onder het blok wat er meestal misgaat.

Voor het vierde deel heb je een server nodig. Vraag je docent of de school er een heeft. Anders huur je er een voor een paar euro per maand bij een hostingbedrijf; dat mag alleen met toestemming van een ouder of verzorger, en zeg hem op als je klaar bent.
