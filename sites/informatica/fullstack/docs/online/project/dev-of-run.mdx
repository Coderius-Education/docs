# Online zetten: fastapi dev of fastapi run

Tot nu toe startte je je server met `fastapi dev`. Dat is een server voor jou, de ontwikkelaar (*developer*). Voor bezoekers is er een tweede:

```bash
fastapi run main.py
```

Typ het in de terminal van VS Code, in je project. Je site doet het precies zoals met `dev`. De verschillen staan in de eerste regels die de terminal laat zien. Met `fastapi dev`:

```text
 ⚡️ Starting FastAPI in development mode
 🌐 Server started at http://127.0.0.1:8000
 ▕  Will watch for changes in these directories:
```

En met `fastapi run`:

```text
 ⚡️ Starting FastAPI in production mode
 🌐 Server started at http://0.0.0.0:8000
```

*Production* is de stand voor echte bezoekers. Open je site op `http://127.0.0.1:8000`, net als altijd. Klik niet op het adres in de terminal: `0.0.0.0` is geen adres om naartoe te gaan, en je browser op Windows komt er niet.

De eerste keer opent Windows ook een venster van de firewall, met de vraag of Python toegang mag hebben tot het netwerk. Klik op **Annuleren**. Je hebt het niet nodig: op je eigen laptop werkt `127.0.0.1` toch. Met **Toegang toestaan** kan iedereen op hetzelfde wifi bij je site, en dat wil je nu niet.

Er zijn twee dingen anders.

## Twee verschillen

| | `fastapi dev` | `fastapi run` |
|:---|:---|:---|
| Je verandert `main.py` | de server start vanzelf opnieuw | de server merkt niets |
| Luistert op | `127.0.0.1`: alleen deze computer | `0.0.0.0`: elk netwerk van deze computer |

Opnieuw starten bij elke wijziging is handig als je bouwt. Op een server is het een risico: een half opgeslagen bestand zet je site plat, en het opletten kost rekenkracht. Daar start je de server zelf opnieuw als je klaar bent. Met `dev` staat er daarom `Will watch for changes`, met `run` niet.

Het adres zegt wie er bij je server kan. `127.0.0.1` is "deze computer", en daar komt niemand anders bij. `0.0.0.0` betekent: luister op elk netwerk waar deze computer aan hangt. Op een server is dat internet.

## Zelf kiezen waar hij luistert

Met `--host` en `--port` kies je het adres zelf:

```bash
fastapi run main.py --host 127.0.0.1 --port 8000
```

Op je laptop wil je dat: je site is nog niet klaar voor bezoekers, en op het wifi van school kan dan niemand meekijken. Straks draait je site in een **container**, een afgeschermd stukje Linux. Daar is het andersom: de container is zijn eigen kleine computer, en dan moet hij juist op `0.0.0.0` luisteren om van buiten de container bereikbaar te zijn. Dat zie je in [les 6](site:fullstack/docs/online/docker/container).

`fastapi run` geeft je handleiding op `/docs` ook aan iedereen. Die heb je in de route Veiligheid uitgezet ([Wat je server laat zien](site:fullstack/docs/veiligheid/zichtbaar/uitzetten)); doe dat nu als je het nog niet deed.

## Er gaat iets mis

### Address already in use

```text
[Errno 10048] error while attempting to bind on address ('0.0.0.0', 8000): only one usage of each socket address (protocol/network address/port) is normally permitted
```

**Oorzaak:** er draait al een server op poort 8000, vaak je eigen `fastapi dev` in een andere terminal.

**Oplossing:** stop die eerst met Ctrl+C, of kies een andere poort met `--port 8001`.

### De pagina op 0.0.0.0 laadt niet

Je klikte op `http://0.0.0.0:8000` in de terminal, en de browser zegt dat het adres ongeldig is of niet bereikbaar.

**Oorzaak:** `0.0.0.0` betekent voor een server "luister overal". Als adres om naartoe te gaan, bestaat het niet.

**Oplossing:** open `http://127.0.0.1:8000`.

### Je klikte op Toegang toestaan

**Oorzaak:** bij de eerste `fastapi run` vroeg de firewall van Windows of Python het netwerk op mag, en je stond het toe. Nu kan iedereen op hetzelfde wifi bij je site als hij draait met `fastapi run`.

**Oplossing:** start je site op je laptop met `--host 127.0.0.1`, of met `fastapi dev`. Wil je de toestemming intrekken, zoek dan in het startmenu naar **Een app toestaan via Windows Firewall** en haal de vinkjes bij Python weg.

## Opdrachten

### Opdracht 1: Run - Het verschil zien

Start je project met `fastapi run main.py`, verander een tekst in `main.py`, en herlaad je browser. Stop en start de server, en herlaad nog een keer.

<details>
<summary>Antwoord</summary>

Na de eerste keer herladen zie je de oude tekst, na de herstart de nieuwe. Een template (`templates/…html`) werkt anders: Jinja leest een template opnieuw als het bestand veranderd is, dus daar zie je een wijziging wel zonder herstart. Python-code in `main.py` nooit.

</details>

### Opdracht 2: Investigate - Waar staat het in de terminal?

Start je project één keer met `fastapi dev main.py` en één keer met `fastapi run main.py --host 127.0.0.1`. Welke regels in de terminal laten de twee verschillen uit de tabel zien?

<details>
<summary>Antwoord</summary>

Het adres staat bij `Server started at`: met `dev` en met `--host 127.0.0.1` is dat `http://127.0.0.1:8000`, zonder `--host` was het `http://0.0.0.0:8000`. Het herladen zie je aan `Will watch for changes in these directories`: die regel staat er alleen bij `dev`. Bovenaan staat ook nog `development mode` of `production mode`.

</details>
