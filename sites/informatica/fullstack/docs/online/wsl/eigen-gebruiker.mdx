# Online zetten: een eigen gebruiker voor je site

<Voorkennis items={[{site: 'linux', to: '/docs/terminal/rechten', label: 'Eigenaar, rechten en root'}, {site: 'linux', to: '/docs/wsl/apt', label: 'sudo'}]} />

In de route Veiligheid zag je hoe een bezoeker iets met je server doet wat jij niet bedoelde. Stel dat er toch een gat in je site zit, en iemand krijgt je server zover dat hij een commando uitvoert. Dan doet dat commando wat de gebruiker mag die je server startte.

Start je hem als jezelf, dan kan dat veel: je ssh-sleutels lezen, je andere projecten veranderen, en met `sudo` misschien de hele computer. Daarom krijgt je site een eigen gebruiker, die alleen bij zijn eigen map kan.

## De gebruiker maken

```bash
sudo adduser --system --group --home /srv/gastenboek gastenboek
```

- `--system` maakt een gebruiker voor een programma: zonder wachtwoord, en niemand kan er met ssh als inloggen.
- `--group` geeft hem een eigen groep met dezelfde naam.
- `--home /srv/gastenboek` geeft hem een eigen map. Op Linux staat wat een server aanbiedt bij afspraak in `/srv` (*serve*).

## Je project in zijn map

Je werkt nu een tijdje als `gastenboek`. Met `sudo -u` voer je een commando uit als een andere gebruiker; hier is dat commando een nieuwe terminal, `bash`:

```bash
sudo -H -u gastenboek bash
whoami
```

```text
gastenboek
```

De `-H` zet de thuismap op die van `gastenboek`. Haal je project op en maak de virtual environment, net als in [les 2](site:fullstack/docs/online/wsl/project-in-linux), maar nu in `/srv/gastenboek/app`:

```bash
cd /srv/gastenboek
git clone https://github.com/sam/gastenboek.git app
cd app
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/fastapi run main.py --host 127.0.0.1
```

`source .venv/bin/activate` heb je niet nodig: als je het programma met zijn hele pad start (`.venv/bin/fastapi`), gebruikt het de Python van die virtual environment.

Open `http://127.0.0.1:8000` op Windows. Je site werkt, maar hij draait nu als `gastenboek`. Stop hem met Ctrl+C. Blijf nog even `gastenboek` voor de vraag hieronder.

## Wat gastenboek wel en niet kan

| | `gastenboek` |
|:---|:---|
| zijn eigen code en databases in `/srv/gastenboek` | lezen en schrijven |
| jouw thuismap | niets |
| instellingen in `/etc` | lezen, niet veranderen |
| `sudo` | niet: hij staat niet in de groep `sudo` en heeft geen wachtwoord |

Je site kan dus zijn eigen bestanden veranderen, maar niet de rest van de computer. Een slot dat helemaal dicht is, is het niet: wie een gat in je site vindt, kan nog steeds bij de berichten en accounts in de databases. Daarom blijft de route Veiligheid nodig. Deze stap zorgt dat het daarbij blijft.

## Er gaat iets mis

### Permission denied in /srv/gastenboek

```text
bash: cd: /srv/gastenboek: Permission denied
```

**Oorzaak:** je bent nog jezelf, niet `gastenboek`. `/srv/gastenboek` heeft de rechten `drwxr-x---` en is van `gastenboek`: jij mag er niet eens in kijken.

**Oplossing:** kijk met `whoami` wie je bent, en start eerst `sudo -H -u gastenboek bash`.

### This account is currently not available

```text
This account is currently not available.
```

**Oorzaak:** je typte `sudo su gastenboek` of `sudo -i -u gastenboek`. Die starten de terminal die bij de gebruiker hoort, en een systeemgebruiker heeft bewust geen terminal.

**Oplossing:** zeg erbij welke terminal je wilt: `sudo -H -u gastenboek bash`.

### Je repository is privé

**Oorzaak:** `gastenboek` heeft geen sleutel voor GitHub, en een wachtwoord werkt daar niet meer.

**Oplossing:** oefen in WSL met een kopie van je project uit [les 2](site:fullstack/docs/online/wsl/project-in-linux), en geef die aan `gastenboek`. Voor de echte server staat een betere manier in [les 7](site:fullstack/docs/online/server/huren).

```bash
sudo cp -r ~/gastenboek /srv/gastenboek/app
sudo rm -r /srv/gastenboek/app/.venv
sudo chown -R gastenboek:gastenboek /srv/gastenboek/app
```

Maak de virtual environment daarna opnieuw, als `gastenboek`. Een `.venv` kun je niet kopiëren: hij onthoudt het pad waar hij gemaakt is.

## Opdrachten

### Opdracht 1: Run - Jouw site als gastenboek

Maak de gebruiker, zet je project in `/srv/gastenboek/app` en start het daar als `gastenboek`. Schrijf een bericht. Van wie is `gastenboek.db`?

<details>
<summary>Tip</summary>

Met `ls -l` zie je de eigenaar van een bestand. Doe je het als jezelf, dan heb je `sudo` nodig: je mag zelf niet in die map kijken.

</details>

<details>
<summary>Antwoord</summary>

```bash
sudo ls -l /srv/gastenboek/app
```

`gastenboek.db` is van `gastenboek`, want die gebruiker maakte het bestand toen je server het eerste bericht opsloeg. Zonder `sudo` krijg je `Permission denied`: de map van je site is net zo afgeschermd als jouw thuismap.

</details>

### Opdracht 2: Investigate - Kan gastenboek sudo?

Typ als `gastenboek`: `sudo whoami`. Wat gebeurt er, en waarom is dat goed?

<details>
<summary>Antwoord</summary>

`sudo` vraagt om het wachtwoord van `gastenboek`, en dat bestaat niet. Wat je ook typt, het lukt niet. Zo kan iemand die via je site als `gastenboek` binnenkomt, geen beheerder worden. Stop met Ctrl+C.

</details>
