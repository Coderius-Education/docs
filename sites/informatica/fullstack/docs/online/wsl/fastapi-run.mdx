# Online zetten: van fastapi dev naar fastapi run

Tot nu toe startte je je server met `fastapi dev`. Dat is een server voor jou, de ontwikkelaar (*developer*). Voor bezoekers is er een tweede:

```bash
fastapi run main.py
```

Start hem in Ubuntu, in je project, met de virtual environment aan. Je site doet het precies zoals met `dev`. De verschillen zie je pas als je ernaar zoekt.

## Twee verschillen

| | `fastapi dev` | `fastapi run` |
|:---|:---|:---|
| Je verandert `main.py` | de server start vanzelf opnieuw | de server merkt niets |
| Luistert op | `127.0.0.1`: alleen deze computer | `0.0.0.0`: elk netwerk van deze computer |

Opnieuw starten bij elke wijziging is handig als je bouwt. Op een server is het een risico: een half opgeslagen bestand zet je site even plat, en het opletten kost rekenkracht. Daar start je de server zelf opnieuw als je klaar bent.

Het adres zegt wie er bij je server kan. `127.0.0.1` is "deze computer", en daar komt niemand anders bij. `0.0.0.0` betekent: luister op elk netwerk waar deze computer aan hangt. Op een server is dat internet.

## Zelf kiezen waar hij luistert

Met `--host` kies je het adres zelf:

```bash
fastapi run main.py --host 127.0.0.1 --port 8000
```

Dat lijkt een stap terug: wie zet een server online op een adres waar niemand bij kan? Toch doe je dat straks. In [les 6](site:fullstack/docs/online/wsl/voordeur) komt er een ander programma voor je server te staan, dat bezoekers ontvangt en doorgeeft. Dan hoeft alleen dat programma bij je server te kunnen.

## Kijken wie luistert

In Linux zie je met `ss` welke programma's op welk adres luisteren. Start `fastapi run main.py` in de ene Ubuntu-terminal, open een tweede en typ:

```bash
ss -tln
```

```text
State   Recv-Q  Send-Q   Local Address:Port   Peer Address:Port
LISTEN  0       2048           0.0.0.0:8000        0.0.0.0:*
```

`-t` toont verbindingen over TCP (wat het web gebruikt), `-l` alleen wie luistert, en `-n` toont adressen als getallen. Er kunnen meer regels staan; de regel met `:8000` is die van jou.

## Er gaat iets mis

### Address already in use

```text
[Errno 98] error while attempting to bind on address ('0.0.0.0', 8000): address already in use
```

**Oorzaak:** er draait al een server op poort 8000, vaak je eigen `fastapi dev` in een andere terminal.

**Oplossing:** stop die eerst met Ctrl+C, of kies een andere poort met `--port 8001`.

### De site werkt op 127.0.0.1, maar niet vanaf een ander apparaat

**Oorzaak:** in WSL zit Linux achter je Windows-computer. Een ander apparaat op het netwerk ziet alleen Windows, ook als je server op `0.0.0.0` luistert.

**Oplossing:** dat is voor nu goed. Op een echte server is er geen Windows ertussen; daar komt het in [les 7](site:fullstack/docs/online/server/huren).

## Opdrachten

### Opdracht 1: Run - Het verschil zien

Start je project met `fastapi run main.py`, verander een tekst in een template of in `main.py`, en herlaad je browser. Stop en start de server, en herlaad nog een keer.

<details>
<summary>Antwoord</summary>

Na de eerste keer herladen zie je de oude tekst, na de herstart de nieuwe. Een template (`templates/…html`) kan anders werken: Jinja leest een template opnieuw als het bestand veranderd is, dus daar zie je een wijziging soms wel zonder herstart. Python-code in `main.py` nooit.

</details>

### Opdracht 2: Investigate - Twee adressen

Start de server één keer zonder `--host` en één keer met `--host 127.0.0.1`. Kijk elke keer met `ss -tln` wat er bij poort 8000 staat.

<details>
<summary>Antwoord</summary>

Zonder `--host` staat er `0.0.0.0:8000`, met `--host 127.0.0.1` staat er `127.0.0.1:8000`. In je browser op Windows werkt `http://127.0.0.1:8000` allebei de keren: WSL geeft het verkeer van Windows door aan Linux.

</details>
