# Online zetten: Docker installeren

<Voorkennis items={[{site: 'linux', to: '/docs/wsl/installeren', label: 'Ubuntu in WSL'}, {site: 'linux', to: '/docs/wsl/apt', label: 'Installeren met sudo apt'}, {site: 'linux', to: '/docs/wsl/diensten', label: 'Een dienst met systemctl'}]} />

Op je laptop draait je site met Windows, jouw Python en jouw virtual environment. Een server heeft Linux, een andere Python en geen virtual environment. Elk verschil is een kans dat iets op je laptop werkt en op de server niet.

**Docker** haalt die verschillen weg. Je pakt je site in, samen met Linux, Python en alle packages, in één pakket: een **image**. Dat image draait overal hetzelfde, op je laptop en op de server. Een draaiend image heet een **container**. Van één image kun je meer containers starten, net zoals je één programma twee keer kunt openen.

Een server draait Linux, dus je oefent in Linux: in Ubuntu in WSL.

## Installeren

Open Ubuntu en installeer Docker en git:

```bash
sudo apt update
sudo apt install docker.io docker-compose-v2 docker-buildx git
```

Dat zijn vier pakketten van Ubuntu zelf:

- `docker.io`: Docker, met het commando `docker` en de dienst die de containers draait;
- `docker-compose-v2`: `docker compose`, voor [les 9](site:fullstack/docs/online/docker/compose);
- `docker-buildx`: het onderdeel dat images bouwt;
- `git`: om je project op te halen.

Docker draait als dienst, en die start meteen. Controleer het:

```bash
systemctl status docker
```

Staat er `active (running)`, dan is het goed. Sluit de status met `q`.

## Jezelf toegang geven

Alleen `root` en de groep `docker` mogen Docker gebruiken. Zet jezelf in die groep:

```bash
sudo usermod -aG docker $USER
```

`$USER` is je eigen naam. Een nieuwe groep telt pas als je opnieuw inlogt. Sluit Ubuntu, typ in PowerShell `wsl --terminate Ubuntu-24.04`, en open Ubuntu opnieuw. Met `groups` zie je nu ook `docker` staan.

:::caution[De groep docker is bijna root]
Wie Docker mag gebruiken, kan een container starten die alles op de computer mag. In de groep `docker` zitten is dus bijna hetzelfde als `root` zijn. Zet er alleen jezelf in, en op een server alleen de beheerder.
:::

## Je eerste container

```bash
docker run hello-world
```

```text
Unable to find image 'hello-world:latest' locally
latest: Pulling from library/hello-world
...
Hello from Docker!
This message shows that your installation appears to be working correctly.

To generate this message, Docker took the following steps:
 1. The Docker client contacted the Docker daemon.
 2. The Docker daemon pulled the "hello-world" image from the Docker Hub.
    (amd64)
 3. The Docker daemon created a new container from that image which runs the
    executable that produces the output you are currently reading.
 4. The Docker daemon streamed that output to the Docker client, which sent it
    to your terminal.
```

De tekst legt zelf uit wat er gebeurde. Het commando `docker` vroeg de dienst (de *daemon*) om het image `hello-world` te draaien. Dat image stond er nog niet, dus de dienst haalde het van **Docker Hub**, een website vol images. Daarna startte hij er een container van, en die zette deze tekst op je scherm en stopte.

Bekijk wat er nu op je computer staat:

```bash
docker images
docker ps -a
```

`docker images` toont het image. `docker ps -a` toont de container, met `Exited (0)` bij de status: hij is klaar, zonder fout. Zonder `-a` zie je alleen containers die nog draaien.

## Er gaat iets mis

### permission denied

```text
permission denied while trying to connect to the docker API at unix:///var/run/docker.sock
```

**Oorzaak:** je zit niet in de groep `docker`, of je bent nog niet opnieuw ingelogd sinds `usermod`.

**Oplossing:** typ `groups`. Staat `docker` er niet bij, doe dan de stap van **Jezelf toegang geven** opnieuw, en vergeet `wsl --terminate Ubuntu-24.04` niet. Zet geen `sudo` voor elk `docker`-commando: dan maak je alles als `root`, en dat geeft later problemen met de rechten van je bestanden.

### failed to connect to the docker API

```text
failed to connect to the docker API at unix:///var/run/docker.sock; check if the path is correct and if the daemon is running: dial unix /var/run/docker.sock: connect: no such file or directory
```

**Oorzaak:** de dienst van Docker draait niet.

**Oplossing:** start hem, en laat hem voortaan vanzelf starten:

```bash
sudo systemctl enable --now docker
```

### `toomanyrequests`

Docker haalt een image niet op, en in de melding staat `toomanyrequests` of `429 Too Many Requests`.

**Oorzaak:** Docker Hub geeft per internetadres een beperkt aantal images per uur. Op school delen alle laptops één adres, dus de hele klas telt samen.

**Oplossing:** wacht een uur, of maak een gratis account op Docker Hub en log in met `docker login`. Dan telt je eigen account, niet het adres van school.

## Opdrachten

### Opdracht 1: Run - Docker op je laptop

Installeer Docker, zet jezelf in de groep `docker`, en draai `hello-world` zonder `sudo`.

<details>
<summary>Antwoord</summary>

```bash
sudo apt update
sudo apt install docker.io docker-compose-v2 docker-buildx git
sudo usermod -aG docker $USER
```

Daarna `wsl --terminate Ubuntu-24.04` in PowerShell, Ubuntu opnieuw openen, en `docker run hello-world`. Je ziet `Hello from Docker!`.

</details>

### Opdracht 2: Investigate - Een Linux in een paar seconden

De tekst van `hello-world` stelt iets voor: `docker run -it ubuntu bash`. Doe het, en typ in de container `cat /etc/os-release` en `whoami`. Typ daarna `exit`. Wat is dit, en wat zegt `docker ps -a` erna?

<details>
<summary>Tip</summary>

`-it` betekent: koppel deze container aan je toetsenbord en je scherm, zodat je erin kunt typen.

</details>

<details>
<summary>Antwoord</summary>

Je prompt verandert in iets als `root@3f2a9c1e7b54:/#`: je zit in een container met een eigen Ubuntu, als `root`. `cat /etc/os-release` laat zien welke Ubuntu het image heeft; dat hoeft niet dezelfde te zijn als die van WSL. Na `exit` stopt de container, en `docker ps -a` toont hem met `Exited`. In een paar seconden had je een hele Linux, en die is weg zodra je hem weggooit met `docker rm`. Dat zie je in [les 6](site:fullstack/docs/online/docker/container).

</details>
