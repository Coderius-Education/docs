# Online zetten: niet als root

<Voorkennis items={[{site: 'linux', to: '/docs/terminal/rechten', label: 'Rechten op bestanden en mappen'}]} />

Start je container, en vraag wie je site draait:

```bash
docker run -d --name gastenboek -p 8000:8000 gastenboek
docker exec gastenboek whoami
```

```text
root
```

`docker exec` voert een commando uit in een container die al draait. Het antwoord is `root`: je site mag alles in de container. Dat is een risico. Zit er een gat in je code, zoals een bestandsnaam van een bezoeker uit [Invoer controleren](site:fullstack/docs/veiligheid/invoer/paden), dan kan wie dat gat vindt ook alles. Hij kan je code veranderen, programma's installeren, en zoeken naar een weg uit de container.

Een webserver hoort daarom te draaien als een gewone gebruiker, die zo weinig mag als kan.

## Een eigen gebruiker in het image

Zet in je Dockerfile, na `COPY . .`, twee regels:

```dockerfile
RUN useradd --system app
USER app
```

`useradd --system` maakt een gebruiker `app` zonder wachtwoord en zonder thuismap: niemand logt als hem in. `USER app` zegt dat alles hierna als `app` draait, ook de `CMD`.

## Een map voor de databases

Je geeft de databases een eigen map, `data`, die van `app` is. Dat zijn drie veranderingen.

**1. In `main.py`** komt elke database in `data/`. Vervang in VS Code met Ctrl+H overal `SqliteDict("` door `SqliteDict("data/`, met **Replace All**. Dan staat er `SqliteDict("data/gastenboek.db")`, `SqliteDict("data/gebruikers.db")`, en zo voor elke database. Zet bovenaan, onder je imports, een regel die de map maakt als hij er nog niet is:

```python
import os

from fastapi import FastAPI
from sqlitedict import SqliteDict

os.makedirs("data", exist_ok=True)

app = FastAPI()
```

SqliteDict maakt een bestand, maar geen map. Zonder die regel start je project zonder Docker niet meer, zoals in [les 11](site:fullstack/docs/online/linux/run).

**2. In de Dockerfile** maak je de map, en geef je hem aan `app`. Verander de `RUN` van hierboven:

```dockerfile
RUN useradd --system app && mkdir data && chown app data
USER app
```

`&&` voert de volgende stap alleen uit als de vorige lukte. Dit gebeurt nog als `root`, want het staat vóór `USER`. Je hele Dockerfile is nu:

```dockerfile
FROM python:3.13-slim

WORKDIR /app

COPY requirements.txt .
RUN python -m pip install -r requirements.txt

COPY . .

RUN useradd --system app && mkdir data && chown app data
USER app

CMD ["fastapi", "run", "main.py", "--port", "8000"]
```

**3. In `.dockerignore`** komt `data/`, zodat je eigen testdatabases niet in het image komen:

```text
.venv
__pycache__
.git
*.db
data/
```

In `.gitignore` hoeft niets bij: `*.db` geldt daar ook voor bestanden in een map.

Bouw en start opnieuw, en kijk:

```bash
docker rm -f gastenboek
docker build -t gastenboek .
docker run -d --name gastenboek -p 8000:8000 gastenboek
docker exec gastenboek whoami
```

<Gelukt>

`docker exec gastenboek whoami` zegt nu:

```text
app
```

En in je gastenboek op `http://127.0.0.1:8000` kun je een account maken en een bericht schrijven, zonder 500.

</Gelukt>

Kijk met `docker exec gastenboek ls -l data` waar de databases staan, en van wie ze zijn.

## Er gaat iets mis

### unable to open database file

```text
sqlite3.OperationalError: unable to open database file
```

**Oorzaak:** een database staat nog niet in `data/`, en `app` mag in `/app` niets maken. Of de map `data` bestaat niet.

**Oplossing:** zoek in `main.py` naar `SqliteDict("` zonder `data/` erachter. Staat het overal goed, controleer dan of de regel met `os.makedirs` er staat.

### Permission denied: 'data'

De container stopt meteen, en `docker logs gastenboek` eindigt met:

```text
PermissionError: [Errno 13] Permission denied: 'data'
```

**Oorzaak:** de Dockerfile maakt de map `data` niet. Dan probeert `os.makedirs` hem te maken, als `app`, in de map van `root`.

**Oplossing:** zet `&& mkdir data && chown app data` achter `useradd` in je Dockerfile, en bouw opnieuw.

### cannot create directory ‘data’: File exists

```text
mkdir: cannot create directory ‘data’: File exists
```

**Oorzaak:** de map `data` uit je project kwam met `COPY . .` mee in het image, met je testdatabases erin.

**Oplossing:** zet `data/` in `.dockerignore`, en bouw opnieuw.

## Opdrachten

### Opdracht 1: Run - Jouw site als app

Doe de drie veranderingen in je eigen project, bouw het image, en laat zien dat je site draait als `app` en dat registreren en schrijven werken. Commit en push daarna.

<details>
<summary>Antwoord</summary>

`docker exec gastenboek whoami` geeft `app`, en `docker exec gastenboek ls -l data` toont je databases met `app` als eigenaar. In je projectmap in Ubuntu komen ze niet: ze staan in de container. `git status` toont daarom alleen `main.py`, de Dockerfile en `.dockerignore` als veranderd.

</details>

### Opdracht 2: Investigate - Wat mag app niet?

Probeer als `app` je code te veranderen: `docker exec gastenboek touch main.py`. Wat zegt de container? Wat betekent dat voor iemand die een gat in je site vindt?

<details>
<summary>Antwoord</summary>

```text
touch: cannot touch 'main.py': Permission denied
```

`main.py` is van `root`, en `app` mag hem lezen maar niet veranderen. Vindt iemand een gat in je site, dan kan hij je databases lezen en veranderen, want die zijn van `app`. Maar je code aanpassen, of iets installeren, lukt hem niet. Dat is minder erg, en het is precies wat je met een eigen gebruiker wilde.

</details>
