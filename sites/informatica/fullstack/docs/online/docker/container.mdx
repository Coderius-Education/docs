# Online zetten: een container draaien

Je image staat klaar. Je start er een container van, en opent je site in je browser, nu uit de container.

## Starten

```bash
docker run -p 8000:8000 gastenboek
```

Je ziet bijna dezelfde regels als bij `fastapi run` in [les 11](site:fullstack/docs/online/linux/run), met `production mode` en `http://0.0.0.0:8000`. Ze zien er wat kaler uit: Docker geeft de container geen echt scherm, en dan laat fastapi de opmaak weg. Open `http://127.0.0.1:8000` in je browser op Windows.

<Gelukt>

Je site opent, nu uit een container. In de terminal komt bij elk verzoek een regel met `GET` en `200 OK` bij, en je gastenboek heeft nog geen berichten.

</Gelukt>

### Een leeg gastenboek

Het gastenboek is leeg. De databases uit les 11 staan nog in je projectmap, maar `.dockerignore` hield ze buiten het image. Een container begint met wat er in het image staat, en daar zit geen enkele database in.

Stop de container met Ctrl+C.

## Een poort naar buiten

Een container is afgeschermd: van buiten kan niemand erbij, ook jij niet. Met `-p` (*publish*) maak je één deur open. `-p 8000:8000` betekent: wat op poort 8000 van deze computer binnenkomt, gaat naar poort 8000 in de container. Het eerste getal is van de computer, het tweede van de container.

Nu zie je ook waarom de container op `0.0.0.0` luistert. Een verzoek via `-p` komt de container binnen over zijn eigen netwerk. Luisterde je site op `127.0.0.1`, dan nam hij alleen verzoeken aan van binnen de container zelf, en kwam jouw browser nooit binnen.

<Voorspel soort="Controlevraag" vraag="Je start je container met docker run -p 9000:8000 gastenboek. Welk adres open je in je browser?">
  <Keuze uitleg="Het tweede getal is de poort in de container. Komt je browser daar rechtstreeks?">Net als eerst: http://127.0.0.1:8000</Keuze>
  <Keuze goed uitleg="Het eerste getal is de poort van je computer. Docker stuurt wat daar binnenkomt door naar poort 8000 in de container.">Poort 9000 van je computer: http://127.0.0.1:9000</Keuze>
  <Keuze uitleg="0.0.0.0 is het adres waarop je site in de container luistert, geen adres om te openen.">Het adres uit de terminal, met 9000: http://0.0.0.0:9000</Keuze>
  <Uitleg>

  Je browser praat met je computer, dus met het eerste getal. In de container luistert je site nog steeds op 8000, en dat hoeft niet te veranderen. Zo kun je twee containers die allebei op 8000 luisteren, naast elkaar draaien: `-p 8000:8000` en `-p 9000:8000`.

  </Uitleg>
</Voorspel>

## Er gaat iets mis

### port is already allocated

```text
docker: Error response from daemon: failed to set up container networking: driver failed programming external connectivity on endpoint …: Bind for 0.0.0.0:8000 failed: port is already allocated
```

Draait er een ander programma dan Docker op die poort, dan eindigt de regel met `address already in use`.

**Oorzaak:** poort 8000 van deze computer is al bezet, door een andere container of een ander programma. Bijvoorbeeld je site uit les 11, als die nog draait met `fastapi run`.

**Oplossing:** stop dat programma met Ctrl+C in zijn terminal, of kies een andere poort voor de computer: `-p 8001:8000`. Docker maakt de container wel aan voordat het misgaat; zulke containers ruim je op in [les 21](site:fullstack/docs/online/docker/compose).

### De browser krijgt geen antwoord

De terminal toont de startregels, maar `http://127.0.0.1:8000` laadt niet, en er komt geen regel met `GET` bij.

**Oorzaak:** je startte de container zonder `-p`. Er is geen deur van je computer naar de container.

**Oplossing:** stop de container met Ctrl+C, en start hem opnieuw met `-p 8000:8000`.
