# Online zetten: je site op de server

<Voorkennis items={[{site: 'linux', to: '/docs/wsl/ssh', label: 'Een sleutelpaar maken met ssh-keygen'}]} />

Op je laptop draait alles in Docker. Op de server doe je hetzelfde, met dezelfde bestanden. Je typt de commando's in deze les op de server, als `sam`, tenzij er staat dat het in WSL is.

## Docker op de server

Installeer Docker zoals in [les 4](site:fullstack/docs/online/docker/installeren), en zet `sam` in de groep `docker`:

```bash
sudo apt update
sudo apt install docker.io docker-compose-v2 docker-buildx git
sudo usermod -aG docker sam
exit
```

Log opnieuw in met ssh, zodat de groep telt. Op de server zit alleen `sam` in die groep: wie erin zit, is bijna `root`.

## Logboeken met een grens

Docker bewaart alles wat een container print, en je site print een regel voor elke bezoeker. Zonder grens groeit dat logboek maanden door, tot de schijf vol is en je site stopt. Geef Docker een grens voordat je de eerste container start:

```bash
sudo nano /etc/docker/daemon.json
```

```json
{
  "log-driver": "local"
}
```

Start Docker daarna opnieuw, en kijk of hij de instelling kent:

```bash
sudo systemctl restart docker
docker info --format '{{.LoggingDriver}}'
```

Er staat `local`. Die manier van bewaren houdt per container hoogstens vijf bestanden van 20 MB bij, en gooit het oudste weg als ze vol zijn. Hij geldt alleen voor containers die Docker daarna maakt. Daarom doe je het nu, voordat er een container is.

## Je project ophalen

Op de server push je nooit; hij haalt alleen op. Is je repository openbaar, kloon hem dan met het https-adres: ophalen mag dan zonder inloggen. Is hij privé, geef de server dan een eigen sleutel die alleen dit project mag lezen: een **deploy key**. Je eigen sleutel uit [les 5](site:fullstack/docs/online/docker/image) zet je hier niet neer: die mag al je repositories veranderen.

```bash
ssh-keygen -t ed25519
cat ~/.ssh/id_ed25519.pub
```

Druk bij de vragen op Enter. Een passphrase laat je leeg: de server moet de sleutel kunnen gebruiken als jij er niet bij bent. Zet de publieke sleutel op GitHub bij je repository onder **Settings**, **Deploy keys**, en laat **Allow write access** uit. Kloon daarna met het ssh-adres:

```bash
cd ~
git clone git@github.com:sam/gastenboek.git
```

De eerste keer vraagt ssh of je de vingerafdruk van GitHub vertrouwt; typ `yes`. Wordt je server ooit gekraakt, dan kan deze sleutel alleen dit ene project lezen, en niets veranderen.

## Traefik op de server

De map `~/traefik` uit WSL hoort niet bij je project, dus hij staat niet op GitHub. Kopieer hem met `scp`, in WSL:

```bash
scp -r ~/traefik sam@203.0.113.10:
```

`scp -r` kopieert de hele map over ssh, naar de thuismap van `sam` ([Bestanden kopiëren met scp](site:linux/docs/wsl/scp)). Start hem daarna op de server:

```bash
docker network create web
cd ~/traefik
docker compose up -d
```

## Je domeinnaam

In je `compose.yaml` staat `Host(` met `gastenboek.localhost`. Op de server moet daar je domeinnaam staan, en op je laptop niet. Daarom haal je de naam uit een **variabele**. Verander het label in WSL, in je project:

```yaml
      - traefik.http.routers.gastenboek.rule=Host(`${DOMEIN:-gastenboek.localhost}`)
```

`${DOMEIN:-gastenboek.localhost}` betekent: de waarde van `DOMEIN`, of `gastenboek.localhost` als die er niet is. Zet `.env` in je `.gitignore` en je `.dockerignore`, en commit en push.

Op de server haal je de nieuwe versie op, en zet je de naam in een bestand `.env` naast `compose.yaml` ([een .env-bestand](site:linux/docs/wsl/variabelen#env)). Compose leest dat bestand vanzelf:

```bash
cd ~/gastenboek
git pull
echo "DOMEIN=gastenboek.voorbeeld.nl" > .env
docker compose up -d --build
```

De `.env` hoort bij deze computer, niet bij je project. Zo werkt dezelfde `compose.yaml` op je laptop en op de server. Open `http://gastenboek.voorbeeld.nl` op je telefoon, via mobiele data en niet via het wifi van school. Daar is je gastenboek, nog met `http`. HTTPS komt in de volgende les.

## Docker en de firewall

In [les 12](site:fullstack/docs/online/server/dichtzetten) hield ufw elke poort tegen die niet in de lijst staat. Voor Docker geldt dat niet. Een poort die je publiceert met `ports` in `compose.yaml` of `-p`, zet Docker zelf open, in de firewall van Linux, vóór de regels van ufw. Een gepubliceerde poort staat dus op internet, wat ufw ook zegt.

Daarom heeft je site geen `ports`: alleen Traefik publiceert iets, poort 80 en 443, en die stonden al open. Wil je ooit iets publiceren dat alleen voor jou is, zet er dan `127.0.0.1:` voor, zoals in [les 9](site:fullstack/docs/online/docker/compose). Dan luistert Docker alleen op de server zelf.

## Er gaat iets mis

### Job for docker.service failed

```text
Job for docker.service failed because the control process exited with error code.
See "systemctl status docker.service" and "journalctl -xeu docker.service" for details.
```

**Oorzaak:** er zit een fout in `/etc/docker/daemon.json`, en dan start Docker niet. Met `sudo journalctl -u docker` zie je welke:

```text
unable to configure the Docker daemon with file /etc/docker/daemon.json: invalid JSON: invalid character '}' looking for beginning of object key string
```

Hier staat een komma te veel achter de laatste regel. JSON is strenger dan Python: een komma alleen tussen twee regels, en aanhalingstekens altijd dubbel.

**Oplossing:** verbeter het bestand met `sudo nano /etc/docker/daemon.json`, en start Docker opnieuw met `sudo systemctl restart docker`.

### permission denied while trying to connect to the docker API

**Oorzaak:** `sam` zit nog niet in de groep `docker`, of je logde daarna niet opnieuw in.

**Oplossing:** typ `exit`, log opnieuw in met ssh, en kijk met `groups` of `docker` erbij staat.

### `Permission denied (publickey)` bij git clone

```text
git@github.com: Permission denied (publickey).
fatal: Could not read from remote repository.
```

**Oorzaak:** GitHub kent de sleutel van de server niet. De deploy key staat er niet, of bij een andere repository.

**Oplossing:** kijk op GitHub onder **Settings**, **Deploy keys** van deze repository of de sleutel er staat, en of het dezelfde is als `cat ~/.ssh/id_ed25519.pub` laat zien.

### 404 page not found op je domein

Traefik antwoordt, maar zegt `404 page not found`.

**Oorzaak:** Traefik zoekt een andere naam. Meestal staat `.env` niet naast `compose.yaml`, of zit er een tikfout in `DOMEIN`. Dan gebruikt Compose `gastenboek.localhost`.

**Oplossing:** kijk welke naam Compose echt gebruikt, verbeter `.env`, en start opnieuw:

```bash
docker compose config | grep Host
docker compose up -d
```

### De browser krijgt geen antwoord

**Oorzaak:** het A-record wijst nog niet naar je server ([les 11](site:fullstack/docs/online/server/huren)), of Traefik draait niet.

**Oplossing:** controleer de naam met `ping -c 1 gastenboek.voorbeeld.nl`, en kijk met `docker ps` of Traefik draait.

## Opdrachten

### Opdracht 1: Run - Je site op internet

Zet je site op de server, achter Traefik, met je eigen domeinnaam. Open hem op je telefoon via mobiele data, en maak er een account.

<details>
<summary>Antwoord</summary>

Je ziet je gastenboek, met een lege lijst: de databases van je laptop staan in een volume op je laptop, niet op de server. Werkt het niet, ga dan van achter naar voren: draait je site (`docker compose ps` in `~/gastenboek`), draait Traefik (`docker compose ps` in `~/traefik`), en wijst de naam naar je server?

</details>

### Opdracht 2: Investigate - Wie bezoekt je site?

Kijk na een bezoek met je telefoon in het logboek van je site:

```bash
cd ~/gastenboek
docker compose logs --tail 5
```

Staat er het adres van Traefik, of dat van je telefoon? Waarom?

<details>
<summary>Antwoord</summary>

Je ziet het adres van je telefoon op internet. Traefik zette het in `X-Forwarded-For`, en je site gelooft die kop door `FORWARDED_ALLOW_IPS=*` uit [les 10](site:fullstack/docs/online/docker/traefik). Daardoor telt de limiet uit de route Veiligheid per bezoeker, en niet iedereen samen.

</details>
