# Online zetten: een back-up

Het volume is het enige op je server dat je niet opnieuw kunt maken: je code staat op GitHub, maar de berichten en accounts van je bezoekers staan alleen in `gastenboek_data`. Hetzelfde geldt voor de instellingen van de server, `.env` en de map `~/traefik`. Een kapotte schijf, een `docker compose down -v` of een opgezegde server, en ze zijn weg. Maak er daarom een kopie van, op een andere computer.

## Een kopie maken

Stop je site even, zodat er tijdens het kopiëren niets verandert, en kopieer de map `data` uit de container:

```bash
mkdir ~/backup
cd ~/gastenboek
docker compose stop
docker compose cp gastenboek:/app/data ~/backup/data
docker compose start
```

`docker compose cp` kopieert tussen een container en de server, ook als de container gestopt is. `gastenboek:` is de naam van de service uit `compose.yaml`. Zet de instellingen van de server erbij:

```bash
cp ~/gastenboek/.env ~/backup/
cp -r ~/traefik ~/backup/
```

Haal de kopie daarna in WSL naar je laptop met `scp`:

```bash
scp -r sam@gastenboek.voorbeeld.nl:backup ~/backup-gastenboek
```

Ging ssh tot nu toe met het IP-adres, dan vraagt hij bij de domeinnaam nog één keer of je de vingerafdruk vertrouwt; het is dezelfde server. Gooi de kopie op de server daarna weg met `rm -r ~/backup`. In `gebruikers.db` staan de wachtwoorden van je bezoekers, als hash; bewaar de back-up dus net zo zorgvuldig als de server zelf.

## Terugzetten

Een back-up die je nooit terugzette, is een gok. Zo gaan de databases terug in het volume, op de server:

```bash
cd ~/gastenboek
docker compose stop
docker compose cp ~/backup/data/. gastenboek:/app/data
docker compose start
docker compose exec -u root gastenboek chown -R app /app/data
```

De `/.` achter `data` betekent: de bestanden uit de map, niet de map zelf. Anders komen ze in `/app/data/data`, waar je site niet zoekt.

De laatste regel is nodig, en je ziet pas later dat hij ontbreekt. Wat `docker compose cp` in een container zet, is van `root`. Je site draait als `app` ([les 7](site:fullstack/docs/online/docker/niet-als-root)) en mag zulke bestanden lezen, maar niet veranderen. `exec -u root` doet één commando als `root` in de draaiende container, en `chown -R app` geeft de databases terug aan `app`.

## Er gaat iets mis

### attempt to write a readonly database

```text
sqlite3.OperationalError: attempt to write a readonly database
```

**Oorzaak:** je zette een back-up terug, en de databases zijn van `root`. Je site leest ze wel, maar schrijven mag niet.

**Oplossing:** geef ze terug aan `app`, terwijl de container draait:

```bash
docker compose exec -u root gastenboek chown -R app /app/data
```

### Permission denied bij rm -r ~/backup

**Oorzaak:** je maakte de back-up met `sudo docker compose cp`. Dan is de kopie van `root`.

**Oplossing:** gooi hem weg met `sudo rm -r ~/backup`, en laat `sudo` voortaan weg voor `docker`.

### Je site is leeg na het terugzetten

**Oorzaak:** de bestanden staan in `/app/data/data`: je typte `~/backup/data` zonder `/.` erachter.

**Oplossing:** kijk met `docker compose exec gastenboek ls /app/data` wat er staat. Zet het opnieuw terug, nu met `/.`, en gooi de map `data` in de container weg met `docker compose exec -u root gastenboek rm -r /app/data/data`.

## Opdrachten

### Opdracht 1: Run - Een back-up op je laptop

Maak een back-up van je server, en haal hem naar je laptop. Wat staat er in `~/backup-gastenboek`?

<details>
<summary>Antwoord</summary>

De map `data` met je databases (`gebruikers.db`, en de andere die je site gebruikt), het bestand `.env`, en de map `traefik` met de `compose.yaml` van de voordeur. Met die drie, en je repository op GitHub, kun je op een nieuwe server alles terugzetten.

</details>

### Opdracht 2: Run - Terugzetten als oefening

Oefen het terugzetten op je laptop, in WSL, waar niets stuk kan. Registreer in je site op `gastenboek.localhost` het account `voor`, en maak een back-up naar `~/proef`. Registreer daarna het account `na`, en zet de back-up terug. Kun je nog inloggen als `na`? En lukt een nieuw account `daarna`?

<details>
<summary>Antwoord</summary>

```bash
cd ~/gastenboek
mkdir ~/proef
docker compose stop
docker compose cp gastenboek:/app/data ~/proef/data
docker compose start
```

Registreer nu `na` in de browser, en zet daarna terug:

```bash
docker compose stop
docker compose cp ~/proef/data/. gastenboek:/app/data
docker compose start
docker compose exec -u root gastenboek chown -R app /app/data
```

Inloggen als `voor` lukt, als `na` niet meer: de databases zijn weer zoals op het moment van de back-up. Het account `daarna` komt erbij. Liet je de laatste regel weg, dan gaf dat een 500.

</details>
