# Online zetten: alleen met een sleutel

<Voorkennis items={[{site: 'linux', to: '/docs/wsl/nano', label: 'Een bestand in /etc bewerken met sudo nano'}]} />

Met je sleutel kom jij binnen. Maar zolang ssh ook wachtwoorden accepteert, kan een programma er een raden. Zet dat uit, en inloggen als `root` meteen ook.

## De instellingen

Maak als `sam` een eigen bestand met instellingen:

```bash
sudo nano /etc/ssh/sshd_config.d/00-veilig.conf
```

```text
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
```

De `00` vooraan doet ertoe. ssh leest de bestanden in die map op alfabet, en de eerste keer dat een instelling voorkomt, telt. Op sommige servers staat er al een bestand, zoals `50-cloud-init.conf`, met `PasswordAuthentication yes`. Jouw bestand komt eerder.

Controleer de instellingen:

```bash
sudo sshd -t
```

Zegt `sshd -t` niets, dan klopt alles.

**Let op:** sluit de terminal waarin je als `sam` bent ingelogd niet, ook niet na het laden. Probeer eerst in een tweede terminal of je nog binnenkomt met `ssh sam@203.0.113.10`. Gaat er iets mis, dan herstel je het in de eerste, die nog openstaat. Laad nu de instellingen:

```bash
sudo systemctl reload ssh
```

<Gelukt>

In een tweede terminal geven deze twee allebei `Permission denied (publickey)`. De tweede probeert het zonder sleutel, dus met een wachtwoord:

```bash
ssh root@203.0.113.10
ssh -o PubkeyAuthentication=no sam@203.0.113.10
```

En `ssh sam@203.0.113.10` laat je nog steeds binnen.

</Gelukt>

## Er gaat iets mis

### sshd -t geeft een fout

```text
/etc/ssh/sshd_config.d/00-veilig.conf: line 1: Bad configuration option: PaswordAuthentication
```

**Oorzaak:** een tikfout in je bestand, hier één `s` te weinig.

**Oplossing:** verbeter het bestand en draai `sudo sshd -t` opnieuw. Laad de instellingen pas als hij niets meer zegt; met een fout erin start ssh niet.

### `Permission denied (publickey)` als sam

```text
sam@203.0.113.10: Permission denied (publickey).
```

**Oorzaak:** de server kent jouw sleutel niet voor `sam`. Nu wachtwoorden uitstaan, vraagt ssh niet meer om een wachtwoord, maar weigert hij meteen.

**Oplossing:** herstel het in de terminal die nog openstaat, met `chown -R sam:sam /home/sam/.ssh` zoals in [les 25](site:fullstack/docs/online/server/gebruiker).
