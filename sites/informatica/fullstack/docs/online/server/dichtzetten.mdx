# Online zetten: de deuren dicht

<Voorkennis items={[{site: 'linux', to: '/docs/wsl/apt', label: 'Bijwerken met apt'}]} />

Je server staat op internet, en het logboek van ssh liet zien dat er al aan de deur wordt gemorreld. In de vorige les zette je ssh al op alleen een sleutel. Voordat je site erop komt, doe je nog twee dingen: alleen de deuren open die nodig zijn, en updates zonder dat jij eraan hoeft te denken.

## Een firewall

Een **firewall** bepaalt welke poorten van buiten bereikbaar zijn. Op Ubuntu heet hij `ufw` (*uncomplicated firewall*). Je hebt drie deuren nodig: ssh om in te loggen, 80 voor `http` en 443 voor `https`.

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

**Let op:** de volgorde doet ertoe. Zet je de firewall aan voordat ssh erdoor mag, dan sluit je jezelf buiten. `ufw enable` waarschuwt daarom:

```text
Command may disrupt existing ssh connections. Proceed with operation (y|n)?
```

Typ `y`. Er staat dan `Firewall is active and enabled on system startup`. Kijk wat er openstaat:

```bash
sudo ufw status
```

```text
Status: active

To                         Action      From
--                         ------      ----
OpenSSH                    ALLOW       Anywhere
80/tcp                     ALLOW       Anywhere
443/tcp                    ALLOW       Anywhere
OpenSSH (v6)               ALLOW       Anywhere (v6)
80/tcp (v6)                ALLOW       Anywhere (v6)
443/tcp (v6)               ALLOW       Anywhere (v6)
```

Elke deur staat er twee keer: één keer voor gewone internetadressen, en met `(v6)` voor de nieuwere IPv6-adressen. Wat niet in de lijst staat, houdt ufw tegen. Ook als je later per ongeluk een programma op `0.0.0.0` laat luisteren. Met één uitzondering, en dat is Docker; die zie je in de volgende les.

## Updates vanzelf

Elke week worden er gaten in programma's gevonden en gedicht. Ubuntu kan de beveiligingsupdates zelf installeren, elke dag. Op een server staat dat meestal al aan:

```bash
cat /etc/apt/apt.conf.d/20auto-upgrades
```

```text
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
```

Staat er twee keer `"1"`, dan is het goed. Kijk niet naar `systemctl status unattended-upgrades`: die dienst draait altijd, ook als de updates uitstaan. Bestaat het bestand niet, of staat er een `"0"`, zet het dan aan:

```bash
sudo apt install unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades
```

Soms is een herstart nodig, bijvoorbeeld na een update van de kern van Linux. Dan staat er een bestand:

```bash
cat /var/run/reboot-required
```

```text
*** System restart required ***
```

Herstart dan met `sudo reboot`. Docker start daarna vanzelf, en je site straks ook, door `restart: unless-stopped` uit [les 9](site:fullstack/docs/online/docker/compose).

## Er gaat iets mis

### Jezelf buitengesloten

```text
ssh: connect to host 203.0.113.10 port 22: Connection timed out
```

**Oorzaak:** de firewall staat aan, maar ssh mag er niet door.

**Oplossing:** bijna elk hostingbedrijf heeft in zijn beheerpagina een **console**: een terminal in je browser, die niet via ssh gaat. Log daar in en zet ssh open:

```bash
sudo ufw allow OpenSSH
```

## Opdrachten

### Opdracht 1: Run - De deuren dicht

Zet de firewall aan met OpenSSH, 80 en 443, en controleer dat automatische updates aanstaan. Log daarna in een tweede terminal opnieuw in, om te zien dat ssh er nog door mag.

<details>
<summary>Antwoord</summary>

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
cat /etc/apt/apt.conf.d/20auto-upgrades
```

`ufw status` toont de zes regels van hierboven, en in `20auto-upgrades` staan twee keer `"1"`. Kom je in de tweede terminal niet meer binnen, gebruik dan de console van je hostingbedrijf, zoals bij **Jezelf buitengesloten**.

</details>

### Opdracht 2: Investigate - Wat luistert er?

Kijk met `sudo ss -tlnp` welke programma's luisteren. Welke luisteren op `0.0.0.0`, `*` of `[::]`, dus op internet? Staat elk daarvan in `ufw status`?

<details>
<summary>Antwoord</summary>

Op een verse Ubuntu 24.04 luistert alleen ssh op internet, op poort 22, en die staat open. Daarnaast zie je `127.0.0.53` en `127.0.0.54` op poort 53: dat is `systemd-resolved`, dat namen opzoekt voor de server zelf, alleen op `127.0.0.…`. Bij jouw hostingbedrijf kan er meer staan. Staat er iets op `0.0.0.0` dat je niet kent, zoek dan uit wat het is; de firewall houdt het tegen, maar een programma dat je niet nodig hebt, zet je beter uit.

</details>
