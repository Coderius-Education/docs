# Online zetten: je domein met HTTPS

Over `http` gaat alles leesbaar over de lijn. Wie op hetzelfde wifi zit, of ergens onderweg een kabel beheert, kan meelezen: het wachtwoord waarmee een bezoeker inlogt, en de cookie met zijn sessie-id. Met `https` is het versleuteld, en weet de browser bovendien zeker dat hij met jouw server praat en niet met een die zich voor jou uitgeeft.

Daarvoor heb je een **certificaat** nodig: een bewijs, ondertekend door een bekende partij, dat jouw server bij jouw domeinnaam hoort. Traefik vraagt er zelf een aan, gratis, bij **Let's Encrypt**, en vernieuwt het op tijd.

## Traefik op 443

Open op de server de `compose.yaml` van Traefik:

```bash
cd ~/traefik
nano compose.yaml
```

Er komen vijf regels bij `command` bij, een poort, en een volume voor de certificaten:

```yaml
services:
  traefik:
    image: traefik:v3
    command:
      - --providers.docker=true
      - --providers.docker.exposedbydefault=false
      - --entrypoints.web.address=:80
      - --entrypoints.web.http.redirections.entrypoint.to=websecure
      - --entrypoints.websecure.address=:443
      - --entrypoints.websecure.http.tls.certresolver=letsencrypt
      - --certificatesresolvers.letsencrypt.acme.httpchallenge.entrypoint=web
      - --certificatesresolvers.letsencrypt.acme.storage=/letsencrypt/acme.json
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - letsencrypt:/letsencrypt
    networks:
      - web
    restart: unless-stopped

volumes:
  letsencrypt:

networks:
  web:
    external: true
```

| Nieuw | Betekenis |
|:---|:---|
| `web.http.redirections.entrypoint.to=websecure` | stuur elk verzoek op poort 80 door naar `https` |
| `websecure.address=:443` | een tweede ingang, `websecure`, op poort 443 |
| `websecure.http.tls.certresolver=letsencrypt` | elke site op 443 krijgt een certificaat van `letsencrypt` |
| `letsencrypt.acme.httpchallenge.entrypoint=web` | Let's Encrypt controleert via poort 80 of de naam bij jouw server hoort |
| `letsencrypt.acme.storage=…` | waar de certificaten bewaard worden: in het volume `letsencrypt` |

Zonder dat volume vraagt Traefik bij elke herstart een nieuw certificaat aan, en Let's Encrypt geeft er maar een paar per week voor dezelfde naam. Start Traefik opnieuw:

```bash
docker compose up -d
```

Aan je site verandert niets: de labels uit [les 21](site:fullstack/docs/online/docker/traefik) gelden voor beide ingangen. Open `https://gastenboek.voorbeeld.nl` op je telefoon. Je site opent zonder waarschuwing over de verbinding.

Twee dingen moeten kloppen voordat het lukt: het A-record wijst naar je server ([les 25](site:fullstack/docs/online/server/naam)), en poort 80 en 443 staan open in de firewall ([les 26](site:fullstack/docs/online/server/dichtzetten)).

## Er gaat iets mis

### Geen certificaat

De browser zegt dat de verbinding niet veilig is. Klik je op de details, dan is het certificaat van `TRAEFIK DEFAULT CERT`. In `docker compose logs` van Traefik staat `Unable to obtain ACME certificate`.

**Oorzaak:** Let's Encrypt kon niet controleren dat de naam bij jouw server hoort, en Traefik gebruikt zolang een certificaat dat hij zelf maakte. Meestal wijst het A-record nog niet naar je server, of poort 80 is dicht. Een derde oorzaak zie je niet met `ping`: een oud `AAAA`-record (een IPv6-adres) van de parkeerpagina van je domeinbedrijf. Let's Encrypt kiest dan dat adres, en komt niet bij jouw server.

**Oplossing:** controleer met `getent ahosts gastenboek.voorbeeld.nl` alle adressen van je naam: staat er een adres tussen dat niet van jouw server is, haal dan dat record weg bij je domeinbedrijf. Kijk met `sudo ufw status` of 80 en 443 openstaan. Wacht daarna even: Traefik probeert het zelf opnieuw. Herstart hem niet steeds: Let's Encrypt laat maar een paar mislukte pogingen per uur toe.

### Je site werkt niet op het IP-adres

Op `http://203.0.113.10` krijg je een waarschuwing over de verbinding, en daarna `404 page not found`.

**Oorzaak:** Traefik stuurt `http` door naar `https`, ook voor het IP-adres. Daar heeft hij geen certificaat voor, en geen site: je site hoort bij de naam.

**Oplossing:** open je site met je domeinnaam. Dat is ook het adres dat je aan anderen geeft.

## Opdrachten

### Opdracht 1: Run - HTTPS voor je site

Zet de nieuwe regels in de `compose.yaml` van Traefik, start hem opnieuw, en open je site met `https`. Klik in de adresbalk op het pictogram voor het adres: wie heeft het certificaat ondertekend, en tot wanneer is het geldig?

<details>
<summary>Antwoord</summary>

Als uitgever staat er Let's Encrypt, met een korte naam als `E5` of `R11` erbij. Het certificaat is hooguit drie maanden geldig, en Traefik vernieuwt het vanzelf ruim voordat het afloopt.

</details>

### Opdracht 2: Modify - Nooit meer http

Traefik stuurt `http` door naar `https`, maar de allereerste keer gaat het verzoek nog onversleuteld. Met de kop `Strict-Transport-Security` vertel je de browser: gebruik voor deze naam voortaan altijd `https`, ook als iemand `http` typt. Zet bij de labels van je site twee regels:

```yaml
      - traefik.http.routers.gastenboek.middlewares=hsts
      - traefik.http.middlewares.hsts.headers.stsSeconds=86400
```

De tweede maakt een **middleware**: een stap die Traefik doet met elk antwoord. De eerste zet die stap op je site. Commit, haal het op op de server, en start opnieuw. Hoe zie je in de ontwikkelaarstools dat de kop meekomt?

<details>
<summary>Tip</summary>

De koppen van een antwoord staan in het tabblad Netwerk, bij een verzoek. Zie [Kijken wat de browser doet](site:fullstack/docs/FastAPI/eerste-server/devtools-netwerk).

</details>

<details>
<summary>Antwoord</summary>

Klik in Netwerk op het verzoek van de pagina. Onder de koppen van het antwoord staat `strict-transport-security: max-age=86400`. `max-age` is in seconden: een dag lang gebruikt de browser alleen nog `https` voor je naam. Grote sites zetten hier een jaar (`31536000`), maar begin klein: een browser die de kop kent, gaat die tijd niet terug naar `http`, ook niet als je server later weg is of iets anders draait. Op je laptop zie je de kop niet: Traefik zet hem alleen bij een antwoord over `https`.

</details>
