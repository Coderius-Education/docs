# Cookies afschermen: uitloggen

Een sessie hoort niet eeuwig te duren. Hij eindigt op twee manieren: de
bezoeker logt uit, of de tijd is om. In allebei de gevallen beslist je server,
niet de browser. De cookie weghalen is niet genoeg: wie het sessie-id eerder
heeft gekopieerd, stuurt het zelf mee. Pas als de sessie uit
`sessies.db` weg is, hoort dat id bij niemand meer.

## Een endpoint om uit te loggen

Een `/uitloggen` ken je al uit opdracht 5 van
[Cookie of sessie?](/docs/FastAPI/cookie-of-sessie). Daar was het een POST, en
dat is geen toeval: een link is altijd een GET, en een link kan ook op een
andere site staan. Hoe dat zit, zag je in [les 3](./samesite).

Zet dit endpoint onder de andere in `main.py`:

<CodeUitleg>

{/* route-dubbel: dezelfde POST /uitloggen als opdracht 5 van Cookie of sessie?, nu in de server van deze reeks */}
```python showLineNumbers
@app.post("/uitloggen")
async def uitloggen(sessie_id: str = Cookie(default="")):
    with SqliteDict("sessies.db") as sessies:
        if sessie_id in sessies:
            del sessies[sessie_id]
            sessies.commit()
    antwoord = JSONResponse({"bericht": "Uitgelogd"})
    antwoord.delete_cookie("sessie_id")
    return antwoord
```

<Regel n={2}>
Het sessie-id uit de cookie, net als bij verwijderen.
</Regel>

<Regel n={3} tot={6}>
De sessie gaat weg op de server. Daarna hoort dit sessie-id bij niemand meer.
</Regel>

<Regel n={8}>
`delete_cookie` zegt tegen de browser: gooi deze cookie weg.
</Regel>

</CodeUitleg>

Geef `static/formulier.html` een knop om uit te loggen. Het is een tweede
formulier, met `method="post"`:

```html
<!doctype html>
<html>
<body>
    <form method="post" action="/bericht">
        <input type="text" name="naam" placeholder="Je naam" required>
        <input type="text" name="bericht" placeholder="Je bericht" required>
        <button type="submit">Verstuur</button>
    </form>
    <form method="post" action="/uitloggen">
        <button>Uitloggen</button>
    </form>
</body>
</html>
```

## Doe de test

Een script `uitloggen.py` plaatst als Sara een bericht en bewaart haar
sessie-id. Daarna logt Sara uit, en probeert een dief met dat bewaarde id haar
bericht te verwijderen:

```python
import httpx

adres = "http://127.0.0.1:8000"

sara = httpx.Client(base_url=adres)
sleutel = sara.post("/bericht", data={"naam": "Sara", "bericht": "Hoi"}).json()["sleutel"]
oud_id = sara.cookies.get("sessie_id")
print(sara.post("/uitloggen").json())
print("Cookie na uitloggen:", sara.cookies.get("sessie_id"))

dief = httpx.Client(base_url=adres, cookies={"sessie_id": oud_id})
print("Met het oude sessie-id:", dief.delete(f"/bericht/{sleutel}").status_code)
```

Uitvoer:

```
{'bericht': 'Uitgelogd'}
Cookie na uitloggen: None
Met het oude sessie-id: 403
```

Sara heeft geen cookie meer, en de server kent haar sessie niet meer. Wie het
oude id nog heeft, is voor de server een nieuwe bezoeker.

## Een sessie laten verlopen

In `set_cookie` staat `max_age`. Daarmee gooit de browser de cookie na 30 dagen
weg, maar `sessies.db` weet daar niets van. Een sessie-id dat iemand heeft
gekopieerd, blijft zo eeuwig geldig. Daarom bewaart de server in de sessie zelf
tot wanneer hij geldt, en kijkt hij daar bij elk verzoek naar.

Zet bovenaan `main.py`, onder de imports, hoe lang een sessie geldt, en een
functie die een sessie ophaalt en controleert:

<CodeUitleg>

```python showLineNumbers
GELDIG = 60 * 60 * 24 * 30

def sessie_ophalen(sessie_id: str) -> dict:
    with SqliteDict("sessies.db") as sessies:
        mijn = sessies.get(sessie_id, {})
        if mijn and mijn.get("tot", 0) < time.time():
            del sessies[sessie_id]
            sessies.commit()
            return {}
    return mijn
```

<Regel n={1}>
30 dagen in seconden, net als `max_age`. Nu staat het getal op één plek.
</Regel>

<Regel n={6}>
`time.time()` is het tijdstip van nu in seconden. Ligt `tot` daarvoor, dan is
de sessie verlopen. Een sessie zonder `tot`, uit een eerdere les, telt ook als
verlopen.
</Regel>

<Regel n={7} tot={9}>
Een verlopen sessie gaat weg, en de functie doet alsof er geen sessie is.
</Regel>

</CodeUitleg>

In `bericht_plaatsen` veranderen drie dingen. Een nieuw sessie-id komt er nu
als er geen geldige sessie is, ook als de oude verlopen is. De sessie krijgt bij
elk bericht een nieuwe `tot`. En `max_age` gebruikt `GELDIG`. Vervang je `bericht_plaatsen` door:

{/* route-dubbel: vervangt POST /bericht uit les 1 en 2, nu met een verlooptijd in de sessie */}
```python
@app.post("/bericht")
async def bericht_plaatsen(
    naam: str = Form(...),
    bericht: str = Form(...),
    sessie_id: str = Cookie(default=""),
):
    if not sessie_ophalen(sessie_id):
        sessie_id = secrets.token_hex(16)

    sleutel = f"bericht_{time.time_ns()}"
    with SqliteDict("gastenboek.db") as db:
        db[sleutel] = {"naam": naam, "bericht": bericht}
        db.commit()

    with SqliteDict("sessies.db") as sessies:
        mijn = sessies.get(sessie_id, {"naam": naam, "berichten": []})
        mijn["naam"] = naam
        mijn["berichten"].append(sleutel)
        mijn["tot"] = time.time() + GELDIG
        sessies[sessie_id] = mijn
        sessies.commit()

    antwoord = JSONResponse({"sleutel": sleutel})
    antwoord.set_cookie(
        key="sessie_id",
        value=sessie_id,
        max_age=GELDIG,
        httponly=True,
        samesite="lax",
    )
    return antwoord
```

In `bericht_verwijderen` en `alles_wissen` vervang je het `with`-blok van
`sessies.db` door één regel:

{/* niet-compileren: losse regel uit een handler */}

```python
    mijn = sessie_ophalen(sessie_id)
```

## Doe de test met een verlopen sessie

Een kwartier of dertig dagen wachten is geen test. Het script `verlopen.py`
zet daarom de tijd van Sara's sessie in je eigen `sessies.db` op een moment dat
al voorbij is, en probeert dan haar bericht te verwijderen:

```python
import time

import httpx
from sqlitedict import SqliteDict

adres = "http://127.0.0.1:8000"

sara = httpx.Client(base_url=adres)
sleutel = sara.post("/bericht", data={"naam": "Sara", "bericht": "Hoi"}).json()["sleutel"]
sessie_id = sara.cookies.get("sessie_id")

with SqliteDict("sessies.db") as sessies:
    mijn = sessies[sessie_id]
    mijn["tot"] = time.time() - 1
    sessies[sessie_id] = mijn
    sessies.commit()

print("Cookie nog in de browser:", sara.cookies.get("sessie_id") is not None)
print("Verwijderen:", sara.delete(f"/bericht/{sleutel}").status_code)
```

Uitvoer:

```
Cookie nog in de browser: True
Verwijderen: 403
```

De cookie staat er nog, net als bij een dief die het id heeft gekopieerd. Toch
weigert de server. Zonder `sessie_ophalen`, met alleen `max_age`, geeft
hetzelfde script `Verwijderen: 200`.

## Er gaat iets mis

Na het uitloggen is de cookie weg, maar `uitloggen.py` geeft
`Met het oude sessie-id: 200`.

**Oorzaak:** het endpoint doet alleen `delete_cookie`. De browser gooit de
cookie weg, maar voor de server is de sessie nog geldig. Wie dat sessie-id nog
heeft, bijvoorbeeld omdat het was uitgelezen voordat je `httponly` gebruikte,
komt er nog steeds mee binnen.

**Oplossing:** gooi altijd ook de sessie op de server weg, zoals in regel 3 tot
en met 6 van `uitloggen`.

## Opdrachten

### Opdracht 1: Investigate - Hoe haalt de server een cookie weg?

Open `http://127.0.0.1:8000/static/formulier.html`, verstuur een bericht, ga
terug en klik op **Uitloggen**. Klik in het tabblad **Netwerk** op het verzoek
`uitloggen` en zoek onder **Reactieheaders** de regel `set-cookie`. Hoe vertelt
de server de browser dat de cookie weg moet?

<details>
<summary>Antwoord</summary>

```
sessie_id=""; expires=…; Max-Age=0; Path=/; SameSite=lax
```

De server zet de cookie opnieuw, met een lege waarde en `Max-Age=0`: houdbaar
voor nul seconden. De browser gooit hem dan meteen weg. Een apart commando om
een cookie te verwijderen bestaat niet.

</details>

### Opdracht 2: Predict - Uitloggen zonder in te loggen

Een nieuwe bezoeker, zonder cookie, stuurt `POST /uitloggen`.

**Vraag:** wat antwoordt de server?

<details>
<summary>Antwoord</summary>

`{'bericht': 'Uitgelogd'}`. Het sessie-id is leeg, dus `if sessie_id in sessies`
is niet waar en er gaat niets weg. Daarna haalt `delete_cookie` een cookie weg
die er niet was. Er gaat niets mis: uitloggen als je niet bent ingelogd, doet
niets.

</details>

<details>
<summary>Zo ziet je `main.py` er nu uit</summary>

```python
import secrets
import time

from fastapi import Cookie, FastAPI, Form, HTTPException
from fastapi.responses import JSONResponse
from fastapi.staticfiles import StaticFiles
from sqlitedict import SqliteDict

GELDIG = 60 * 60 * 24 * 30

app = FastAPI()
app.mount("/static", StaticFiles(directory="static"), name="static")

def sessie_ophalen(sessie_id: str) -> dict:
    with SqliteDict("sessies.db") as sessies:
        mijn = sessies.get(sessie_id, {})
        if mijn and mijn.get("tot", 0) < time.time():
            del sessies[sessie_id]
            sessies.commit()
            return {}
    return mijn

@app.post("/bericht")
async def bericht_plaatsen(
    naam: str = Form(...),
    bericht: str = Form(...),
    sessie_id: str = Cookie(default=""),
):
    if not sessie_ophalen(sessie_id):
        sessie_id = secrets.token_hex(16)

    sleutel = f"bericht_{time.time_ns()}"
    with SqliteDict("gastenboek.db") as db:
        db[sleutel] = {"naam": naam, "bericht": bericht}
        db.commit()

    with SqliteDict("sessies.db") as sessies:
        mijn = sessies.get(sessie_id, {"naam": naam, "berichten": []})
        mijn["naam"] = naam
        mijn["berichten"].append(sleutel)
        mijn["tot"] = time.time() + GELDIG
        sessies[sessie_id] = mijn
        sessies.commit()

    antwoord = JSONResponse({"sleutel": sleutel})
    antwoord.set_cookie(
        key="sessie_id",
        value=sessie_id,
        max_age=GELDIG,
        httponly=True,
        samesite="lax",
    )
    return antwoord

@app.get("/berichten")
async def berichten():
    with SqliteDict("gastenboek.db") as db:
        return dict(db)

@app.delete("/bericht/{sleutel}")
async def bericht_verwijderen(sleutel: str, sessie_id: str = Cookie(default="")):
    mijn = sessie_ophalen(sessie_id)
    if sleutel not in mijn.get("berichten", []):
        raise HTTPException(status_code=403, detail="Dit is niet jouw bericht")

    with SqliteDict("gastenboek.db") as db:
        if sleutel in db:
            del db[sleutel]
            db.commit()
    return {"bericht": "Verwijderd"}

@app.delete("/berichten")
async def alles_wissen(sessie_id: str = Cookie(default="")):
    mijn = sessie_ophalen(sessie_id)
    with SqliteDict("gastenboek.db") as db:
        for sleutel in mijn.get("berichten", []):
            if sleutel in db:
                del db[sleutel]
        db.commit()
    return {"bericht": "Jouw berichten zijn gewist"}

@app.post("/uitloggen")
async def uitloggen(sessie_id: str = Cookie(default="")):
    with SqliteDict("sessies.db") as sessies:
        if sessie_id in sessies:
            del sessies[sessie_id]
            sessies.commit()
    antwoord = JSONResponse({"bericht": "Uitgelogd"})
    antwoord.delete_cookie("sessie_id")
    return antwoord
```

Een sessie eindigt nu op de server: bij uitloggen, of als de tijd om is. Koppel
je later inloggen aan je sessie, dan eindigt ook dat inloggen op deze twee
manieren.

</details>
