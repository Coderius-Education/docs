# Wie mag wat: de controle met 403

In [les 1](./zwakheid) verwijderde Alex het bericht van Sara, met of zonder
knop. De controle hoort daarom op de plek waar het verzoek binnenkomt: in het
endpoint. De server weet wie deze bezoeker is: sinds het inloggen staat zijn
naam in zijn sessie. En bij elk bericht staat de naam van wie het plaatste. Zijn
die twee niet gelijk, dan verwijdert het endpoint niets.

Heb je [opdracht 5 van Sessies](/docs/FastAPI/onthouden/sessies#opdracht-5-make---echt-afschermen)
gemaakt, dan deed je dit al, op `/verwijderen`. Hier zet je dezelfde controle op
`DELETE /bericht/{sleutel}`, en zie je met het script uit les 1 dat hij werkt.

## De controle in het endpoint

Vervang `bericht_verwijderen` in je `main.py` door deze:

<CodeUitleg>

```python showLineNumbers
@app.delete("/bericht/{sleutel}")
async def bericht_verwijderen(sleutel: str, sessie_id: str = Cookie(default="")):
    with SqliteDict("sessies.db") as sessies:
        mijn = sessies.get(sessie_id, {})

    with SqliteDict("gastenboek.db") as db:
        bericht = db.get(sleutel)
        if bericht is None or bericht["naam"] != mijn.get("naam"):
            raise HTTPException(status_code=403, detail="Dit is niet jouw bericht")
        del db[sleutel]
        db.commit()
    return {"bericht": "Verwijderd"}
```

<Regel n={2}>
Het endpoint vraagt nu ook de cookie op, net als `bericht_plaatsen`.
</Regel>

<Regel n={3} tot={4}>
De sessie van deze bezoeker. Geen cookie of een onbekend sessie-id geeft een lege dictionary, en daarin is `mijn.get("naam")` gelijk aan `None`.
</Regel>

<Regel n={7} tot={9}>
Eerst de controle, vóór er iets verandert. Bestaat het bericht niet, of staat er een andere naam bij dan in de sessie, dan stopt de functie met **403 Forbidden**: de server begrijpt wat je vraagt, maar jij mag het niet. De andere codes staan op [de startpagina](/docs/veiligheid#statuscodes).
</Regel>

<Regel n={10} tot={11}>
Pas nu gaat het bericht weg.
</Regel>

</CodeUitleg>

## Doe de test opnieuw

Gooi `gastenboek.db`, `sessies.db` en `gebruikers.db` weg, start de server
opnieuw, en draai `test_verwijderen.py` uit [les 1](./zwakheid):

```
Alex verwijdert het bericht van Sara: 403
Nog in het gastenboek: ['Sara', 'Alex']
```

Alex stuurt nog steeds hetzelfde verzoek, maar de server weigert. Het bericht
van Sara staat er nog.

## Waar de controle zit

De controle zit in het endpoint zelf, na het ophalen van de sessie en vóór het
verwijderen.

## Er gaat iets mis

Het verwijderen geeft `500 Internal Server Error`, ook bij je eigen bericht. In
de terminal van je server eindigt de foutmelding met:

```
NameError: name 'sessie_id' is not defined
```

**Oorzaak:** je hebt de nieuwe regels in `bericht_verwijderen` gezet, maar de
parameter `sessie_id: str = Cookie(default="")` niet. Dan bestaat `sessie_id`
niet in de functie.

**Oplossing:** zet de parameter erbij, zoals in regel 2 hierboven.

## Opdrachten

### Opdracht 1: Run - Sara mag wel

Zet onderaan `test_verwijderen.py` een stuk erbij waarin Sara haar eigen bericht
verwijdert. Lukt dat, en wat staat er daarna nog in het gastenboek?

<details>
<summary>Tip</summary>

Het is dezelfde lus als voor Alex, maar dan met `sara.get` en `sara.delete`.

</details>

<details>
<summary>Antwoord</summary>

```python
for sleutel, bericht in sara.get("/berichten").json().items():
    if bericht["naam"] == "Sara":
        antwoord = sara.delete(f"/bericht/{sleutel}")
        print(f"Sara verwijdert haar eigen bericht: {antwoord.status_code}")

namen = []
for bericht in sara.get("/berichten").json().values():
    namen.append(bericht["naam"])
print(f"Nog in het gastenboek: {namen}")
```

Uitvoer, na de twee regels van Alex:

```
Sara verwijdert haar eigen bericht: 200
Nog in het gastenboek: ['Alex']
```

De `Client` van Sara stuurt haar cookie mee, en in haar sessie staat de naam Sara, dezelfde naam als bij het bericht.

</details>

### Opdracht 2: Predict - Een nieuw venster

Sara opent het gastenboek in een privévenster. Daar logt ze opnieuw in, als
Sara, en stuurt ze het verzoek om haar eigen bericht te verwijderen. In het
script is dat een derde `httpx.Client`, die met haar naam en wachtwoord
inlogt.

**Vraag:** krijgt ze `200` of `403`?

<details>
<summary>Tip</summary>

Waarmee vergelijkt de controle de naam bij het bericht: met de browser, of met
de naam in de sessie?

</details>

<details>
<summary>Antwoord</summary>

`200`. Het privévenster heeft een ander sessie-id, maar onder dat id staat ook
de naam Sara, want ze logde in met haar wachtwoord. De controle kijkt naar die
naam, niet naar het venster. Logt ze in het privévenster níét in, dan heeft ze
geen sessie en krijgt ze `403`.

</details>

### Opdracht 3: Investigate - Een sleutel die niet bestaat

Alex stuurt `alex.delete("/bericht/bestaat_niet")`. Welke statuscode krijgt hij,
en waarom is het goed dat het geen `404` is?

<details>
<summary>Antwoord</summary>

`403`, met `{'detail': 'Dit is niet jouw bericht'}`: een bericht dat niet
bestaat, valt onder dezelfde voorwaarde als een bericht van een ander. Zo leert
Alex niets over sleutels van anderen: een bestaand bericht van Sara en een
verzonnen sleutel geven hetzelfde antwoord. Hetzelfde idee zag je bij
[Inloggen: een wachtwoord controleren](/docs/FastAPI/accounts/inloggen): één melding
voor een onbekende naam en een fout wachtwoord.

</details>

<details>
<summary>Zo ziet je `main.py` er nu uit</summary>

```python
import secrets
import time

from fastapi import Cookie, FastAPI, Form, HTTPException
from fastapi.responses import JSONResponse
from sqlitedict import SqliteDict

app = FastAPI()

@app.post("/registreer")
async def registreer(naam: str = Form(...), wachtwoord: str = Form(...)):
    with SqliteDict("gebruikers.db") as gebruikers:
        if naam in gebruikers:
            raise HTTPException(status_code=400, detail="Deze naam is al bezet")
        gebruikers[naam] = wachtwoord
        gebruikers.commit()
    return {"bericht": f"Welkom, {naam}"}

@app.post("/inloggen")
async def inloggen(naam: str = Form(...), wachtwoord: str = Form(...)):
    with SqliteDict("gebruikers.db") as gebruikers:
        opgeslagen = gebruikers.get(naam)
    if opgeslagen != wachtwoord:
        raise HTTPException(status_code=401, detail="Naam of wachtwoord klopt niet")

    sessie_id = secrets.token_hex(16)
    with SqliteDict("sessies.db") as sessies:
        sessies[sessie_id] = {"naam": naam}
        sessies.commit()

    antwoord = JSONResponse({"bericht": f"Ingelogd als {naam}"})
    antwoord.set_cookie(key="sessie_id", value=sessie_id, max_age=60 * 60 * 24 * 30)
    return antwoord

@app.post("/bericht")
async def bericht_plaatsen(bericht: str = Form(...), sessie_id: str = Cookie(default="")):
    with SqliteDict("sessies.db") as sessies:
        mijn = sessies.get(sessie_id, {})
    if not mijn:
        raise HTTPException(status_code=401, detail="Log eerst in")

    sleutel = f"bericht_{time.time_ns()}"
    with SqliteDict("gastenboek.db") as db:
        db[sleutel] = {"naam": mijn["naam"], "bericht": bericht}
        db.commit()
    return {"sleutel": sleutel}

@app.get("/berichten")
async def berichten():
    with SqliteDict("gastenboek.db") as db:
        return dict(db)

@app.delete("/bericht/{sleutel}")
async def bericht_verwijderen(sleutel: str, sessie_id: str = Cookie(default="")):
    with SqliteDict("sessies.db") as sessies:
        mijn = sessies.get(sessie_id, {})

    with SqliteDict("gastenboek.db") as db:
        bericht = db.get(sleutel)
        if bericht is None or bericht["naam"] != mijn.get("naam"):
            raise HTTPException(status_code=403, detail="Dit is niet jouw bericht")
        del db[sleutel]
        db.commit()
    return {"bericht": "Verwijderd"}
```

Het verwijderen controleert nu wie het vraagt.

</details>
