# Te veel verzoeken: zelf twintig verzoeken

<Voorkennis
  items={[
    {site: 'python', to: '/docs/herhalen/06a-for-loop', label: 'De for-loop'},
  ]}
/>

In [les 2](site:fullstack/docs/veiligheid/dos/verzoek) mat je één verzoek. Nu stuur je er twintig achter elkaar
naar je eigen server, en tel je hoeveel er antwoord krijgen.

## Twintig verzoeken

Start je server met `fastapi dev main.py`, met het endpoint uit les 1. Maak een
bestand `test_verzoeken.py`:

{/* bestand: test_verzoeken.py */}

<CodeUitleg>

```python showLineNumbers
import httpx

adres = "http://127.0.0.1:8000/"

gelukt = 0
for nummer in range(20):
    antwoord = httpx.get(adres)
    print(f"Verzoek {nummer + 1}: status {antwoord.status_code}")
    if antwoord.status_code == 200:
        gelukt += 1

print(f"Gelukt: {gelukt} van de 20")
```

<Regel n={3}>
Alleen je eigen server, zoals in les 1.
</Regel>

<Regel n={5}>
`gelukt` telt hoeveel verzoeken antwoord 200 krijgen.
</Regel>

<Regel n={6} tot={10}>
De for-loop stuurt twintig keer hetzelfde `GET`-verzoek. Elke keer dat het lukt, gaat de teller één omhoog.
</Regel>

</CodeUitleg>

### Het script draaien

Draai het in een tweede terminal:

```bash
python test_verzoeken.py
```

<Gelukt>

Je ziet twintig regels met `status 200`, en aan het eind:

{/* draai: test_verzoeken.py; deel */}

```text
Gelukt: 20 van de 20
```

In de terminal van je server staan twintig regels met `GET /`, één per verzoek.

</Gelukt>

## Dit is de zwakheid

Twintig verzoeken zijn niets voor je server. Maar elk verzoek krijgt
antwoord, hoe vaak het ook komt en van wie. Er is niets in je
server dat zegt "zo is het wel genoeg". Zet in gedachten `range(20)` op
`range(20000)`, en laat dat door duizend computers tegelijk doen: zo ziet een
aanval eruit. Wat zo'n aanval is, zie je in [les 4](site:fullstack/docs/veiligheid/dos/dos-en-ddos), en in
[les 5](site:fullstack/docs/veiligheid/dos/limiet) zet je er een grens op.

<Voorspel soort="Controlevraag" vraag="Je draait test_verzoeken.py daarna meteen nog twee keer, zonder iets op te slaan. Wat print de derde keer op de laatste regel?">
  <Keuze goed uitleg="Je server houdt niet bij wie al hoeveel verzoeken stuurde. Ook de derde keer krijgt alles antwoord.">Gelukt: 20 van de 20, net als de eerste keer</Keuze>
  <Keuze uitleg="Een server die telt en dan weigert, heb je nog niet; die bouw je in les 5. Nu onthoudt hij niets.">Gelukt: 0 van de 20, want je had je beurt al gehad</Keuze>
  <Keuze uitleg="Na elk antwoord is je server klaar met dat verzoek. Er blijft niets liggen voor de volgende keer.">Minder dan 20, want je server loopt steeds verder achter</Keuze>
  <Uitleg>

  Je server onthoudt niet hoe vaak iemand al iets vroeg, dus de zestigste krijgt net zo goed antwoord als de eerste. Dat is de zwakheid; in les 5 zet je er een grens op.

  </Uitleg>
</Voorspel>

## Er gaat iets mis

### Gelukt: 0 van de 20

Elke regel zegt `status 404`, en aan het eind staat `Gelukt: 0 van de 20`.

**Oorzaak:** het adres klopt niet, bijvoorbeeld omdat er een pad als `/test`
in `adres` staat terwijl je server alleen `/` kent.

**Oplossing:** open `http://127.0.0.1:8000/` in je browser. Zie je daar
`Hallo wereld!`, zet dan precies dat adres in `adres`.

### ConnectError

Het script stopt meteen met een `httpx.ConnectError`.

**Oorzaak:** je server draait niet, zoals in [les 2](site:fullstack/docs/veiligheid/dos/verzoek).

**Oplossing:** start je server in de eerste terminal met `fastapi dev main.py`,
en draai het script opnieuw.

## Opdrachten

### Opdracht 1: Predict - Vijftig keer

Je verandert `range(20)` in `range(50)` en draait het script opnieuw.

**Vraag:** hoeveel verzoeken lukken er, en ligt je server daarna plat?

<details>
<summary>Tip</summary>

Er is nog niets dat je server laat weigeren. Kijk ook goed naar de laatste
`print`.

</details>

<details>
<summary>Antwoord</summary>

Alle vijftig lukken. De laatste regel is:

```
Gelukt: 50 van de 20
```

Het getal 20 staat vast in de laatste `print`. Pas je dat aan naar 50, dan
staat er `Gelukt: 50 van de 50`. Je server ligt niet plat: open na het script
`http://127.0.0.1:8000/`, en je krijgt meteen antwoord. Of dat ook zo is terwijl
het script nog loopt, probeer je in [les 4](site:fullstack/docs/veiligheid/dos/dos-en-ddos).

</details>
