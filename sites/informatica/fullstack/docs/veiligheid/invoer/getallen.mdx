# Invoer controleren: getallen en keuzes

Een gastenboek met een cijfer voor de site, van 1 tot en met 10. In de HTML
staat dat netjes:

```html
<input type="number" name="cijfer" min="1" max="10" required>
```

Maar `min` en `max` zijn net als `maxlength` uit [les 1](./maxlength): de
browser houdt je tegen, een script niet. Op de server kan een cijfer dan
`honderd` zijn, of `11`, of `0`.

## Een getal met een grens

<CodeUitleg>

```python showLineNumbers
@app.post("/bericht")
async def bericht_plaatsen(
    naam: str = Form(..., max_length=30),
    bericht: str = Form(..., max_length=280),
    cijfer: int = Form(..., ge=1, le=10),
):
    if not naam.strip():
        raise HTTPException(status_code=400, detail="Vul een naam in")
    with SqliteDict("gastenboek.db") as db:
        db[f"bericht_{time.time_ns()}"] = {"naam": naam, "bericht": bericht, "cijfer": cijfer}
        db.commit()
    return {"lengte": len(bericht), "cijfer": cijfer}
```

<Regel n={5}>
`int` zegt: dit moet een geheel getal zijn. `ge=1` betekent groter dan of gelijk aan 1, `le=10` kleiner dan of gelijk aan 10.
</Regel>

<Regel n={10}>
Het cijfer gaat mee de database in.
</Regel>

</CodeUitleg>

Vervang `bericht_plaatsen` door deze. Zette je in opdracht 2 van
[les 4](./inhoud) ook een controle op het bericht, neem die twee regels dan
mee, onder de controle op de naam. In de code van deze les staan ze niet, net
als in de stand van les 4.

Zet het `<input>` met `name="cijfer"` in `static/formulier.html`, zodat ook het
formulier een cijfer meestuurt.

## Doe de test

Een script `cijfer.py` probeert vier cijfers:

```python
import httpx

adres = "http://127.0.0.1:8000/bericht"

for cijfer in ["8", "honderd", "11", "0"]:
    antwoord = httpx.post(adres, data={"naam": "Sara", "bericht": "hoi", "cijfer": cijfer})
    if antwoord.status_code == 200:
        print(cijfer, "->", antwoord.json())
    else:
        print(cijfer, "->", antwoord.status_code, antwoord.json()["detail"][0]["msg"])
```

Uitvoer:

```
8 -> {'lengte': 3, 'cijfer': 8}
honderd -> 422 Input should be a valid integer, unable to parse string as an integer
11 -> 422 Input should be less than or equal to 10
0 -> 422 Input should be greater than or equal to 1
```

Een formulier stuurt alles als tekst, ook `"8"`. FastAPI maakt er een getal van,
en weigert wat geen getal is of buiten de grens valt. In je functie is `cijfer`
dus altijd een getal van 1 tot en met 10.

## Toestaan wat mag

Bij een getal zet je een onder- en een bovengrens. Bij een keuze uit een paar
woorden, zoals een stemming, maak je een lijst met wat mag, en weiger je de
rest:

<CodeUitleg>

```python showLineNumbers
STEMMINGEN = ["blij", "neutraal", "boos"]

@app.post("/bericht")
async def bericht_plaatsen(
    naam: str = Form(..., max_length=30),
    bericht: str = Form(..., max_length=280),
    cijfer: int = Form(..., ge=1, le=10),
    stemming: str = Form(...),
):
    if not naam.strip():
        raise HTTPException(status_code=400, detail="Vul een naam in")
    if stemming not in STEMMINGEN:
        raise HTTPException(status_code=400, detail="Kies blij, neutraal of boos")
    with SqliteDict("gastenboek.db") as db:
        db[f"bericht_{time.time_ns()}"] = {
            "naam": naam,
            "bericht": bericht,
            "cijfer": cijfer,
            "stemming": stemming,
        }
        db.commit()
    return {"lengte": len(bericht), "cijfer": cijfer, "stemming": stemming}
```

<Regel n={1}>
De lijst met wat mag, bovenaan `main.py`, boven je endpoints.
</Regel>

<Regel n={12} tot={13}>
`not in` is waar als de stemming niet in de lijst staat. Dan stuur je een eigen `400`, net als bij de lege naam in [les 4](./inhoud).
</Regel>

<Regel n={15} tot={20}>
De stemming gaat mee de database in, en komt terug in het antwoord. De dictionary staat over meer regels, want hij is te lang voor één.
</Regel>

</CodeUitleg>

Vervang `bericht_plaatsen` door deze, weer met je controle op het bericht als
je die hebt, en zet in `static/formulier.html` een `<select>` met dezelfde drie
woorden binnen het `<form>`:

```html
<select name="stemming">
    <option>blij</option>
    <option>neutraal</option>
    <option>boos</option>
</select>
```

Een script `stemming.py` probeert er twee:

```python
import httpx

adres = "http://127.0.0.1:8000/bericht"

for stemming in ["blij", "vrolijk"]:
    gegevens = {"naam": "Sara", "bericht": "hoi", "cijfer": "8", "stemming": stemming}
    antwoord = httpx.post(adres, data=gegevens)
    print(stemming, "->", antwoord.status_code, antwoord.json())
```

Uitvoer:

```
blij -> 200 {'lengte': 3, 'cijfer': 8, 'stemming': 'blij'}
vrolijk -> 400 {'detail': 'Kies blij, neutraal of boos'}
```

Je noemt op wat mag, dus alles wat je niet noemde, is geweigerd. Ook een
woord dat je zelf nooit bedacht had.

`stemming` is verplicht, net als `cijfer`. De scripts uit de vorige lessen, en
ook `cijfer.py`, sturen geen stemming mee. Die krijgen nu een `422`, met in
`detail` het veld `stemming` en `Field required`; `cijfer.py` print bij `8`
dan `422 Field required`. Zet in zo'n script `"stemming": "blij"` bij de
`data`.

## Er gaat iets mis

Elk verzoek geeft `422` met `cijfer` of `stemming` en `Field required`, ook
vanuit het formulier.

**Oorzaak:** het veld komt niet mee. In het formulier heet het veld anders dan
de parameter, of het `<input>` of `<select>` staat buiten het `<form>`. Een
script uit een eerdere les, zoals `fouten.py`, stuurt het helemaal niet mee.

**Oplossing:** controleer dat er `name="cijfer"` en `name="stemming"` staan,
binnen het `<form>`. Zet in een script `"cijfer": "8"` en `"stemming": "blij"`
bij de `data`.

## Opdrachten

### Opdracht 1: Predict - Een half cijfer

Je stuurt als cijfer `7.5`.

**Vraag:** wat antwoordt de server?

<details>
<summary>Antwoord</summary>

`422`, met `Input should be a valid integer, unable to parse string as an
integer`. Een `int` is een geheel getal; `7.5` is dat niet.

</details>

### Opdracht 2: Investigate - Een hoofdletter

Je stuurt als stemming `Blij`, met een hoofdletter.

**Vraag:** wat antwoordt de server, en hoe zorg je dat `Blij` toch mag?

<details>
<summary>Tip</summary>

`"Blij" == "blij"` is in Python niet waar. Met `lower()` maak je van alle
letters kleine letters.

</details>

<details>
<summary>Antwoord</summary>

`400 {'detail': 'Kies blij, neutraal of boos'}`. `Blij` staat niet in de lijst:
voor Python is een hoofdletter een ander teken. Wil je het toestaan, zet dan
bovenaan de functie:

```python
stemming = stemming.lower()
```

Dan wordt `Blij` eerst `blij`, en komt hij door de controle. In de database
staat dan `blij`, zoals in je lijst.

</details>

<details>
<summary>Zo ziet je `main.py` er nu uit</summary>

```python
import time

from fastapi import FastAPI, Form, HTTPException
from fastapi.staticfiles import StaticFiles
from sqlitedict import SqliteDict

app = FastAPI()
app.mount("/static", StaticFiles(directory="static"), name="static")

STEMMINGEN = ["blij", "neutraal", "boos"]

@app.post("/bericht")
async def bericht_plaatsen(
    naam: str = Form(..., max_length=30),
    bericht: str = Form(..., max_length=280),
    cijfer: int = Form(..., ge=1, le=10),
    stemming: str = Form(...),
):
    if not naam.strip():
        raise HTTPException(status_code=400, detail="Vul een naam in")
    if stemming not in STEMMINGEN:
        raise HTTPException(status_code=400, detail="Kies blij, neutraal of boos")
    with SqliteDict("gastenboek.db") as db:
        db[f"bericht_{time.time_ns()}"] = {
            "naam": naam,
            "bericht": bericht,
            "cijfer": cijfer,
            "stemming": stemming,
        }
        db.commit()
    return {"lengte": len(bericht), "cijfer": cijfer, "stemming": stemming}
```

Elk veld heeft nu een controle op de server: de lengte, het getal en de keuze
bewaakt FastAPI of je eigen lijst.

</details>
