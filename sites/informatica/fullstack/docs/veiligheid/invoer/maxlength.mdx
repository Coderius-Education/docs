# Invoer controleren: maxlength is geen controle

In een formulier kun je met `maxlength` een grens zetten op een veld. De
browser laat je dan niet verder typen. Maar die grens is een hulp voor wie zich
vergist, geen controle. Met een script zie je waarom, en hoe ver het gaat.
Deed je de uitbreiding JavaScript al, dan ken je het idee uit
[Server of browser?](site:fullstack/docs/FastAPI/in-de-browser/server-of-browser); deze les kun je ook
zonder die uitbreiding volgen.

## Doe het na, op je eigen server

Start je server uit [les 1](site:fullstack/docs/veiligheid/invoer/startbestand),
en open het formulier uit de map `static`:
`http://127.0.0.1:8000/static/formulier.html`. Typ een lang bericht in het vak
`bericht`: na 280 tekens gaat er niets meer bij, want `maxlength` houdt je tegen.

### Een script in plaats van het formulier

Nu een scriptje `groot.py`, naast `main.py`, dat níét via het formulier gaat,
maar rechtstreeks naar het endpoint:

{/* bestand: groot.py */}

<CodeUitleg>

```python showLineNumbers
import httpx

adres = "http://127.0.0.1:8000/bericht"

bericht = "a" * 1_000_000
antwoord = httpx.post(adres, data={"naam": "Sara", "bericht": bericht})
print(antwoord.json())
```

<Regel n={5}>
Een miljoen keer de letter `a`: dat kreeg je er in het formulier nooit in. `1_000_000` is hetzelfde getal als `1000000`, maar leesbaarder.
</Regel>

<Regel n={6}>
Hetzelfde verzoek dat de browser zou sturen, maar zonder de grens uit de HTML.
</Regel>

</CodeUitleg>

### Het script draaien

Draai het met `python groot.py`, en daarna `lees_database.py` uit les 1.

<Gelukt>

`groot.py` print:

{/* draai: groot.py */}

```text
{'lengte': 1000000}
```

En `lees_database.py` print onderaan, onder je berichten uit het formulier:

```text
[Sara] 1000000 tekens
```

Je server bewaarde een bericht van een miljoen tekens, terwijl het formulier
na 280 stopte.

</Gelukt>

### Wat er gebeurde

Alle miljoen tekens staan in je database. `maxlength` zat in de HTML, en die
HTML draaide in de browser die je nu hebt overgeslagen. Het endpoint zag alleen
het verzoek, en dat had geen grens.

Eén bericht van een miljoen tekens is al vervelend, en een script dat dat
duizend keer doet, vult je schijf.

## Eén ruwe grens

Helemaal zonder grens is je server niet. Maak naast `groot.py` een tweede
script, `te_groot.py`, met tien miljoen tekens en onderaan ook de statuscode.
`groot.py` zelf laat je zoals hij is: die heb je in de opdrachten en in les 3
nog nodig.

{/* bestand: te_groot.py */}

```python
import httpx

adres = "http://127.0.0.1:8000/bericht"

bericht = "a" * 10_000_000
antwoord = httpx.post(adres, data={"naam": "Sara", "bericht": bericht})
print(antwoord.json())
print(antwoord.status_code)
```

Uitvoer:

{/* draai: te_groot.py */}

```text
{'detail': 'Field exceeded maximum size of 1024KB.'}
400
```

### Wie hield het tegen?

Starlette, het deel van FastAPI dat formulieren leest, weigert zelf een veld
dat groter is dan een megabyte, ongeveer een miljoen tekens. Het bericht van
precies een miljoen kwam er nog net door. Die grens beschermt je tegen het
ergste, maar een bericht in een gastenboek hoort geen megabyte te zijn. De
echte grens zet je zelf, in [les 3](site:fullstack/docs/veiligheid/invoer/grenzen).

<Voorspel soort="Controlevraag" vraag="Een klasgenoot haalt in DevTools maxlength uit het formulier in zijn eigen browser, en verstuurt 300 tekens. Komt dat bericht in je database?">
  <Keuze goed uitleg="De HTML in zijn browser mag hij veranderen, en je endpoint controleert de lengte nog niet.">Ja: de grens stond alleen in zijn browser</Keuze>
  <Keuze uitleg="Je server stuurt de HTML één keer op. Wat een browser er daarna mee doet, ziet je server niet.">Nee: jouw server stuurde het formulier, dus jouw maxlength geldt nog</Keuze>
  <Keuze uitleg="Starlette weigert pas boven een megabyte. Hoeveel tekens is dat ongeveer?">Nee: Starlette houdt een te lang veld tegen</Keuze>
  <Uitleg>

  Alles in je HTML is een hulp voor de bezoeker. Wie de HTML in zijn browser
  aanpast of een script gebruikt, stuurt wat hij wil, en je endpoint ziet alleen
  wat er in het verzoek staat.

  </Uitleg>
</Voorspel>

## Er gaat iets mis

### `Field required` in plaats van de lengte

`groot.py` print geen lengte, maar een melding zoals deze:

```
{'detail': [{'type': 'missing', 'loc': ['body', 'bericht'], 'msg': 'Field required', 'input': None}]}
```

**Oorzaak:** je stuurt geen `naam` of `bericht` mee, of de namen in `data`
komen niet overeen met de `Form`-parameters, zoals `berichten` in plaats van
`bericht`. FastAPI mist dan een verplicht veld en antwoordt met een `422`.

**Oplossing:** stuur beide velden mee, met precies de namen `naam` en `bericht`,
net als het formulier.

Wat er in zo'n `422` staat, lees je in [les 4](site:fullstack/docs/veiligheid/invoer/fouten-lezen). Alle
statuscodes van deze route staan op [de startpagina](site:fullstack/docs/veiligheid#statuscodes).

## Opdrachten

### Opdracht 1: Predict - 300 tekens

In het formulier kom je niet verder dan 280 tekens. Je stuurt met een script een
bericht van 300 tekens.

**Vraag:** wat antwoordt de server?

<details>
<summary>Antwoord</summary>

`{'lengte': 300}`. De server kent de grens van 280 niet: die staat alleen in
de HTML.

</details>

### Opdracht 2: Investigate - Vijf keer

Draai `groot.py`, met het bericht van `1_000_000` tekens, vijf keer achter
elkaar, en daarna `lees_database.py`. Veranderde je `groot.py` voor opdracht 1,
zet het bericht dan eerst terug op `1_000_000`. Hoeveel tekens staan er nu in je
database?

<details>
<summary>Tip</summary>

Tel ook het bericht mee dat er al stond.

</details>

<details>
<summary>Antwoord</summary>

Onder je berichten uit het formulier staan zes regels
`[Sara] 1000000 tekens`: het bericht van daarnet en de vijf nieuwe.
Stuurde je in opdracht 1 echt 300 tekens, dan staat daartussen ook
`[Sara] 300 tekens`. Het bericht van `te_groot.py` staat er niet bij: dat
weigerde de server. Samen zes miljoen tekens, en het bestand `gastenboek.db` is ongeveer zes
megabyte. Elke keer dat het script draait, groeit het. Een script dat niet
stopt, maakt je schijf vol.

</details>
