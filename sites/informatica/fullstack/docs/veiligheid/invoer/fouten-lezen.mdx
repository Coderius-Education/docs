# Invoer controleren: een 422 lezen

In [les 3](site:fullstack/docs/veiligheid/invoer/grenzen) printte je alleen de melding. Het antwoord van een `422`
zegt meer: welk veld het was, wat voor fout, en wat er binnenkwam. Met die
gegevens kan een script zeggen wat er mis is.

## Twee fouten tegelijk

Maak een script `fouten.py` dat een te lange naam en een leeg bericht stuurt:

{/* bestand: fouten.py */}

<CodeUitleg>

```python showLineNumbers
import httpx

adres = "http://127.0.0.1:8000/bericht"

antwoord = httpx.post(adres, data={"naam": "a" * 31, "bericht": ""})
print(antwoord.status_code)
for fout in antwoord.json()["detail"]:
    print(fout["loc"][1], fout["type"], fout["msg"])
```

<Regel n={7}>
`detail` is een lijst, met één dictionary per fout. Een for-loop loopt ze langs.
</Regel>

<Regel n={8}>
Uit elke fout drie stukken: het veld, het soort fout, en de melding.
</Regel>

</CodeUitleg>

### fouten.py draaien

Draai het, met de server uit les 3.

<Gelukt>

`fouten.py` print de statuscode en een regel per fout:

{/* draai: fouten.py */}

```text
422
naam string_too_long String should have at most 30 characters
bericht missing Field required
```

FastAPI controleert alle velden, en meldt alle fouten in één keer.

</Gelukt>

## Wat er in één fout staat

Elke fout is een dictionary. Voor de te lange naam ziet hij er zo uit:

```
{'type': 'string_too_long', 'loc': ['body', 'naam'], 'msg': 'String should have at most 30 characters', 'input': 'aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa', 'ctx': {'max_length': 30}}
```

| Sleutel | Betekent |
|:---:|:---:|
| `type` | het soort fout, als vast woord |
| `loc` | waar: `body` is het formulier, daarna het veld |
| `msg` | de melding in het Engels |
| `input` | wat er binnenkwam |
| `ctx` | de grens die gold, als die er is |

Daarom pakt `fouten.py` `fout["loc"][1]`: het tweede stuk van `loc` is de naam
van het veld.

## Een leeg veld is al een fout

Het lege bericht gaf `missing`, en dat zonder dat je er iets voor schreef.
`Form(...)` maakt een veld verplicht, en voor FastAPI telt een leeg veld als
niet ingevuld. Een `min_length=1` erbij is dus niet nodig.

  <Uitleg>

  `detail` is een lijst met één fout per veld dat niet klopt. Daarom kan een
  script per veld zeggen wat er mis is.

  </Uitleg>
</Voorspel>

## Er gaat iets mis

### `KeyError: 'detail'`

Je verandert in `fouten.py` de naam in `Sara` en het bericht in `hoi`, en het
script stopt met:

```
KeyError: 'detail'
```

**Oorzaak:** de server keurde alles goed, en antwoordde met een `200` en
`{'lengte': 3}`. In dat antwoord staat geen `detail`, dus
`antwoord.json()["detail"]` bestaat niet.

**Oplossing:** lees `detail` alleen als de server een `422` stuurde. Onder
`adres` staat dan:

```python
antwoord = httpx.post(adres, data={"naam": "Sara", "bericht": "hoi"})
print(antwoord.status_code)
if antwoord.status_code == 422:
    for fout in antwoord.json()["detail"]:
        print(fout["loc"][1], fout["type"], fout["msg"])
```
