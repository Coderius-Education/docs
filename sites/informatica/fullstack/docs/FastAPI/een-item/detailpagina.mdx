Je lijst toont alle berichten onder elkaar, op één pagina. Op echte websites klik je op één item en krijg je een eigen pagina, met een eigen URL die je kunt delen. Daarvoor moet de URL zeggen wélk bericht je bedoelt.

## De sleutel in de URL

In [Eén route voor veel pagina's: path-parameters](/docs/FastAPI/veel-paginas/path-parameters) gaf `/dier/{naam}` elk dier een eigen pagina. Een bericht krijgt op dezelfde manier een eigen adres, met de sleutel uit de database in het pad. Een vraagteken, zoals `/zoek?term=python` uit [GET vs POST](/docs/FastAPI/formulieren/get_vs_post), kan ook, maar voor één item is een path-parameter gebruikelijker. Zet dit endpoint onder je andere endpoints:

```python
@app.get("/bericht/{sleutel}")
async def bericht_detail(request: Request, sleutel: str):
    return {"je_vroeg_om": sleutel}
```

Ga je naar `/bericht/bericht_17` dan krijg je `{"je_vroeg_om":"bericht_17"}`, net als bij de dieren.

## Het bericht opzoeken

Met die sleutel kun je het bericht uit de database halen. Vervang je endpoint door deze versie:

{/* route-dubbel: vervangt de eerste versie van GET /bericht/{sleutel} hierboven */}
```python
@app.get("/bericht/{sleutel}")
async def bericht_detail(request: Request, sleutel: str):
    with SqliteDict("gastenboek.db") as db:
        bericht = db.get(sleutel)
    return templates.TemplateResponse(
        request,
        "bericht.html",
        {"bericht": bericht}
    )
```

`db.get(sleutel)` geeft `None` als de sleutel niet bestaat, in plaats van te crashen met een `KeyError`.

De template `templates/bericht.html` toont één bericht, met een link terug naar de lijst:

```html
<!DOCTYPE html>
<html>
    <body>
        <h1>Bericht van {{ bericht.naam }}</h1>
        <p>{{ bericht.bericht }}</p>
        <a href="/berichten">Terug naar alle berichten</a>
    </body>
</html>
```

## Wat als het niet bestaat

Iemand kan een URL intypen die nergens op slaat, of een bericht dat net verwijderd is opvragen. Dan is `bericht` gelijk aan `None` en toont je template een lege pagina. Dat is verwarrend: de bezoeker denkt dat er iets stuk is.

Zeg liever expliciet dat het niet bestaat, met `HTTPException`. Zet `HTTPException` bij je imports en vervang je endpoint nog een keer:

<CodeUitleg>

{/* route-dubbel: vervangt de tweede versie van GET /bericht/{sleutel} hierboven */}
```python showLineNumbers
from fastapi import HTTPException

@app.get("/bericht/{sleutel}")
async def bericht_detail(request: Request, sleutel: str):
    with SqliteDict("gastenboek.db") as db:
        bericht = db.get(sleutel)

    if bericht is None:
        raise HTTPException(status_code=404, detail="Dit bericht bestaat niet")

    return templates.TemplateResponse(
        request,
        "bericht.html",
        {"bericht": bericht}
    )
```

<Regel n={3} tot={4}>
`{sleutel}` in het pad komt binnen als de parameter `sleutel`; de twee namen moeten gelijk zijn.
</Regel>

<Regel n={6}>
`db.get(sleutel)` geeft `None` als de sleutel niet bestaat, in plaats van een `KeyError`.
</Regel>

<Regel n={8} tot={9}>
Hier staat `raise`, geen `return`. Je geeft geen antwoord terug maar onderbreekt de functie, en Python voert de regels eronder niet meer uit. **404** is de code die "niet gevonden" betekent. Diezelfde code kreeg je eerder als je een adres opvroeg waar geen endpoint bij hoort; nu stuur je hem zelf.
</Regel>

</CodeUitleg>

## Linken vanuit de lijst

Sinds het [verwijderen](/docs/FastAPI/gastenboek/redirect#verwijderen-en-terug) stuurt `/berichten` de sleutels al mee, via `db.items()`. Dezelfde sleutel zet je nu in een link. In `templates/berichten.html` wordt de naam klikbaar; het verwijderformulier blijft staan:

```html
{% for sleutel, bericht in berichten %}
    <li>
        <a href="/bericht/{{ sleutel }}">{{ bericht.naam }}</a>: {{ bericht.bericht }}
        <form method="post" action="/verwijderen">
            <input type="hidden" name="sleutel" value="{{ sleutel }}">
            <button type="submit">Verwijderen</button>
        </form>
    </li>
{% endfor %}
```

<details>
<summary>Zo ziet je `templates/berichten.html` er nu uit</summary>

Alleen de naam in de `<li>` is nu een link; de rest is zoals in [Doorsturen na opslaan (redirect)](/docs/FastAPI/gastenboek/redirect).

```html
<!DOCTYPE html>
<html>
    <head>
        <title>Gastenboek</title>
        <link rel="stylesheet" href="/static/css/style.css">
    </head>
    <body>
        <h1>Gastenboek</h1>

        {% if berichten %}
            <ul>
                {% for sleutel, bericht in berichten %}
                    <li>
                        <a href="/bericht/{{ sleutel }}">{{ bericht.naam }}</a>: {{ bericht.bericht }}
                        <form method="post" action="/verwijderen">
                            <input type="hidden" name="sleutel" value="{{ sleutel }}">
                            <button type="submit">Verwijderen</button>
                        </form>
                    </li>
                {% endfor %}
            </ul>
        {% else %}
            <p>Nog geen berichten. Wees de eerste.</p>
        {% endif %}

        <a href="/gastenboek">Nieuw bericht</a>
    </body>
</html>
```

## Testen

1. Ga naar `/berichten` en klik op een naam
2. Je ziet één bericht, en de sleutel staat in de adresbalk
3. Verander de sleutel in de adresbalk in iets willekeurigs
4. Je krijgt `{"detail":"Dit bericht bestaat niet"}` met status 404

:::danger[Gaat er iets mis?]
Krijg je een pagina met lege plekken in plaats van een 404? Dan staat je `if bericht is None` waarschijnlijk ná de `return`. Zie je `{"status_code":404,"detail":"Dit bericht bestaat niet","headers":null}` met status 200? Dan schreef je `return` in plaats van `raise`. Meer oplossingen staan op [Er gaat iets mis](/docs/troubleshooting).
:::

## Opdrachten

### Opdracht 1: Predict - Twee keer niet gevonden

Je endpoint `/bericht/{sleutel}` staat er, met de controle op `None`. Je gaat naar twee adressen die allebei niet bestaan:

1. `/bericht/onzin`
2. `/bericht/onzin/meer`

**Vraag:** krijg je twee keer hetzelfde te zien?

<details>
<summary>Tip</summary>

Zoek bij elk adres het endpoint dat erbij past. Draait je eigen functie bij allebei?

</details>

<details>
<summary>Antwoord</summary>

Nee. Allebei geven ze een 404, maar met een andere tekst:

1. `/bericht/onzin` past op je route. Je functie draait, vindt niets en stuurt jouw 404: `{"detail":"Dit bericht bestaat niet"}`.
2. `/bericht/onzin/meer` past op geen enkele route. Je functie draait niet, en FastAPI stuurt zelf `{"detail":"Not Found"}`.

</details>

### Opdracht 2: Run

Maak het `/bericht/{sleutel}` endpoint en de template `bericht.html`. Pas je lijst aan zodat elke naam een link is.

### Opdracht 3: Investigate - Zonder de controle

Zet een `#` voor de twee regels met `if bericht is None:` en `raise HTTPException(...)`. Ga naar `/bericht/onzin` met het tabblad Netwerk open. Wat zie je op de pagina, en welke statuscode staat in Netwerk?

<details>
<summary>Antwoord</summary>

De pagina toont "Bericht van" met een lege plek erachter, en eronder een lege regel. `bericht` is `None`, en Jinja2 zet voor `{{ bericht.naam }}` dan niets neer, zonder foutmelding. In Netwerk staat `200`: voor de browser ging alles goed. Een bezoeker, en ook een zoekmachine, kan niet zien dat dit bericht niet bestaat. Haal de `#` weer weg.

</details>

### Opdracht 4: Make - Bezoeker begroeten

Maak een endpoint `/welkom/{naam}` dat een template toont met "Welkom, [naam]". Geef een 404 met de tekst "Onbekende bezoeker" als de naam niet in je lijst met bekende bezoekers staat, bijvoorbeeld `["Sam", "Jan", "Sarah"]`.

<details>
<summary>Tip</summary>

`naam not in bekend` is waar als de naam niet in de lijst `bekend` staat. Zet die controle vóór de `TemplateResponse`, met `raise`.

</details>

<details>
<summary>Antwoord</summary>

`templates/welkom.html`:
```html
<!DOCTYPE html>
<html>
    <body>
        <h1>Welkom, {{ naam }}</h1>
    </body>
</html>
```

```python
@app.get("/welkom/{naam}")
async def welkom(request: Request, naam: str):
    bekend = ["Sam", "Jan", "Sarah"]
    if naam not in bekend:
        raise HTTPException(status_code=404, detail="Onbekende bezoeker")
    return templates.TemplateResponse(request, "welkom.html", {"naam": naam})
```

</details>

### Opdracht 5: Make - Bericht per nummer

Geef elk bericht een nummer in de URL: `/bericht-nummer/1` toont het eerste bericht, `/bericht-nummer/2` het tweede. Geef een 404 als dat nummer niet bestaat.

<details>
<summary>Tip</summary>

Schrijf `nummer: int` als type. FastAPI zet de tekst uit de URL dan om naar een getal. Een lijst begint bij 0, dus het eerste bericht staat op `alle_berichten[nummer - 1]`.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.get("/bericht-nummer/{nummer}")
async def bericht_nummer(request: Request, nummer: int):
    with SqliteDict("gastenboek.db") as db:
        alle_berichten = list(db.values())

    if nummer < 1 or nummer > len(alle_berichten):
        raise HTTPException(status_code=404, detail="Dit bericht bestaat niet")

    return templates.TemplateResponse(
        request,
        "bericht.html",
        {"bericht": alle_berichten[nummer - 1]}
    )
```

Door `nummer: int` te schrijven controleert FastAPI zelf of het een getal is. Typ je `/bericht-nummer/abc`, dan krijg je een 422 nog voordat jouw code draait.

</details>
