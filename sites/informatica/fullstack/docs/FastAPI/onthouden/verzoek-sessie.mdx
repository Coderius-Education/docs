# Zo werkt het: een sessie

De diagrammen van [één klik](/docs/FastAPI/een-item/verzoek-get) en [één formulier](/docs/FastAPI/een-item/verzoek-get#een-formulier) gaan uit van een verzoek dat op zichzelf staat. Dat is ook wat er gebeurt: je server weet niet dat je er net ook al was. Een sessie is het rondje dat dat gat dicht.

<VerzoekCyclus variant="sessie" />

Stap 3 is het hele verschil met een gewone cookie. De server leest niet wat de browser stuurde, maar zoekt het op in zijn eigen database, en alleen het id reist mee in de cookie. In [Cookie of sessie?](/docs/FastAPI/onthouden/cookie-of-sessie) gebruikte je dit diagram om de twee aanpakken te vergelijken. Hier hoort bij elke stap de regel uit je `main.py` uit [Onthouden op de server: sessies](/docs/FastAPI/onthouden/sessies):

- De browser doet stap 1 en 6 zelf; daar schrijf je niets voor.
- Stap 2 is de parameter `sessie_id: str = Cookie(default="")` van je endpoint.
- Bij stap 3 en 4 hoort `sessies.get(sessie_id, {})`. Een onbekend id geeft een lege dictionary, en dan is er geen sessie.
- In je `POST /inloggen` is `antwoord.set_cookie(key="sessie_id", value=sessie_id, …)` stap 5. In de antwoorden daarna zit geen nieuwe cookie: je server zet hem één keer, en de browser stuurt hem steeds terug.
