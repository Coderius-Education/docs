## In je code

Het hele verschil met een gewone cookie zit in de stap De server zoekt de sessie op. De server leest niet wat de browser stuurde, maar zoekt het op in zijn eigen database, en alleen het id reist mee in de cookie. Zo hoort bij elke stap van het rondje een regel uit je `main.py` uit [Onthouden op de server: sessies](site:fullstack/docs/FastAPI/onthouden/sessies):

- De cookie meesturen en bewaren doet de browser zelf; daar schrijf je niets voor.
- Dat FastAPI de cookie doorgeeft, is de parameter `sessie_id: str = Cookie(default="")` van je endpoint.
- De sessie opzoeken en weten wie er is, is `sessies.get(sessie_id, {})`. Een onbekend id geeft een lege dictionary, en dan is er geen sessie.
- In je `POST /inloggen` zet `antwoord.set_cookie(key="sessie_id", value=sessie_id, …)` de cookie op het antwoord dat teruggaat. In de antwoorden daarna zit geen nieuwe cookie: je server zet hem één keer, en de browser stuurt hem steeds terug.
