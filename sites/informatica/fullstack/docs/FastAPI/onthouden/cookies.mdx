# Onthouden met een cookie

Je gastenboek werkt, maar het vraagt bij elk bericht opnieuw je naam en je wachtwoord, ook als je net een bericht hebt geplaatst. Dat komt niet doordat je iets vergeten bent te programmeren: je server kán niet weten dat jij het weer bent. Hier laat je de browser je naam onthouden. Je wachtwoord typ je nog wel; waarom, ontdek je in opdracht 3.

## De server herkent je niet

Elk verzoek staat op zichzelf. De browser vraagt een pagina op, Python stuurt een antwoord, en daarna is het contact verbroken. Vraag je een seconde later een tweede pagina op, dan begint alles opnieuw: je server heeft geen idee dat jij dezelfde bezoeker bent als daarnet. Dat is geen gebrek, het is hoe het web werkt.

Wil je toch iets onthouden tussen twee verzoeken, dan moet je die informatie ergens bewaren. Een **cookie** is daar de eenvoudigste vorm van: een klein stukje tekst dat je meegeeft met je antwoord, en dat de browser vanaf dan bij élk volgend verzoek automatisch terugstuurt.

## Een cookie meegeven

Tot nu toe gaf je endpoint alleen inhoud terug. Een antwoord kan ook opdrachten voor de browser bevatten, en `set_cookie` is er daar een van. Vervang je `POST /gastenboek` door deze versie. De controle op de lengte uit [Server of browser?](/docs/FastAPI/in-de-browser/server-of-browser) en die op het wachtwoord uit [Inloggen: een wachtwoord controleren](/docs/FastAPI/accounts/inloggen) blijven bovenaan staan:

<CodeUitleg>

{/* route-dubbel: vervangt POST /gastenboek uit Inloggen of het htmx-recept, nu met een cookie */}
```python showLineNumbers
@app.post("/gastenboek")
async def gastenboek_opslaan(
    naam: str = Form(...),
    wachtwoord: str = Form(...),
    bericht: str = Form(...),
):
    if len(bericht) > 80:
        raise HTTPException(status_code=400, detail="Bericht is te lang")

    with SqliteDict("gebruikers.db") as gebruikers:
        opgeslagen = gebruikers.get(naam)
    if opgeslagen != wachtwoord:
        raise HTTPException(status_code=401, detail="Naam of wachtwoord klopt niet")

    with SqliteDict("gastenboek.db") as db:
        db[f"bericht_{time.time_ns()}"] = {"naam": naam, "bericht": bericht}
        db.commit()

    antwoord = RedirectResponse(url="/berichten", status_code=303)
    antwoord.set_cookie(key="naam", value=naam, max_age=60 * 60 * 24 * 30)
    return antwoord
```

<Regel n={19}>
Je maakt het antwoord nu eerst als variabele, in plaats van het meteen terug te geven. Return je het meteen, dan heb je geen plek om er iets aan toe te voegen.
</Regel>

<Regel n={20}>
`set_cookie` zet een cookie op het antwoord: een naam, een waarde, en met `max_age` de houdbaarheid in seconden. Hier is dat 30 dagen: `60 * 60 * 24 * 30`. Laat je `max_age` weg, dan verdwijnt de cookie zodra de bezoeker de browser afsluit.
</Regel>

<Regel n={21}>
Pas nu gaat het antwoord terug, mét de cookie erop.
</Regel>

</CodeUitleg>

Alleen de naam gaat in de cookie, nooit het wachtwoord. Een cookie staat leesbaar in de browser, en reist bij elk verzoek mee.

Gebruik je het htmx-formulier uit de [htmx-recepten](/docs/FastAPI/zonder-herladen/htmx-overzicht), dan laat je de omleiding weg: maak van je `HTMLResponse` de variabele `antwoord`, zet daar `set_cookie` op en return hem.

## De cookie terugkrijgen

Vanaf nu stuurt de browser die cookie mee bij elk verzoek aan jouw server. Je vraagt hem op met `Cookie`, net zoals je formuliervelden met `Form` opvraagt. Vervang je `GET /gastenboek`, dat tot nu toe een `FileResponse` gaf:

<CodeUitleg>

{/* route-dubbel: vervangt GET /gastenboek uit post_naar_database.mdx, nu met een template */}
```python showLineNumbers
from fastapi import Cookie

@app.get("/gastenboek")
async def gastenboek_form(request: Request, naam: str = Cookie(default="")):
    return templates.TemplateResponse(request, "gastenboek.html", {"naam": naam})
```

<Regel n={4}>
`Cookie(default="")` haalt de cookie `naam` uit het verzoek, zoals `Form(...)` een formulierveld haalt. `default=""` bepaalt wat je krijgt als er nog geen cookie is: bij een eerste bezoek een lege tekst.
</Regel>

</CodeUitleg>

Je formulier was tot nu toe een vast bestand, `static/pages/gastenboek_form.html`. Om er een naam in te kunnen zetten moet het een **template** worden: verplaats het hele bestand naar `templates/gastenboek.html`, met de `<head>` en de script-tags die er misschien al in staan, en zet de waarde in het naamveld. Alleen dat veld verandert: `value="{{ naam }}"` komt erbij. Zonder htmx en JavaScript ziet het formulier er dan zo uit:

```html
<form method="post" action="/gastenboek">
    <input type="text" name="naam" value="{{ naam }}" required>
    <input type="password" name="wachtwoord" required>
    <input type="text" name="bericht" required>
    <button type="submit">Verstuur</button>
</form>
```

Bij een eerste bezoek is `{{ naam }}` leeg en zie je een leeg veld. Daarna staat je naam er al in; je wachtwoord typ je zelf. Heeft jouw formulier `hx-post` en `hx-target`, of een `id` voor je tekenteller, laat die dan staan.

## Testen

1. Start je server en schrijf een bericht, met je naam en je wachtwoord
2. Ga terug naar `/gastenboek`: je naam staat er al, het wachtwoordveld is leeg
3. Open de ontwikkelaarstools met `F12` en zoek in het tabblad **App** (Application; in Firefox **Opslag**) bij Cookies de regel `http://127.0.0.1:8000`. Daar staat jouw naam. Heeft je naam een spatie of een letter als ë, dan zet de server er aanhalingstekens omheen of maakt hij van de ë een code als `\353`; in het formulier staat hij weer zoals je hem typte

:::danger[Gaat er iets mis?]
Blijft het veld leeg terwijl je wel een bericht hebt verstuurd? Controleer of `set_cookie` op het antwoord staat dat je ook echt returnt. Meer oplossingen staan op [Er gaat iets mis](/docs/troubleshooting).
:::

## Opdrachten

### Opdracht 1: Predict - Wie stuurt wat?

Je hebt een cookie met je naam. Je vraagt daarna drie pagina's op: `/berichten`, `/gastenboek` en `/bericht/bericht_123`.

**Vraag:** bij hoeveel van die drie verzoeken stuurt de browser de cookie mee?

<details>
<summary>Tip</summary>

Bepaalt jouw Python-code wanneer een cookie meegaat, of de browser?

</details>

<details>
<summary>Antwoord</summary>

Alle drie. De browser stuurt de cookie bij elk verzoek aan jouw server mee, of je endpoint er nu iets mee doet of niet. Dat je hem alleen in `/gastenboek` uitleest, verandert daar niets aan.

</details>

### Opdracht 2: Run

Pas je POST-endpoint aan zodat het de naam als cookie meegeeft, verplaats je formulier naar `templates/gastenboek.html` en lees de cookie uit in je GET-endpoint. Controleer dat je naam blijft staan.

### Opdracht 3: Investigate - Verander je eigen cookie

Zoek de cookie op in het tabblad **App** en dubbelklik op de waarde om hem in een andere naam te veranderen. Herlaad daarna `/gastenboek`.

<details>
<summary>Antwoord</summary>

In het formulier staat nu de naam die jij zelf in de cookie hebt getypt. Je server neemt hem klakkeloos over.

Hier kan dat weinig kwaad: met de naam van een ander kom je zonder diens wachtwoord niet in het gastenboek. Maar stel dat je het wachtwoord wilt overslaan, en de cookie zou gelden als bewijs dat je bent ingelogd. Dan was iedereen met één dubbelklik iemand anders. Een cookie staat op de computer van de bezoeker, en die kan er alles van maken. Voor een naam die je alleen als gemak invult is dat prima; voor iets waar rechten aan hangen, zoals wie is ingelogd of wie mag verwijderen, niet. Daar gaat de [volgende les](/docs/FastAPI/onthouden/sessies) over.

</details>

### Opdracht 4: Make - Vergeet mij

Maak een endpoint `/vergeet` dat de cookie weghaalt en de bezoeker terugstuurt naar het formulier. Zet er een link naartoe onder je formulier.

<details>
<summary>Tip</summary>

Naast `set_cookie` bestaat er ook `delete_cookie`, met alleen de naam van de cookie als argument. Ook hier geldt: eerst het antwoord maken, dan de cookie eraf halen, dan returnen.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.get("/vergeet")
async def vergeet():
    antwoord = RedirectResponse(url="/gastenboek")
    antwoord.delete_cookie("naam")
    return antwoord
```

In `templates/gastenboek.html`:
```html
<a href="/vergeet">Ik ben iemand anders</a>
```

Na het klikken is het naamveld weer leeg: de browser heeft de cookie weggegooid en stuurt hem dus niet meer mee.

Dit mag een GET zijn, want op de server verandert er niets: alleen een cookie voor het gemak verdwijnt uit de browser. Waarom uitloggen wél een POST is, lees je straks in [Cookie of sessie?](/docs/FastAPI/onthouden/cookie-of-sessie).

</details>

### Opdracht 5: Make - Welkom terug

Laat boven het formulier "Welkom terug, [naam]" staan als de bezoeker al eens een bericht heeft geplaatst, en "Welkom" als dat niet zo is.

<details>
<summary>Tip</summary>

De template weet al of `naam` gevuld is. Met `{% if naam %}` kun je daarop reageren, net zoals je in [Alles tonen: een for-lus in je template](/docs/FastAPI/gastenboek/lijst_tonen) een lege lijst opving.

</details>

<details>
<summary>Antwoord</summary>

In `templates/gastenboek.html`:
```html
{% if naam %}
    <h1>Welkom terug, {{ naam }}</h1>
{% else %}
    <h1>Welkom</h1>
{% endif %}
```

Je endpoint hoeft niet te veranderen: de lege standaardwaarde uit `Cookie(default="")` is voor Jinja2 al genoeg om te weten dat er niets is.

</details>
