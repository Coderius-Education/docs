# Doorsturen na opslaan (redirect)

Je gastenboek werkt, maar na het versturen van een bericht sta je op een doodlopende pagina. Druk je daar op F5, dan vraagt je browser of je het formulier nog een keer wilt versturen. Zeg je ja, dan staat hetzelfde bericht twee keer in je database. Daarom stuur je de bezoeker na het opslaan door naar de berichten.

## RedirectResponse

Met `RedirectResponse` stuur je de browser door naar een andere URL. Zet `RedirectResponse` bij je imports:

```python
from fastapi.responses import RedirectResponse
```

Vervang dan je POST-endpoint `/gastenboek` uit [Elk bericht bewaren: een eigen sleutel](/docs/FastAPI/berichten-opslaan/eigen-sleutel). Alleen de laatste regel verandert:

<CodeUitleg>

{/* route-dubbel: vervangt POST /gastenboek uit Elk bericht bewaren */}
```python showLineNumbers
@app.post("/gastenboek")
async def gastenboek_opslaan(naam: str = Form(...), bericht: str = Form(...)):
    with SqliteDict("gastenboek.db") as db:
        sleutel = f"bericht_{time.time_ns()}"
        db[sleutel] = {"naam": naam, "bericht": bericht}
        db.commit()
    return RedirectResponse(url="/berichten", status_code=303)
```

<Regel n={3} tot={6}>
Het opslaan is hetzelfde als in [Elk bericht bewaren: een eigen sleutel](/docs/FastAPI/berichten-opslaan/eigen-sleutel): een eigen sleutel per bericht, met `import time` bovenaan je bestand.
</Regel>

<Regel n={7}>
Het endpoint geeft nu geen pagina terug, maar een opdracht aan de browser: ga naar `/berichten`. De browser doet dat meteen, en de bezoeker ziet zijn eigen bericht achteraan staan. Nu nog als JSON; in de volgende les wordt `/berichten` een echte pagina.
</Regel>

</CodeUitleg>

## Waarom 303

Zonder `status_code=303` werkt het niet. `RedirectResponse` stuurt standaard een 307, en 307 betekent: doe hetzelfde verzoek nog een keer op de nieuwe URL. Jouw verzoek was een POST, dus de browser stuurt een POST naar `/berichten`. Dat endpoint is een `@app.get`, dus je krijgt **405 Method Not Allowed**.

Een 303 zegt wél wat je bedoelt: ga naar die URL met een GET.

Eerst een POST en dan doorsturen naar een GET: dat heet het **post/redirect/get**-patroon. Bijna elke website die je gebruikt doet dit na een formulier.

## Testen

1. Vul het gastenboek in en klik Verstuur
2. Je belandt op `/berichten` en ziet je eigen bericht staan, nog als JSON
3. Druk op F5. De pagina herlaadt, zonder vraag over opnieuw versturen

:::danger[Gaat er iets mis?]
Krijg je **405 Method Not Allowed** meteen na het versturen? Dan mist `status_code=303`. Meer oplossingen staan op [Er gaat iets mis](/docs/troubleshooting).
:::

## Opdrachten

### Opdracht 1: Predict - Waar kom je uit?

{/* route-dubbel: voorspelvraag, met eigen paden zodat uitproberen niet botst met het project */}
```python
@app.post("/inschrijven")
async def inschrijven(naam: str = Form(...)):
    return RedirectResponse(url="/bedankt", status_code=303)

@app.get("/bedankt")
async def bedankt():
    return {"bericht": "Bedankt"}
```

**Vraag:** welke URL staat er in de adresbalk nadat je het formulier hebt verstuurd?

<details>
<summary>Tip</summary>

Een redirect verandert niet alleen wat je ziet, maar ook wat er in de adresbalk staat.

</details>

<details>
<summary>Antwoord</summary>

`/bedankt`. De browser volgt de redirect en vraagt die pagina op alsof je er zelf naartoe was gegaan. Van `/inschrijven` zie je niets terug.

</details>

### Opdracht 2: Run

Pas je `/gastenboek` POST-endpoint aan zodat het doorstuurt naar `/berichten`. Verstuur een bericht en kijk of je op de lijst uitkomt.

### Opdracht 3: Investigate - Zonder 303

Haal `status_code=303` weg en verstuur nog een keer.

<details>
<summary>Antwoord</summary>

Je krijgt **405 Method Not Allowed**. Zonder dat getal stuurt FastAPI een 307, en dan herhaalt de browser je POST op `/berichten`. Daar staat alleen een `@app.get`, dus het antwoord is: dit endpoint doet geen POST. Je bericht is wel opgeslagen; alleen het doorsturen ging mis. Ga je terug en verstuur je hetzelfde formulier nog een keer, dan staat het er twee keer in.

</details>

### Opdracht 4: Make - Annuleren

Maak een endpoint `/annuleren` dat niets opslaat en de bezoeker direct doorstuurt naar `/berichten`. Zet er een link naartoe op je gastenboekformulier.

<details>
<summary>Tip</summary>

Een bezoeker komt hier via een gewone link, dus het is een `@app.get`. Een redirect vanuit een GET heeft geen 303 nodig.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.get("/annuleren")
async def annuleren():
    return RedirectResponse(url="/berichten")
```

In `static/pages/gastenboek_form.html`, onder het formulier:
```html
<a href="/annuleren">Annuleren</a>
```

Hier mag de standaard 307 blijven staan: het oorspronkelijke verzoek was al een GET, dus het herhalen daarvan levert precies op wat je wilt.

</details>
