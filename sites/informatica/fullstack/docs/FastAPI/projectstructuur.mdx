# Projectstructuur

Je project groeit met de lessen mee. Elke stand hieronder is de vorige plus wat die les toevoegt. Een bestand verdwijnt alleen als een les zegt dat je het verplaatst. Bestanden die je in een opdracht maakt, zoals `contact.html` of `about.css`, staan er niet bij.

Ook de map `.venv` ontbreekt in de bomen, net als `__pycache__`, die Python zelf aanmaakt. In je Explorer zie je ze wel, naast `main.py`; je verandert er niets in.

## Bij [Je eerste endpoint](/docs/FastAPI/eerste_endpoint)

```
je-project/
└── main.py
```

Alleen een Python-bestand, meer heb je niet nodig.

## Bij [HTML in bestanden](/docs/FastAPI/html_bestanden)

```
je-project/
├── main.py
└── static/
    └── pages/
        └── home.html
```

HTML staat nu in aparte bestanden, in `static/pages/`.

## Bij [Links tussen pagina's](/docs/FastAPI/links)

```
je-project/
├── main.py
└── static/
    └── pages/
        ├── about.html
        └── home.html
```

Een tweede pagina, met een link heen en terug.

## Bij [CSS in een eigen bestand (static files)](/docs/FastAPI/static_files)

```
je-project/
├── main.py
└── static/
    ├── css/
    │   └── style.css
    └── pages/
        ├── about.html
        └── home.html
```

CSS in een eigen map, bereikbaar via `/static/css/style.css`.

## Bij [Afbeeldingen tonen](/docs/FastAPI/afbeeldingen)

```
je-project/
├── main.py
└── static/
    ├── css/

    ├── pages/
    │   ├── about.html
    │   ├── foto.html
    │   └── home.html
    └── kat.jpg
```

Afbeeldingen staan direct in de map `static`.

## Bij [Templates met Jinja2](/docs/FastAPI/templates) tot en met [Een formulier beantwoorden met een template](/docs/FastAPI/post_met_templates)

```
je-project/
├── main.py
├── static/
│   ├── css/
│   │   └── style.css
│   ├── pages/
│   │   ├── about.html
│   │   ├── foto.html
│   │   ├── groet_form.html
│   │   ├── home.html
│   │   └── naam_form.html
│   └── kat.jpg
└── templates/
    ├── dobbelsteen.html
    └── groet_resultaat.html
```

Er komt een map `templates/` bij voor Jinja2-templates. De formulieren zelf blijven vaste bestanden in `static/pages/`.

:::tip[Verschil: static/pages vs templates]
- `static/pages/`: vaste HTML-bestanden, die altijd hetzelfde zijn
- `templates/`: HTML-bestanden met `{{ variabelen }}` die Python invult
:::

## Bij [Gegevens opslaan met SqliteDict](/docs/FastAPI/database) en [Een formulier opslaan](/docs/FastAPI/post_naar_database)

```
je-project/

├── namen.db
├── test_db.py
├── static/

│   │   ├── foto.html
│   │   ├── gastenboek_form.html
│   │   ├── groet_form.html
│   │   ├── home.html
```

De `.db`-bestanden maakt `sqlitedict` zelf aan, de eerste keer dat je iets opslaat. `test_db.py` en `mijn_data.db` komen uit de proef in [Gegevens opslaan met SqliteDict](/docs/FastAPI/database); je server gebruikt ze niet.

## Compleet overzicht

| Map | Wat staat er? | Voorbeeld |
|-----|---------------|-----------|
| `/` | Python code en databases | `main.py`, `gastenboek.db`, `sessies.db` |
| `static/css/` | CSS bestanden | `style.css` |
| `static/js/` | JavaScript en htmx | `app.js`, `htmx.min.js` |
| `static/pages/` | Vaste HTML pagina's | `home.html`, `about.html` |
| `static/` | Afbeeldingen | `kat.jpg` |
| `templates/` | Jinja2 templates, ook stukken voor htmx | `berichten.html`, `berichten_lijst.html` |

**Tip:** bij zoveel bestanden komt git goed van pas. Maak een commit bij elke werkende versie; dan durf je te verbouwen, want je kunt altijd terug. Hoe je dat in VS Code doet staat in <SiteLink site="editor" to="/git/vscode/">Git in VS Code</SiteLink>.
