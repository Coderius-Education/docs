Je gastenboek slaat berichten op, maar om ze te zien moet je nog naar `/berichten` en een hoop JSON lezen. Nu zet je ze op een echte pagina.

## De for-lus in een template

Tot nu toe vulde je template één waarde in met `{{ naam }}`. Met `{% for %}` herhaalt Jinja2 een stuk HTML voor elk item in een lijst:

```html
<ul>
    {% for bericht in berichten %}
        <li>{{ bericht.naam }}: {{ bericht.bericht }}</li>
    {% endfor %}
</ul>
```

Dit werkt net als een for-lus in Python, alleen sluit je de lus af met `{% endfor %}` in plaats van met inspringen. HTML kent geen inspringing die betekenis heeft.

## De data meesturen

In [Elk bericht bewaren: een eigen sleutel](/docs/FastAPI/berichten-opslaan/eigen-sleutel) gaf `/berichten` de berichten nog als JSON terug. Vervang dat endpoint door deze versie, die alle berichten ophaalt en meestuurt onder de naam die de template gebruikt:

<CodeUitleg>

{/* route-dubbel: vervangt GET /berichten (JSON) uit Elk bericht bewaren */}
```python showLineNumbers
@app.get("/berichten")
async def berichten(request: Request):
    with SqliteDict("gastenboek.db") as db:
        alle_berichten = list(db.values())
    return templates.TemplateResponse(
        request,
        "berichten.html",
        {"berichten": alle_berichten}
    )
```

<Regel n={4}>
`db.values()` geeft alle opgeslagen berichten, zonder hun sleutels. De `list()` eromheen ken je uit [Elk bericht bewaren: een eigen sleutel](/docs/FastAPI/berichten-opslaan/eigen-sleutel), en hier is hij net zo nodig: de template loopt pas door de berichten als de database allang weer dicht is. Vergeet je hem, dan krijg je ook hier `AttributeError: 'NoneType' object has no attribute 'select'`.
</Regel>

<Regel n={8}>
De lijst gaat mee onder de naam `berichten`, en dat is precies de naam die de template in `{% for bericht in berichten %}` gebruikt.
</Regel>

</CodeUitleg>

## Compleet voorbeeld

`templates/berichten.html`:

```html
<!DOCTYPE html>
<html>
    <head>
        <title>Gastenboek</title>
        <link rel="stylesheet" href="/static/css/style.css">
    </head>
    <body>
        <h1>Gastenboek</h1>

        <ul>
            {% for bericht in berichten %}
                <li>{{ bericht.naam }}: {{ bericht.bericht }}</li>
            {% endfor %}
        </ul>

        <a href="/gastenboek">Nieuw bericht</a>
    </body>
</html>
```

1. Start je server en ga naar `http://127.0.0.1:8000/berichten`
2. Je ziet de berichten die je eerder verstuurde, nu als lijst
3. Vul het formulier op `/gastenboek` nog een keer in. Na het versturen kom je vanzelf op de lijst uit, en die is gegroeid

## Opdrachten

### Opdracht 1: Predict - Hoeveel regels?

{/* niet-compileren: fragment uit een handler */}
```python
namen = ["Jan", "Sarah", "Piet"]
return templates.TemplateResponse(request, "namen.html", {"namen": namen})
```

Template:
```html
<h1>Bezoekers</h1>
{% for naam in namen %}
    <p>{{ naam }}</p>
{% endfor %}
```

**Vraag:** hoeveel `<h1>` en hoeveel `<p>` staan er straks op de pagina?

<details>
<summary>Tip</summary>

Jinja2 herhaalt alleen wat tússen `{% for %}` en `{% endfor %}` staat. De rest staat er één keer.

</details>

<details>
<summary>Antwoord</summary>

Eén `<h1>` en drie `<p>`. De `<h1>` staat buiten de lus, dus die komt er maar één keer.

</details>

### Opdracht 2: Run

Maak `templates/berichten.html` uit het voorbeeld en pas je `/berichten` endpoint aan. Vul het gastenboek een paar keer in en kijk of je lijst groeit.

### Opdracht 3: Investigate - Endfor vergeten

Haal in je complete `berichten.html` de regel `{% endfor %}` weg en herlaad de pagina.

<details>
<summary>Antwoord</summary>

De browser zegt `Internal Server Error`. Onderaan in je terminal staat:

```
jinja2.exceptions.TemplateSyntaxError: Unexpected end of template. Jinja was looking for the following tags: 'endfor' or 'else'. The innermost block that needs to be closed is 'for'.
```

Jinja2 leest je template van boven naar beneden. De lus is nog open als het bestand ophoudt, en dan weet hij niet waar de herhaling stopt. Elke `{% for %}` heeft een `{% endfor %}` nodig. Zet de regel terug.

</details>

### Opdracht 4: Make - Nummer erbij

Zet een volgnummer voor elk bericht: "1. Jan: Hallo", "2. Sarah: Leuke site".

<details>
<summary>Tip</summary>

Jinja2 houdt zelf bij hoeveel keer de lus gedraaid heeft. Binnen een `{% for %}` kun je `{{ loop.index }}` gebruiken; die begint bij 1.

</details>

<details>
<summary>Antwoord</summary>

```html
<ul>
    {% for bericht in berichten %}
        <li>{{ loop.index }}. {{ bericht.naam }}: {{ bericht.bericht }}</li>
    {% endfor %}
</ul>
```

`loop.index` telt vanaf 1. Wil je vanaf 0 tellen, gebruik dan `loop.index0`.

</details>

### Opdracht 5: Make - Tabel met bezoekers

Toon de berichten in een `<table>` in plaats van een lijst, met twee kolommen: naam en bericht. Zorg dat de kopregel er één keer staat.

<details>
<summary>Tip</summary>

De `<tr>` met de kopjes hoort buiten de lus. Alleen de `<tr>` met de data herhaal je.

</details>

<details>
<summary>Antwoord</summary>

```html
<table>
    <tr>
        <th>Naam</th>
        <th>Bericht</th>
    </tr>
    {% for bericht in berichten %}
        <tr>
            <td>{{ bericht.naam }}</td>
            <td>{{ bericht.bericht }}</td>
        </tr>
    {% endfor %}
</table>
```

De kopregel staat buiten de lus, dus die verschijnt één keer. De rij met `<td>` staat erbinnen en komt er voor elk bericht opnieuw.

</details>
