Je lijst toont alle berichten onder elkaar, op één pagina. Op echte websites klik je op één item en krijg je een eigen pagina, met een eigen URL die je kunt delen. Daarvoor moet de URL zeggen wélk bericht je bedoelt.

## De sleutel in de URL

In [Eén route voor veel pagina's: path-parameters](/docs/FastAPI/veel-paginas/path-parameters) gaf `/dier/{naam}` elk dier een eigen pagina. Een bericht krijgt op dezelfde manier een eigen adres, met de sleutel uit de database in het pad. Een vraagteken, zoals `/zoek?term=python` uit [Een waarde na een vraagteken: query-parameters](/docs/FastAPI/veel-paginas/query-parameters), kan ook, maar voor één item is een path-parameter gebruikelijker. Zet dit endpoint onder je andere endpoints:

```python
@app.get("/bericht/{sleutel}")
async def bericht_detail(request: Request, sleutel: str):
    return {"je_vroeg_om": sleutel}
```

Ga je naar `/bericht/bericht_17` dan krijg je `{"je_vroeg_om":"bericht_17"}`, net als bij de dieren.

## Het bericht opzoeken

Met die sleutel kun je het bericht uit de database halen. Vervang je endpoint door deze versie:

{/* route-dubbel: vervangt de eerste versie van GET /bericht/{sleutel} hierboven */}
```python
@app.get("/bericht/{sleutel}")
async def bericht_detail(request: Request, sleutel: str):
    with SqliteDict("gastenboek.db") as db:
        bericht = db.get(sleutel)
    return templates.TemplateResponse(
        request,
        "bericht.html",
        {"bericht": bericht}
    )
```

`db.get(sleutel)` geeft `None` als de sleutel niet bestaat, in plaats van te crashen met een `KeyError`.

De template `templates/bericht.html` toont één bericht, met een link terug naar de lijst:

```html
<!DOCTYPE html>
<html>
    <body>
        <h1>Bericht van {{ bericht.naam }}</h1>
        <p>{{ bericht.bericht }}</p>
        <a href="/berichten">Terug naar alle berichten</a>
    </body>
</html>
```

## Linken vanuit de lijst

Om naar een bericht te linken, heeft de lijst zijn sleutel nodig. Tot nu toe stuurde `/berichten` alleen de berichten mee, via `db.values()`. Met **`db.items()`** gaan de sleutels mee. Vervang je endpoint `/berichten`:

<CodeUitleg>

{/* route-dubbel: vervangt GET /berichten uit Alles tonen, nu met db.items() */}
```python showLineNumbers
@app.get("/berichten")
async def berichten(request: Request):
    with SqliteDict("gastenboek.db") as db:
        alle_berichten = list(db.items())
    return templates.TemplateResponse(
        request,
        "berichten.html",
        {"berichten": alle_berichten}
    )
```

<Regel n={4}>
`db.items()` geeft paren: eerst de sleutel, dan het bericht. De `list()` eromheen is net zo nodig als bij `db.values()`.
</Regel>

</CodeUitleg>

In `templates/berichten.html` loop je nu over twee dingen tegelijk, en wordt de naam een link met de sleutel erin. Vervang de for-lus binnen de `<ul>` door deze:

```html
{% for sleutel, bericht in berichten %}
    <li><a href="/bericht/{{ sleutel }}">{{ bericht.naam }}</a>: {{ bericht.bericht }}</li>
{% endfor %}
```

`{% for sleutel, bericht in berichten %}` pakt elk paar uit in twee namen, net als `for sleutel, waarde in db.items():` in Python. Vergeet je de `sleutel, ` in de lus, dan wordt elk bericht een lege regel met alleen een dubbele punt: Jinja2 zoekt dan `naam` in een paar, en dat heeft geen naam.

Heb je in een opdracht `berichten` ook buiten deze lus gebruikt, zoals `berichten[-1].naam`? Pas dat dan ook aan: elk item is nu een paar, dus `berichten[-1][1].naam`.

<details>
<summary>Zo ziet je `templates/berichten.html` er nu uit</summary>

Het `{% if %}`-blok uit [Nog niets? if en else in je template](/docs/FastAPI/berichten-tonen/leeg) blijft staan; alleen de lus binnen de `<ul>` is nieuw.

```html
<!DOCTYPE html>
<html>
    <head>
        <title>Gastenboek</title>
        <link rel="stylesheet" href="/static/css/style.css">
    </head>
    <body>
        <h1>Gastenboek</h1>

        {% if berichten %}
            <ul>
                {% for sleutel, bericht in berichten %}
                    <li><a href="/bericht/{{ sleutel }}">{{ bericht.naam }}</a>: {{ bericht.bericht }}</li>
                {% endfor %}
            </ul>
        {% else %}
            <p>Nog geen berichten. Wees de eerste.</p>
        {% endif %}

        <a href="/gastenboek">Nieuw bericht</a>
    </body>
</html>
```

</details>

## Opdrachten

### Opdracht 1: Predict - Waar kom je uit?

In je database staat een bericht van Sam onder de sleutel `bericht_1767225600123456789`. Je klikt op `/berichten` op de naam Sam.

**Vraag:** welke URL staat er daarna in de adresbalk, en welke waarde krijgt `sleutel` in je functie?

<details>
<summary>Tip</summary>

Kijk naar de `href` in je template: `/bericht/{{ sleutel }}`.

</details>

<details>
<summary>Antwoord</summary>

De adresbalk toont `/bericht/bericht_1767225600123456789`, en `sleutel` is de tekst `"bericht_1767225600123456789"`. De template zette de sleutel in de link, en FastAPI haalt hem er bij `{sleutel}` weer uit.

</details>

### Opdracht 2: Run

Maak het `/bericht/{sleutel}` endpoint en de template `bericht.html`. Pas je lijst aan zodat elke naam een link is.

### Opdracht 3: Investigate - Een sleutel die niet bestaat

Ga naar `/bericht/onzin` met het tabblad Netwerk open. Wat zie je op de pagina, en welke statuscode staat in Netwerk?

<details>
<summary>Antwoord</summary>

De pagina toont "Bericht van" met een lege plek erachter, en eronder een lege regel. `db.get("onzin")` geeft `None`, en Jinja2 zet voor `{{ bericht.naam }}` dan niets neer, zonder foutmelding. In Netwerk staat `200`: voor de browser ging alles goed. Een bezoeker, en ook een zoekmachine, kan niet zien dat dit bericht niet bestaat. Dat los je op in de volgende les.

</details>

### Opdracht 4: Make - Alle berichten van één naam

Maak een route `/van/{naam}` die alle berichten toont die onder die naam zijn geschreven. Gebruik je template `berichten.html` niet; maak een eigen template `van.html` met de naam als kop en de berichten als lijst.

<details>
<summary>Tip</summary>

Loop in je endpoint door `db.values()` en zet elk bericht met `bericht["naam"] == naam` in een nieuwe lijst. Stuur die lijst en de naam mee naar de template.

</details>

<details>
<summary>Antwoord</summary>

`templates/van.html`:
```html
<!DOCTYPE html>
<html>
    <body>
        <h1>Berichten van {{ naam }}</h1>
        <ul>
            {% for bericht in berichten %}
                <li>{{ bericht.bericht }}</li>
            {% endfor %}
        </ul>
        <a href="/berichten">Alle berichten</a>
    </body>
</html>
```

```python
@app.get("/van/{naam}")
async def van(request: Request, naam: str):
    zijn_berichten = []
    with SqliteDict("gastenboek.db") as db:
        for bericht in db.values():
            if bericht["naam"] == naam:
                zijn_berichten.append(bericht)
    return templates.TemplateResponse(
        request,
        "van.html",
        {"naam": naam, "berichten": zijn_berichten}
    )
```

Een naam die niemand gebruikte, geeft een pagina met alleen de kop. De `for`-lus over `db.values()` staat binnen het `with`-blok; daarbuiten is de database dicht.

</details>
