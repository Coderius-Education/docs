# Bouw zelf — vind ook de index van het maximum

**Leerdoel:** je past het patroon aan om niet alleen de **waarde**, maar
ook de positie terug te geven.

## Opdracht

### De opdracht

Schrijf `vind_index_van_maximum(lijst)` die de index teruggeeft van het
maximum. Staat het maximum er meerdere keren, geef dan de eerste index.

- `vind_index_van_maximum([3, 7, 2, 9, 4])` → `3`
- `vind_index_van_maximum([10, 20, 20, 10])` → `1` (eerste 20)
- `vind_index_van_maximum([42])` → `0`

### Aan de slag

De startcode roept je functie aan op vier lijsten en print de gevonden
index.

Verwachte uitvoer:

```
3
1
0
1
```

<details>
<summary>Tip</summary>

Welke startwaarde kies je voor `max_index`, en met welke waarde vergelijk
je elk nieuw getal als je alleen een index bewaart?

Loop door de lijst met `enumerate` (ken je uit
[lineair zoeken, bouwsteen 1](site:algorithms/docs/lineair-zoeken/bouwen/04-doorlopen))
zodat je in elke ronde zowel de huidige index als de huidige waarde
hebt.

</details>

<details>
<summary>Antwoord</summary>

```python
def vind_index_van_maximum(lijst):
    max_index = 0
    for i, waarde in enumerate(lijst):
        if waarde > lijst[max_index]:
            max_index = i
    return max_index

print(vind_index_van_maximum([3, 7, 2, 9, 4]))    # 3
print(vind_index_van_maximum([10, 20, 20, 10]))   # 1
print(vind_index_van_maximum([42]))               # 0
```

Waarom `>` en niet `>=`?

- Met `>` blijft bij gelijke waardes de eerste index staan.
- Met `>=` wordt het de laatste.

Beide zijn geldige keuzes — kies bewust.

</details>

## Onderzoek

**Vraag:** wat geeft `vind_index_van_maximum([7, 7, 7, 7])` terug? En wat
als je `>` in je functie vervangt door `>=`?

<details>
<summary>Antwoord</summary>

Met de `>`-versie krijg je `0` terug — de eerste 7 wint, want geen latere
waarde is strikt groter. Met `>=` zou je `3` krijgen, de laatste dus.

Geen van beide is fout; het is een ontwerpkeuze. Bij gelijke
waardes, welke positie tel je als de winnaar? In de praktijk kies je
meestal de eerste, want dat is voorspelbaarder en past bij hoe lineair
zoeken werkt.

</details>

## Uitdaging (optioneel)

Schrijf `vind_alle_indexen_van_maximum(lijst)` die een lijst van alle
indexen returnt waar het maximum staat.

Verwachte uitvoer:

```
[0, 2, 4]
[2]
```

<PyRunner initialCode={`def vind_alle_indexen_van_maximum(lijst):
    # vul aan
    return []

print(vind_alle_indexen_van_maximum([5, 3, 5, 2, 5]))
print(vind_alle_indexen_van_maximum([1, 2, 3]))`} />

<details>
<summary>Tip</summary>

Welke indexen meetellen, weet je pas als je het maximum kent. Hoe kom je
daar eerst aan?

</details>

<details>
<summary>Antwoord</summary>

```python
def vind_alle_indexen_van_maximum(lijst):
    maximum = lijst[0]
    for waarde in lijst:
        if waarde > maximum:
            maximum = waarde
    indexen = []
    for i, waarde in enumerate(lijst):
        if waarde == maximum:
            indexen.append(i)
    return indexen

print(vind_alle_indexen_van_maximum([5, 3, 5, 2, 5]))   # [0, 2, 4]
print(vind_alle_indexen_van_maximum([1, 2, 3]))         # [2]
```

Zo loop je twee keer door de lijst: eerst om het maximum te vinden, dan
om de indexen te verzamelen. Het kan ook in één ronde, als je de lijst
`indexen` opnieuw begint zodra je een groter getal tegenkomt, maar twee
rondes zijn makkelijker te lezen.

</details>
