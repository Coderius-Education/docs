# Bouw zelf — vergelijk lineair en binair

**Leerdoel:** je zet beide algoritmes naast elkaar op dezelfde data en
telt het werk. De theorie wordt nu meetbaar.

## Opdracht

### De opdracht

Schrijf beide algoritmes zo dat ze het aantal vergelijkingen tellen, en
laat ze los op gesorteerde lijsten van 10 tot 100.000 getallen.

De startcode zoekt in het slechtste geval voor binair zoeken: het doel komt
niet voor en is groter dan alles in de lijst. Dan gaat binair zoeken elke
ronde naar de rechter helft, en die is bij een even aantal net één groter
dan de linker. Lineair zoeken bekijkt dan elk getal.

- `lineair_tellen(lijst, doel)` geeft het aantal vergelijkingen van lineair
  zoeken terug.
- `binair_tellen(lijst, doel)` doet hetzelfde voor binair zoeken.

### Aan de slag

:::caution
`binair_tellen` heeft een while-lus. Krimpt het zoekgebied niet in elke
ronde, dan stopt hij nooit en loopt het tabblad van de browser vast: de
speeltuin heeft geen stopknop. Kopieer je code eerst naar een kladblok.
:::

Verwachte uitvoer:

```
n        lineair    binair
10       10         4
100      100        7
1000     1000       10
10000    10000      14
100000   100000     17
```

<details>
<summary>Tip</summary>

Waar in `binair_zoek` vergelijkt de code `lijst[midden]` met het doel? Daar
hoort de teller omhoog te gaan, en wat geef je terug in plaats van een
index?

</details>

<details>
<summary>Antwoord</summary>

```python
def lineair_tellen(lijst, doel):
    vergelijkingen = 0
    for waarde in lijst:
        vergelijkingen += 1
        if waarde == doel:
            return vergelijkingen
    return vergelijkingen

def binair_tellen(lijst, doel):
    laag = 0
    hoog = len(lijst) - 1
    vergelijkingen = 0
    while laag <= hoog:
        vergelijkingen += 1
        midden = (laag + hoog) // 2
        if lijst[midden] == doel:
            return vergelijkingen
        elif lijst[midden] < doel:
            laag = midden + 1
        else:
            hoog = midden - 1
    return vergelijkingen

print(lineair_tellen(list(range(1000)), 1000))   # 1000
print(binair_tellen(list(range(1000)), 1000))    # 10
```

</details>

## Wat zie je?

Kloppen beide functies, dan print de code deze tabel:

```
n        lineair    binair
10       10         4
100      100        7
1000     1000       10
10000    10000      14
100000   100000     17
```

**Vraag:** hoeveel extra werk kost een lijst die tien keer zo lang is, bij
lineair en bij binair zoeken?

<details>
<summary>Antwoord</summary>

- Lineair: tien keer zoveel. Het werk groeit even hard als de lijst.
- Binair: drie of vier vergelijkingen extra. Elke vergelijking halveert
  wat er over is, dus een lijst die twee keer zo lang is, kost één
  vergelijking meer.

Op een lijst van een miljard zou het verschil nog groter zijn: een
miljard vergelijkingen tegenover 30.

</details>

## Uitdaging (optioneel)

### De opdracht

Komt een waarde meer dan eens voor, dan geeft `binair_zoek` de index waar
het midden toevallig landt. Bij `[1, 2, 2, 2, 3]` en doel 2 is dat index 2.
Pas binair zoeken aan zodat het de **eerste** index met die waarde
teruggeeft.

- `binair_zoek_eerste([1, 2, 2, 2, 3], 2)` → `1`
- `binair_zoek_eerste([1, 2, 2, 2, 3], 4)` → `-1`

### Aan de slag

:::caution
Je past hier een while-lus aan. Krimpt het zoekgebied niet in elke ronde,
ook niet na een match, dan stopt hij nooit en loopt het tabblad van de
browser vast. Kopieer je code eerst naar een kladblok.
:::

Verwachte uitvoer:

```
1
-1
```

<details>
<summary>Tip</summary>

Bij een match weet je dat het doel er is, maar niet of het de eerste is.
Waar kan een eerdere staan, en hoe onthoud je de match die je al had?

</details>

<details>
<summary>Antwoord</summary>

```python
def binair_zoek_eerste(lijst, doel):
    laag = 0
    hoog = len(lijst) - 1
    gevonden = -1
    while laag <= hoog:
        midden = (laag + hoog) // 2
        if lijst[midden] == doel:
            gevonden = midden
            hoog = midden - 1      # blijf links zoeken
        elif lijst[midden] < doel:
            laag = midden + 1
        else:
            hoog = midden - 1
    return gevonden

print(binair_zoek_eerste([1, 2, 2, 2, 3], 2))   # 1
print(binair_zoek_eerste([1, 2, 2, 2, 3], 4))   # -1
```

De lus stopt nog steeds: ook bij een match krimpt het zoekgebied, want
`hoog` gaat omlaag.

</details>
