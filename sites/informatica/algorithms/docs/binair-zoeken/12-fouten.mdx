# Er gaat iets mis — vier fouten

**Leerdoel:** je herkent de klassieke valkuilen van binair zoeken.

## Een kommagetal als index: `/` in plaats van `//`

{/* foutmelding-van: lijst = [1, 3, 5, 7]\nmidden = (0 + 3) / 2\nprint(lijst[midden]) */}

```
TypeError: list indices must be integers or slices, not float
```

**Oorzaak:** je berekende het midden met `/` in plaats van `//`. Die deling
geeft altijd een kommagetal, ook als hij precies uitkomt: `(0 + 6) / 2` is
`3.0`. Een index moet een geheel getal zijn, dus ook `lijst[3.0]` mag niet.

**Oplossing:** deel met `//`. Die rondt naar beneden af op een geheel getal.

{/* niet-draaien: fragment; laag en hoog komen uit de functie */}
```python
# FOUT
midden = (laag + hoog) / 2

# GOED
midden = (laag + hoog) // 2
```

Meer uitleg: [Bouwsteen 2 — het midden berekenen](site:algorithms/docs/binair-zoeken/bouwen/05-midden).

## Oneindige lus: `laag = midden`

Geen foutmelding: Python blijft rekenen en het tabblad van de browser loopt
vast, ook de Reset-knop. Sluit het tabblad en open de les opnieuw. Je code
ben je dan kwijt: kopieer hem eerst naar een kladblok als je iets uitprobeert
wat mis kan gaan.

**Oorzaak:** je schreef `laag = midden` in plaats van `laag = midden + 1`.
Bij `laag = 1, hoog = 2` blijft `midden = 1`: het zoekgebied krimpt nooit.

**Oplossing:** schrijf `laag = midden + 1`. Dan valt het onderzochte midden
af, krimpt het zoekgebied elke ronde, en stopt de lus altijd.

{/* niet-compileren: fragment; alleen de elif-tak van de vergelijking */}
```python
# FOUT
elif lijst[midden] < doel:
    laag = midden

# GOED
elif lijst[midden] < doel:
    laag = midden + 1
```

Meer uitleg: [Bouwsteen 3 — vergelijken](site:algorithms/docs/binair-zoeken/bouwen/06-vergelijken).

## Het laatste element overgeslagen: `laag < hoog`

Geen foutmelding, maar bij sommige lijsten wel een fout antwoord:
`binair_zoek([5], 5)` geeft `-1`, terwijl 5 wél in de lijst staat.

**Oorzaak:** met `while laag < hoog` slaat de lus de laatste ronde over
zodra `laag == hoog`. Dan blijft één element ongecontroleerd.

**Oplossing:** gebruik `while laag <= hoog`. Bij `laag == hoog` is er nog
één element over om te bekijken.

{/* niet-compileren: vormfragment; het lijf van de lus is weggelaten */}
```python
# FOUT
while laag < hoog:

# GOED
while laag <= hoog:
```

Meer uitleg: [Bouwsteen 4 — herhalen met een while-lus](site:algorithms/docs/binair-zoeken/bouwen/07-while).

## Een ongesorteerde lijst

Geen foutmelding, alleen een fout antwoord. Dat maakt deze fout
gevaarlijk: hij doet stilletjes het verkeerde.

**Oorzaak:** het algoritme gaat ervan uit dat het doel rechts ligt als
`lijst[midden] < doel`. Die aanname klopt alleen op een gesorteerde lijst.

**Oplossing:** sorteer de lijst eerst, en zoek in de gesorteerde versie.

{/* niet-draaien: fragment; binair_zoek staat op de compleet-pagina */}
```python
# FOUT
binair_zoek([5, 1, 4, 2, 3], 1)   # -1, terwijl 1 op index 1 staat

# GOED
binair_zoek(sorted([5, 1, 4, 2, 3]), 1)
```

Zoek je vaak in dezelfde lijst, sorteer hem dan één keer en bewaar de
gesorteerde versie. Sorteren kost werk, maar daarna is elk zoeken snel.
