# Eerst lezen, dan schrijven met PRIMM

**De tip:** laat een leerling werkende code eerst lezen en voorspellen, dan
draaien en onderzoeken, en pas daarna aanpassen en zelf maken. Wie code moet
schrijven die hij nog niet kan lezen, raadt.

**Controlevraag:** Leest en voorspelt de leerling werkende code voordat hij zelf code schrijft?

## Waar komt dit vandaan

PRIMM staat voor de vijf fasen van een les: Predict, Run, Investigate,
Modify en Make. Sue Sentance en haar collega's
bouwden het op uit eerder onderzoek naar programmeeronderwijs en uit het werk
van Vygotsky, die leren beschrijft als iets dat begint in het gesprek met
anderen en daarna pas in het eigen hoofd komt.

De volgorde keert om wat in een programmeerles vaak gebeurt. Daar krijgt een
beginner een leeg bestand en een opdracht. In PRIMM is de code er al, en van
de docent. De leerling zegt eerst wat hij denkt dat de code doet, kijkt of
dat klopt, en zoekt uit waarom. Dan verandert hij iets kleins, en pas in de
laatste fase begint hij zelf.

## Het onderzoek

Sentance, Waite en Kallia lieten docenten op dertien scholen acht tot twaalf
weken lesgeven met PRIMM, aan 493 leerlingen van 11 tot 14 jaar, met een
controlegroep ernaast. Vooraf en achteraf maakten de leerlingen een toets, en
de docenten werden geïnterviewd.

De leerlingen uit de PRIMM-lessen scoorden op de toets achteraf beter dan de
controlegroep. De docenten noemden meer voordelen, waaronder dat ze er een
klas met grote niveauverschillen mee konden lesgeven zonder leerlingen kwijt
te raken.

Sentance, S., Waite, J., & Kallia, M. (2019). *Teaching computer programming
with PRIMM: a sociocultural perspective.* Computer Science Education, 29(2–3),
136–176.

[Lees de paper (DOI)](https://doi.org/10.1080/08993408.2019.1608781)

## Hoe wij dit toepassen

In de web-cursus is elke fase een tabblad van de les, in deze volgorde. Zie
[Koppen en lijsten](site:web/docs/html-css/koppen-lijsten).

- **Predict** toont code en stelt één vraag. Het antwoord staat dichtgeklapt,
  zodat de leerling eerst zelf iets moet zeggen.
- **Probeer en onderzoek** is Run en Investigate samen: de code staat klaar
  in een oefenveld, met de onderzoeksvragen erboven en bij elke vraag een
  antwoord om te controleren.
- **Modify** geeft dezelfde code terug met een gerichte opdracht.
- **Make** begint bijna leeg. In de lessen over JavaScript zijn dat drie
  opdrachten die oplopen van aanpassen naar zelf bouwen.

Wat een site niet kan, is het gesprek. PRIMM rekent erop dat leerlingen hun
voorspelling hardop zeggen en met elkaar vergelijken. Dat deel is aan de
docent: laat tweetallen hun voorspelling eerst aan elkaar vertellen voordat
iemand op Run klikt.
