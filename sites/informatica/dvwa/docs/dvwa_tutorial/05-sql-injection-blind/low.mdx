# SQL Injection (Blind) — Low

<LabBadge status="deels" />

<Ethiek />

Soms is een webserver kwetsbaar voor SQL Injection, maar toont hij de database-output niet op je scherm. Je bent dan "blind".

<Voorkennis
  items={[
    {to: '/docs/sql_leren', label: 'Hoe een SQL-query werkt'},
  ]}
/>

## 1. Predict (Voorspel)

De server zoekt een gebruikers-ID op en verklapt alleen of het bestaat:

```php
$id = $_GET['id'];
$query = "SELECT first_name, last_name FROM users WHERE user_id = '$id'";

if ($rij) {
    echo "Gebruiker bestaat.";
} else {
    echo "Gebruiker bestaat niet.";
}
```

**Vraag:** Wat is het grootste verschil met de "gewone" SQL Injection-uitdaging in wat jij op het scherm ziet?

<details>

<summary>Antwoord</summary>

Bij gewone SQL Injection print de site echt de voornaam en achternaam, zodat je met een `UNION` hele tabellen kunt uitlezen. Hier krijg je **alleen** een vaste tekst: "bestaat" of "bestaat niet" — een ja/nee-antwoord. Er komt nooit data op je scherm. Je bent dus blind, en moet de database ondervragen met vragen waarop het antwoord ja of nee is.

</details>

## 2. Run (Uitvoeren)

Start het lab en kijk hoe de applicatie normaal reageert.

<DvwaLab module="sql_injection_blind" level="low" />

Vul ID `1` in: het scherm zegt "bestaat". Vul ID `99` in: het scherm zegt "bestaat niet". Probeer ook `2` en `3` en noteer welke bestaan.

## 3. Investigate (Onderzoeken)

Typ nu `1'` (het getal 1 met één enkel aanhalingsteken) en klik op Controleren.

**Vraag:** Wat zie je? Verandert de reactie ten opzichte van een gewoon ID? Wat zegt dat over hoe de applicatie je invoer verwerkt?

<details>

<summary>Antwoord</summary>

Je krijgt "bestaat niet", terwijl gebruiker 1 wél bestaat. Het losse aanhalingsteken breekt de SQL-syntax, de query mislukt, en de applicatie meldt daarom "bestaat niet". Dat onthult dat jouw invoer ongefilterd in de query belandt. Vanaf nu kun je ja/nee-vragen aan de database stellen via de "bestaat"/"bestaat niet"-reactie.

</details>

## 4. Modify & Make (Aanpassen & Maken)

Omdat de site kwetsbaar is, kun je vragen stellen waarop het antwoord ja of nee is. Dat heet **Boolean Based Blind SQL Injection**.

Vul deze twee payloads in en vergelijk het resultaat:
1. `1' AND '1'='1`
2. `1' AND '1'='2`

<details>

<summary>Tip</summary>

Denk aan de SQL die ontstaat (het laatste aanhalingsteken van de query sluit jouw payload netjes af):
`WHERE user_id = '1' AND '1'='1'` — altijd waar → bestaat
`WHERE user_id = '1' AND '1'='2'` — nooit waar → bestaat niet

</details>

<details>

<summary>Antwoord</summary>

De eerste toont "bestaat", de tweede "bestaat niet", want het tweede deel van de `AND` was onwaar. Daarmee heb je een kanaal om elke ja/nee-vraag aan de database te stellen.

Op een echte databaseserver vraag je zo letter voor letter naar verborgen gegevens, bijvoorbeeld met `substring()` om één teken van een wachtwoord te toetsen. In dit lab bewijs je het principe met de twee payloads hierboven.

</details>

## 5. ✓ Wat moest je zien?

:::tip[Controle]
- `1' AND '1'='1` geeft "bestaat" terug — de conditie is waar.
- `1' AND '1'='2` geeft "bestaat niet" terug — de conditie is onwaar.
- Het verschil tussen die twee bewijst dat jouw SQL-code echt door de database wordt uitgevoerd.

Krijg je bij beide payloads hetzelfde? Controleer of je de aanhalingstekens exact hebt overgetypt.
:::

## 6. Er gaat iets mis...

Blind SQL Injection is als een spelletje "Wie ben ik", waarbij je letter voor letter een database leegtrekt. Met de hand is dat eindeloos monnikenwerk. Daarom gebruiken pentesters vrijwel altijd de tool **SQLmap** in Kali Linux: die vuurt per seconde tientallen ja/nee-raadsels af en puzzelt de antwoorden vanzelf in elkaar. In dit browser-lab stel je de vragen met de hand, één payload per keer.
