# 2.3 Programma's installeren

<Voorkennis items={[{to: '/docs/linux/terminal/rechten', label: 'Eigenaar, rechten en root'}]} />

Op Windows download je een programma van een website. Op Ubuntu haal je het met **apt** uit één grote verzameling, die Ubuntu zelf bijhoudt en controleert. Probeer eerst dit:

```bash
tree
```

```
Command 'tree' not found, but can be installed with:
sudo apt install tree
```

Ubuntu kent het programma, maar het staat nog niet op je computer. Hij zegt er meteen bij hoe je het krijgt.

## sudo: even beheerder zijn

Een programma installeren verandert dingen in mappen van `root`. Dat mag jij niet, zag je in [1.7](site:dvwa/docs/linux/terminal/rechten). Met `sudo` voor een commando voer je dat ene commando uit als `root`:

```bash
sudo apt update
```

```
[sudo] password for sam:
```

Ubuntu vraagt jouw wachtwoord, dat van stap 3 bij de installatie. Je ziet weer niets terwijl je typt. Daarna onthoudt `sudo` het een kwartier.

`apt update` haalt de nieuwste lijst op van wat er te krijgen is. Doe het voor je iets installeert: met een oude lijst zoekt apt naar versies die er niet meer zijn.

## Installeren

```bash
sudo apt install tree
```

apt laat zien wat hij gaat installeren en hoeveel ruimte het kost, en vraagt `Do you want to continue? [Y/n]`. Druk op Enter: de hoofdletter `Y` is het antwoord dat geldt als je niets typt.

Nu werkt het:

```bash
tree ~
```

## Voorspel

Je typt `apt install tree`, zonder `sudo`. Wat gebeurt er?

<details>
<summary>Klik hier als je het hebt geprobeerd</summary>

```
E: Could not open lock file /var/lib/dpkg/lock-frontend - open (13: Permission denied)
E: Unable to acquire the dpkg frontend lock (/var/lib/dpkg/lock-frontend), are you root?
```

apt mag als `sam` niet in `/var/lib/dpkg` schrijven, en vraagt aan het eind of je wel `root` bent. Er gaat niets kapot: zet `sudo` ervoor en het lukt.

</details>

## Alles bijwerken

Ubuntu krijgt steeds updates, ook voor beveiligingslekken. Zo installeer je ze allemaal:

```bash
sudo apt update
sudo apt upgrade
```

Op een server doe je dat vaak. Een lek dat al gedicht is maar bij jou nog openstaat, is de makkelijkste weg naar binnen.

## Opdracht 2.3.a: een koe die praat

Het pakket `cowsay` tekent een koe die zegt wat jij wilt.

1. Installeer het pakket.
2. Laat de koe `Hallo uit Linux` zeggen.

<details>
<summary>Klik hier voor een tip</summary>

Eerst de lijst bijwerken, dan installeren, beide met `sudo`. Daarna is `cowsay` een commando: de tekst komt erachter.

</details>

<details>
<summary>Klik hier voor het antwoord</summary>

```bash
sudo apt update
sudo apt install cowsay
cowsay "Hallo uit Linux"
```

Krijg je `cowsay: command not found`, sluit dan Ubuntu en open hem opnieuw, of start het met het volledige pad: `/usr/games/cowsay`.

</details>

## Er gaat iets mis

### Unable to locate package

```
E: Unable to locate package tre
```

**Oorzaak:** apt kent geen pakket met die naam. Meestal een typfout, of je hebt `apt update` nog nooit gedaan.

**Oplossing:** controleer de naam, en doe eerst `sudo apt update`.

### Are you root?

```
E: Unable to acquire the dpkg frontend lock (/var/lib/dpkg/lock-frontend), are you root?
```

**Oorzaak:** je bent `sudo` vergeten.

**Oplossing:**

```bash
# FOUT
apt install tree

# GOED
sudo apt install tree
```

### sudo voor alles

**Oorzaak:** het werkte met `sudo`, dus je zet het overal voor.

**Oplossing:** gebruik `sudo` alleen als het moet. Een bestand dat je met `sudo` maakt in je thuismap, is van `root`, en dat mag je daarna zelf niet meer veranderen. En een typfout met `sudo rm` kan alles weggooien, ook van Ubuntu zelf.
