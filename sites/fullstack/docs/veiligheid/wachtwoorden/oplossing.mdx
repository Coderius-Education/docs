# Wachtwoorden: de oplossing

<Voorkennis
  items={[
    {site: 'python', to: '/docs/fouten/16a-try-en-except', label: 'Try en except'},
  ]}
/>

In [de zwakheid](./zwakheid) zag je twee problemen met `sha256`: hetzelfde
wachtwoord geeft dezelfde hash, en een computer rekent er miljoenen per seconde
uit. Een hash die speciaal voor wachtwoorden gemaakt is, lost allebei op:

- Hij doet er een **zout** bij (Engels: *salt*): een stukje toeval dat per
  wachtwoord anders is. Hetzelfde wachtwoord geeft dan elke keer een andere
  hash.
- Hij is **expres traag**. Voor jouw server maakt dat niets uit: die rekent
  één hash uit als iemand inlogt. Voor een aanvaller die miljoenen pogingen wil
  doen, wel.

De aanbevolen hash voor wachtwoorden heet **Argon2**. Installeer hem met
`python -m pip install argon2-cffi`.

## Argon2 in je server

<CodeUitleg>

```python showLineNumbers
from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError
from fastapi import FastAPI, Form
from sqlitedict import SqliteDict

app = FastAPI()
ph = PasswordHasher()

@app.post("/registreer")
async def registreer(naam: str = Form(...), wachtwoord: str = Form(...)):
    with SqliteDict("gebruikers.db") as db:
        db[naam] = ph.hash(wachtwoord)
        db.commit()
    return {"bericht": f"Welkom, {naam}"}

@app.post("/inloggen")
async def inloggen(naam: str = Form(...), wachtwoord: str = Form(...)):
    with SqliteDict("gebruikers.db") as db:
        opgeslagen = db.get(naam)
    if opgeslagen is None:
        return {"bericht": "Naam of wachtwoord klopt niet"}
    try:
        ph.verify(opgeslagen, wachtwoord)
    except VerifyMismatchError:
        return {"bericht": "Naam of wachtwoord klopt niet"}
    return {"bericht": "Ingelogd"}
```

<Regel n={7}>
Een `PasswordHasher` rekent Argon2-hashes uit, met instellingen die veilig zijn voor nu.
</Regel>

<Regel n={12}>
`ph.hash` maakt de hash, met een nieuw zout erin. Die hash gaat de database in, het wachtwoord zelf niet.
</Regel>

<Regel n={20} tot={21}>
Bestaat de naam niet, dan zeg je hetzelfde als bij een fout wachtwoord. Zo verraad je niet welke namen er wél een account hebben.
</Regel>

<Regel n={22} tot={25}>
`ph.verify` rekent de hash van het ingetypte wachtwoord uit met het zout uit de opgeslagen hash, en vergelijkt. Klopt het niet, dan gooit hij een `VerifyMismatchError`, en die vang je af.
</Regel>

</CodeUitleg>

Gooi eerst `gebruikers.db` weg: daar staan nog wachtwoorden of `sha256`-hashes
in uit stap 1. Start je server en draai `registreer.py` en
`lees_database.py` opnieuw:

```
sara: $argon2id$v=19$m=65536,t=3,p=4$X9osXpPM7r/H8fRMyPCE+Q$etV1GLXtmN/ukJB8evD8IraZPm5jt9WONzagikgkl+Y
alex: $argon2id$v=19$m=65536,t=3,p=4$rUMs0YcTR/e1avCX01vrOg$W5Flt1JoAhellSR9YETx3ZUDa6GbtisQrZIkWsRXIVs
noor: $argon2id$v=19$m=65536,t=3,p=4$l6Q0IpvVuX7N4fBZ5PP8nw$sxddUqdV6fZMCPkJwMIlVqfwTAmuvgOQYSZjhAH2H5Q
```

Jouw codes zijn anders, want het zout is elke keer nieuw. Sara en Noor hebben
nog steeds hetzelfde wachtwoord, maar dat zie je nergens meer aan. Een
opgeslagen hash bestaat uit stukken, gescheiden door een `$`:

| Stuk | Betekent |
|:---:|:---:|
| `argon2id` | welk algoritme |
| `m=65536,t=3,p=4` | hoeveel geheugen en rekenwerk het kost |
| `X9osXpPM7r/H8fRMyPCE+Q` | het zout |
| `etV1GLXt…` | de hash zelf |

Omdat het zout en de instellingen in de hash staan, heeft `ph.verify` genoeg
aan de opgeslagen code en het ingetypte wachtwoord.

## Doe de test opnieuw

Probeer in te loggen met een scriptje `inloggen.py`:

```python
import httpx

adres = "http://127.0.0.1:8000/inloggen"

pogingen = [("sara", "welkom123"), ("sara", "welkom124"), ("bob", "welkom123")]
for naam, wachtwoord in pogingen:
    antwoord = httpx.post(adres, data={"naam": naam, "wachtwoord": wachtwoord})
    print(f"{naam}, {wachtwoord}: {antwoord.json()['bericht']}")
```

Uitvoer:

```
sara, welkom123: Ingelogd
sara, welkom124: Naam of wachtwoord klopt niet
bob, welkom123: Naam of wachtwoord klopt niet
```

Draai daarna `raad.py` uit stap 1. Het vindt niets meer: het vergelijkt
`sha256`-hashes, en die staan er niet meer in.

Een slimme aanvaller past zijn script natuurlijk aan en probeert elk woord met
`ph.verify`. Dan vindt hij `welkom123` alsnog: een wachtwoord uit elke
woordenlijst blijft zwak. Het verschil zit in de snelheid. Meet het zelf met
`snelheid.py`:

```python
import hashlib
import time

from argon2 import PasswordHasher

ph = PasswordHasher()

begin = time.perf_counter()
for i in range(100000):
    hashlib.sha256(f"poging{i}".encode()).hexdigest()
duur = time.perf_counter() - begin
print(f"sha256: {100000 / duur:.0f} pogingen per seconde")

begin = time.perf_counter()
for i in range(20):
    ph.hash(f"poging{i}")
duur = time.perf_counter() - begin
print(f"argon2: {20 / duur:.0f} pogingen per seconde")
```

Op de computer waarop deze les is getest, gaf dat:

```
sha256: 2194629 pogingen per seconde
argon2: 19 pogingen per seconde
```

Jouw getallen zijn anders, maar het verschil is steeds ongeveer honderdduizend
keer. Een woordenlijst van een miljoen wachtwoorden kost met `sha256` een halve
seconde, en met Argon2 ruim veertien uur, voor één gebruiker. Heeft elke gebruiker
een eigen zout, dan begint de aanvaller bij de volgende gebruiker weer
opnieuw.

## Er gaat iets mis

Je vervangt `ph.verify` door een vergelijking:

{/* niet-compileren: fragment uit de functie inloggen, met return buiten een functie */}

```python
# FOUT
if ph.hash(wachtwoord) == opgeslagen:
    return {"bericht": "Ingelogd"}

# GOED
try:
    ph.verify(opgeslagen, wachtwoord)
except VerifyMismatchError:
    return {"bericht": "Naam of wachtwoord klopt niet"}
return {"bericht": "Ingelogd"}
```

Er komt geen foutmelding, maar niemand kan meer inloggen, ook niet met het
goede wachtwoord.

**Oorzaak:** `ph.hash` maakt elke keer een nieuw zout, dus elke keer een andere
hash. Twee hashes van hetzelfde wachtwoord zijn nooit gelijk.

**Oplossing:** vergelijk nooit zelf. `ph.verify` haalt het zout uit de
opgeslagen hash en rekent daarmee.

Staat er nog een oude `sha256`-hash of een wachtwoord als gewone tekst in de database,
dan krijgt `inloggen.py` `500 Internal Server Error` terug, en eindigt de
foutmelding in de terminal van je server met
`argon2.exceptions.InvalidHashError`: `ph.verify` herkent die code niet als
Argon2-hash. Gooi `gebruikers.db` weg en registreer opnieuw.

## Opdrachten

### Opdracht 1: Predict - Twee keer hashen

```python
from argon2 import PasswordHasher

ph = PasswordHasher()
print(ph.hash("welkom123") == ph.hash("welkom123"))
```

**Vraag:** print dit `True` of `False`?

<details>
<summary>Tip</summary>

Wat doet `ph.hash` elke keer anders dan `sha256`?

</details>

<details>
<summary>Antwoord</summary>

`False`. Elke `ph.hash` krijgt een nieuw zout, dus twee hashes van hetzelfde
wachtwoord verschillen. Daarom controleer je met `ph.verify`, dat `True`
teruggeeft als het wachtwoord klopt.

</details>

### Opdracht 2: Run

Zet Argon2 in je server, gooi `gebruikers.db` weg, en draai `registreer.py`,
`lees_database.py` en `inloggen.py`. Kloppen de drie inlogpogingen met de
uitvoer hierboven?

<details>
<summary>Antwoord</summary>

Ja: Sara komt binnen met `welkom123`, en niet met `welkom124`. Bob heeft geen
account en krijgt dezelfde melding als een fout wachtwoord. In
`lees_database.py` zie je alleen `$argon2id$`-codes, bij Sara en Noor
verschillend.

</details>

### Opdracht 3: Make - Wachtwoord wijzigen (uitdaging)

Maak een endpoint `/wijzig` met drie velden: `naam`, `oud` en `nieuw`. Klopt
het oude wachtwoord, dan bewaar je de hash van het nieuwe. Klopt het niet, dan
verandert er niets.

<details>
<summary>Tip</summary>

Het begin is hetzelfde als bij `/inloggen`: opzoeken en `ph.verify` met het
oude wachtwoord. Pas als dat lukt, open je de database opnieuw en zet je
`ph.hash(nieuw)` onder de naam.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.post("/wijzig")
async def wijzig(naam: str = Form(...), oud: str = Form(...), nieuw: str = Form(...)):
    with SqliteDict("gebruikers.db") as db:
        opgeslagen = db.get(naam)
    if opgeslagen is None:
        return {"bericht": "Naam of wachtwoord klopt niet"}
    try:
        ph.verify(opgeslagen, oud)
    except VerifyMismatchError:
        return {"bericht": "Naam of wachtwoord klopt niet"}
    with SqliteDict("gebruikers.db") as db:
        db[naam] = ph.hash(nieuw)
        db.commit()
    return {"bericht": "Wachtwoord gewijzigd"}
```

Het oude wachtwoord moet kloppen, anders kan iemand die jouw laptop even
gebruikt je wachtwoord veranderen.

</details>
