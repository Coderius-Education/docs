# Ophalen zonder herladen

Versturen gaat nu zonder dat de pagina verspringt. Ophalen kan op dezelfde manier: een knop die de lijst met berichten ververst, en daarna een lijst die zichzelf ververst. Zet je server open voor de klas, dan zie je de berichten van anderen verschijnen zonder dat iemand op F5 drukt.

## Een template voor alleen de lijst

Het antwoord van de server is straks niet één zin, maar de hele lijst. Zet die in een eigen template, `templates/berichten_lijst.html`, zonder `<html>` of `<head>` eromheen. Het is een stuk pagina, geen hele pagina:

```html
<ul>
    {% for sleutel, bericht in berichten %}
        <li>{{ bericht.naam }}: {{ bericht.bericht }}</li>
    {% endfor %}
</ul>
```

## Een endpoint voor alleen de lijst

```python
@app.get("/berichten/lijst")
async def berichten_lijst(request: Request):
    with SqliteDict("gastenboek.db") as db:
        alle_berichten = list(db.items())
    return templates.TemplateResponse(
        request,
        "berichten_lijst.html",
        {"berichten": alle_berichten}
    )
```

Dit is het endpoint uit [Een lijst tonen](/docs/FastAPI/lijst_tonen) met een andere template. Ga in je browser naar `/berichten/lijst`: je ziet een kale lijst zonder kop of opmaak. Dit endpoint is niet bedoeld om zelf te bezoeken, maar om een stuk van een pagina te vervangen.

## Een knop die ververst

Koppel htmx in de `<head>` van `berichten.html`, geef de lijst een id en zet er een knop bij:

```html
<button hx-get="/berichten/lijst" hx-target="#berichten-lijst">Ververs</button>

<div id="berichten-lijst">
    <ul>
        {% for sleutel, bericht in berichten %}
            <li>{{ bericht.naam }}: {{ bericht.bericht }}</li>
        {% endfor %}
    </ul>
</div>
```

**`hx-get`** doet wat een link doet, een GET naar dat pad, maar de pagina blijft staan. Het antwoord komt in `#berichten-lijst`, in plaats van de lijst die er stond.

## Vanzelf verversen

Een knop vraagt om een klik. Met **`hx-trigger`** kies je een ander moment:

```html
<div id="berichten-lijst" hx-get="/berichten/lijst" hx-trigger="every 10s">
```

Elke tien seconden haalt htmx de lijst op en zet hem op zijn plek. Een `hx-target` is hier niet nodig: zonder doel komt het antwoord in het element zelf, en dat is precies de bedoeling.

Kijk in de terminal. Elke tien seconden komt er een regel bij, ook als er niets veranderd is. Dat is de vraag die straks in [Server of browser?](/docs/FastAPI/server-of-browser) terugkomt: hoe vaak gebeurt het? Elke tien seconden is te doen. Bij elke toetsaanslag niet.

## Testen

1. Maak de template en het endpoint, en zet de knop Ververs op je berichtenpagina
2. Open `/berichten` in twee tabbladen. Verstuur een bericht via `/gastenboek` in het ene en klik in het andere op Ververs: het bericht staat er
3. Zet `hx-trigger="every 10s"` op de lijst en herhaal stap 2 zonder te klikken

:::danger[Gaat er iets mis?]
Gebeurt er niets bij een klik? Kijk in Netwerk. Een rode regel met 404 betekent dat het pad in `hx-get` niet bestaat als endpoint. htmx zet een foutantwoord nooit in de pagina, dus je ziet het alleen daar. Bekijk de [troubleshooting pagina](/docs/troubleshooting) voor meer oplossingen.
:::

## Opdrachten

### Opdracht 1: Predict - Elke seconde

Je zet `hx-trigger="every 1s"` op de lijst en laat de pagina een minuut open staan zonder iets te doen.

**Vraag:** hoeveel regels komen er in de terminal bij?

<details>
<summary>Tip</summary>

htmx weet niet of er iets veranderd is. Het vraagt, en de server antwoordt.

</details>

<details>
<summary>Antwoord</summary>

Zestig. Eén per seconde, ook al is de lijst al die tijd hetzelfde. Met tien bezoekers zijn dat 600 verzoeken per minuut voor niets. Kies het interval dus naar wat de bezoeker nodig heeft, niet naar wat kan.

</details>

### Opdracht 2: Run

Bouw de knop en de automatische verversing. Zet je server open voor iemand naast je, zoals in [Laat het aan anderen zien](/docs/FastAPI/laat-het-zien), en laat die een bericht sturen.

### Opdracht 3: Investigate - De server staat uit

Stop je server met Ctrl+C en klik op Ververs. Kijk daarna in Netwerk.

<details>
<summary>Antwoord</summary>

Op de pagina gebeurt niets: de oude lijst blijft staan. In Netwerk staat een rode regel met `(mislukt)`, zonder statuscode, want er was geen server om te antwoorden. htmx laat de pagina met rust als een verzoek mislukt. Dat is prettig voor de bezoeker, maar het betekent ook dat jij fouten alleen in Netwerk ziet.

</details>

### Opdracht 4: Make - Eén keer schrijven

De lijst staat nu twee keer in je project: in `berichten.html` en in `berichten_lijst.html`. Verander je één van de twee, dan loopt de ander achter. Zorg dat hij maar één keer bestaat.

<details>
<summary>Tip</summary>

Jinja2 kan een template in een andere template plakken, met `{% include "bestandsnaam" %}`. Dat werkt ook binnen een `<div>`.

</details>

<details>
<summary>Antwoord</summary>

In `templates/berichten.html`:

```html
<div id="berichten-lijst" hx-get="/berichten/lijst" hx-trigger="every 10s">
    {% include "berichten_lijst.html" %}
</div>
```

De pagina en het antwoord van `/berichten/lijst` gebruiken nu precies dezelfde HTML. Verander je iets aan een regel van de lijst, dan verandert het op beide plekken.

</details>

### Opdracht 5: Make - Nieuwste eerst

Maak een knop "Nieuwste eerst" die de lijst omgekeerd ophaalt. Het omdraaien gebeurt op de server.

<details>
<summary>Tip</summary>

Een query-parameter uit [GET vs POST](/docs/FastAPI/get_vs_post): `hx-get="/berichten/lijst?volgorde=nieuw"`. In je endpoint een parameter `volgorde: str = "oud"`, en `alle_berichten.reverse()` als hij op `"nieuw"` staat.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.get("/berichten/lijst")
async def berichten_lijst(request: Request, volgorde: str = "oud"):
    with SqliteDict("gastenboek.db") as db:
        alle_berichten = list(db.items())
    if volgorde == "nieuw":
        alle_berichten.reverse()
    return templates.TemplateResponse(
        request,
        "berichten_lijst.html",
        {"berichten": alle_berichten}
    )
```

```html
<button hx-get="/berichten/lijst?volgorde=nieuw" hx-target="#berichten-lijst">Nieuwste eerst</button>
```

De server bepaalt de volgorde en stuurt het stuk opnieuw. Dat kost een verzoek, maar werkt ook als de lijst te lang is om helemaal op de pagina te zetten.

</details>
