# Doorsturen na opslaan (redirect)

Je gastenboek werkt, maar na het versturen van een bericht sta je op een doodlopende pagina. Druk je daar op F5, dan vraagt je browser of je het formulier nog een keer wilt versturen — en zo krijg je hetzelfde bericht twee keer in je database. In deze les stuur je de bezoeker na het opslaan terug naar de lijst.

## RedirectResponse

Met `RedirectResponse` stuur je de browser door naar een andere URL:

<CodeUitleg>

```python showLineNumbers
from fastapi.responses import RedirectResponse

@app.post("/gastenboek")
async def gastenboek_opslaan(naam: str = Form(...), bericht: str = Form(...)):
    with SqliteDict("gastenboek.db") as db:
        db[f"bericht_{time.time_ns()}"] = {"naam": naam, "bericht": bericht}
        db.commit()
    return RedirectResponse(url="/berichten", status_code=303)
```

<Regel n={6}>
Het opslaan is hetzelfde als in [Een formulier opslaan](/docs/FastAPI/post_naar_database): een eigen sleutel per bericht, met `import time` bovenaan je bestand.
</Regel>

<Regel n={8}>
Hier zit het verschil met de vorige les. Het endpoint geeft geen pagina terug, maar een opdracht aan de browser: ga naar `/berichten`. De browser doet dat meteen, en de bezoeker ziet zijn eigen bericht bovenaan de lijst verschijnen. Waarom er `status_code=303` bij moet, staat hieronder.
</Regel>

</CodeUitleg>

## Waarom 303

`status_code=303` lijkt een detail, maar zonder dat getal werkt het niet. `RedirectResponse` stuurt standaard een **307**, en 307 betekent: doe hetzelfde verzoek nog een keer op de nieuwe URL. Jouw verzoek was een POST, dus de browser stuurt een POST naar `/berichten` — en dat endpoint is een `@app.get`. Resultaat: **405 Method Not Allowed**.

**303** betekent wél wat je bedoelt: ga naar die URL met een GET.

Deze combinatie — POST, dan doorsturen naar een GET — heet het **post/redirect/get**-patroon. Bijna elke website die je gebruikt doet dit na een formulier.

## Verwijderen en terug

Hetzelfde patroon werkt ook voor verwijderen: een formulier met een POST, en daarna terug naar de lijst. Om één bericht aan te wijzen heb je zijn sleutel nodig. Stuur de berichten daarom mét hun sleutel naar de template, met `db.items()` in plaats van `db.values()`:

<CodeUitleg>

```python showLineNumbers
@app.get("/berichten")
async def berichten(request: Request):
    with SqliteDict("gastenboek.db") as db:
        alle_berichten = list(db.items())
    return templates.TemplateResponse(
        request,
        "berichten.html",
        {"berichten": alle_berichten}
    )

@app.post("/verwijderen")
async def verwijderen(sleutel: str = Form(...)):
    with SqliteDict("gastenboek.db") as db:
        if sleutel in db:
            del db[sleutel]
            db.commit()
    return RedirectResponse(url="/berichten", status_code=303)
```

<Regel n={4}>
`db.items()` geeft paren: eerst de sleutel, dan het bericht.
</Regel>

<Regel n={14} tot={16}>
`del db[sleutel]` haalt het bericht weg. De `if sleutel in db` voorkomt een crash als iemand twee keer op verwijderen klikt.
</Regel>

<Regel n={17}>
Daarna weer terug naar de lijst, met 303, precies zoals na het opslaan.
</Regel>

</CodeUitleg>

In `templates/berichten.html` loop je nu over twee dingen tegelijk, en krijgt elk bericht een eigen formuliertje:

```html
{% for sleutel, bericht in berichten %}
    <li>
        {{ bericht.naam }}: {{ bericht.bericht }}
        <form method="post" action="/verwijderen">
            <input type="hidden" name="sleutel" value="{{ sleutel }}">
            <button type="submit">Verwijderen</button>
        </form>
    </li>
{% endfor %}
```

Een `<input type="hidden">` ziet de bezoeker niet, maar hij gaat wel mee met het formulier. Zo weet `/verwijderen` welk bericht weg moet.

## Testen

1. Vul het gastenboek in en klik Verstuur
2. Je belandt op `/berichten` en ziet je eigen bericht staan
3. Druk op F5. De pagina herlaadt, zonder vraag over opnieuw versturen
4. Klik bij een bericht op Verwijderen. Je blijft op de lijst, en het bericht is weg

:::danger[Gaat er iets mis?]
Krijg je **405 Method Not Allowed** meteen na het versturen? Dan mist `status_code=303`. Bekijk de [troubleshooting pagina](/docs/troubleshooting) voor meer oplossingen.
:::

## Opdrachten

### Opdracht 1: Predict - Waar kom je uit?

```python
@app.post("/opslaan")
async def opslaan(naam: str = Form(...)):
    return RedirectResponse(url="/bedankt", status_code=303)

@app.get("/bedankt")
async def bedankt():
    return {"bericht": "Bedankt"}
```

**Vraag:** welke URL staat er in de adresbalk nadat je het formulier hebt verstuurd?

<details>
<summary>Tip</summary>

Een redirect verandert niet alleen wat je ziet, maar ook wat er in de adresbalk staat.

</details>

<details>
<summary>Antwoord</summary>

`/bedankt`. De browser volgt de redirect en vraagt die pagina op alsof je er zelf naartoe was gegaan. Van `/opslaan` zie je niets terug.

</details>

### Opdracht 2: Run

Pas je `/gastenboek` POST-endpoint aan zodat het doorstuurt naar `/berichten`. Verstuur een bericht en kijk of je op de lijst uitkomt.

### Opdracht 3: Investigate - Zonder 303

Haal `status_code=303` weg en verstuur nog een keer.

<details>
<summary>Antwoord</summary>

Je krijgt **405 Method Not Allowed**. Zonder dat getal stuurt FastAPI een 307, en dan herhaalt de browser je POST op `/berichten`. Daar staat alleen een `@app.get`, dus het antwoord is: dit endpoint doet geen POST.

</details>

### Opdracht 4: Make - Annuleren

Maak een endpoint `/annuleren` dat niets opslaat en de bezoeker direct terugstuurt naar het formulier op `/gastenboek`. Zet er een link naartoe op je berichtenpagina.

<details>
<summary>Tip</summary>

Dit endpoint wordt met een gewone link bezocht, dus het is een `@app.get`. Een redirect vanuit een GET heeft geen 303 nodig.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.get("/annuleren")
async def annuleren():
    return RedirectResponse(url="/gastenboek")
```

In `templates/berichten.html`:
```html
<a href="/annuleren">Nieuw bericht schrijven</a>
```

Hier mag de standaard 307 blijven staan: het oorspronkelijke verzoek was al een GET, dus het herhalen daarvan levert precies op wat je wilt.

</details>

### Opdracht 5: Make - Een melding na verwijderen

Laat na het verwijderen bovenaan de lijst "Bericht verwijderd" zien. Bij een bezoek aan `/berichten` zonder verwijderen staat die zin er niet.

<details>
<summary>Tip</summary>

Stuur door naar `/berichten?verwijderd=1`. Het stuk na het vraagteken kun je in het endpoint uitlezen, zoals in [GET vs POST](/docs/FastAPI/get_vs_post). Geef het een standaardwaarde, zodat `/berichten` zonder vraagteken ook werkt, en gebruik `{% if %}` in de template.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.get("/berichten")
async def berichten(request: Request, verwijderd: int = 0):
    with SqliteDict("gastenboek.db") as db:
        alle_berichten = list(db.items())
    return templates.TemplateResponse(
        request,
        "berichten.html",
        {"berichten": alle_berichten, "verwijderd": verwijderd}
    )

@app.post("/verwijderen")
async def verwijderen(sleutel: str = Form(...)):
    with SqliteDict("gastenboek.db") as db:
        if sleutel in db:
            del db[sleutel]
            db.commit()
    return RedirectResponse(url="/berichten?verwijderd=1", status_code=303)
```

Bovenaan `templates/berichten.html`:
```html
{% if verwijderd %}
    <p>Bericht verwijderd</p>
{% endif %}
```

</details>
