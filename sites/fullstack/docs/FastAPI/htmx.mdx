# Zonder herladen met htmx

<Voorkennis
  items={[
    {site: 'web', to: '/docs/js-basics/scriptjs', label: 'Een script koppelen met script src'},
  ]}
/>

Na het versturen van een bericht verspringt de pagina: de browser gaat naar `/gastenboek`, krijgt een omleiding, en laadt `/berichten` helemaal opnieuw. In deze les blijft de pagina staan. De browser stuurt het formulier op de achtergrond, en de server stuurt één zin terug die onder het formulier verschijnt. Daar gebruik je **htmx** voor: een bestand dat je HTML twee nieuwe attributen geeft. Je schrijft er zelf geen JavaScript voor.

## Waar het bestand komt

Maak een map `static/js/` en zet daar <a href="/htmx/htmx.min.js" download>htmx.min.js</a> in (versie 2.0.10):

```
je-project/
├── main.py
├── static/
│   ├── css/
│   ├── js/
│   │   └── htmx.min.js
│   └── pages/
│       └── gastenboek_form.html
└── templates/
```

Het is dezelfde versie als op [htmx.org](https://htmx.org/docs/#installing). Door het bestand in je eigen project te zetten werkt je site ook op een netwerk dat externe scripts blokkeert, zoals op school. Aan `main.py` verandert niets: `app.mount` serveert de map `static` al.

## Twee attributen op je formulier

Open `static/pages/gastenboek_form.html`. Koppel htmx in de `<head>`, en vervang `method` en `action` door `hx-post`:

```html
<!DOCTYPE html>
<html>
    <head>
        <script src="/static/js/htmx.min.js"></script>
    </head>
    <body>
        <h1>Gastenboek</h1>
        <form hx-post="/gastenboek" hx-target="#antwoord">
            <input type="text" name="naam" placeholder="Je naam" required>
            <input type="text" name="bericht" placeholder="Je bericht" required>
            <button type="submit">Verstuur</button>
        </form>
        <p id="antwoord"></p>
    </body>
</html>
```

**`hx-post`** doet wat `method="post"` en `action` samen deden, met één verschil: htmx stuurt het verzoek, en de browser blijft op de pagina. **`hx-target`** zegt waar het antwoord van de server komt: in het element met id `antwoord`, de lege `<p>` onder het formulier.

## Eén regel anders in het endpoint

<CodeUitleg>

```python showLineNumbers
from fastapi.responses import HTMLResponse

@app.post("/gastenboek")
async def gastenboek_opslaan(naam: str = Form(...), bericht: str = Form(...)):
    with SqliteDict("gastenboek.db") as db:
        db[f"bericht_{time.time_ns()}"] = {"naam": naam, "bericht": bericht}
        db.commit()
    return HTMLResponse(f"Bedankt, {naam}. Je bericht staat in het gastenboek.")
```

<Regel n={4} tot={7}>
Dit is je endpoint uit [Terug naar de lijst](/docs/FastAPI/redirect), ongewijzigd. Voor je Python-code maakt het niet uit of htmx het formulier stuurde of de browser zelf.
</Regel>

<Regel n={8}>
Hier zat `return RedirectResponse(url="/berichten", status_code=303)`. Dat hoeft niet meer: de browser is nooit weggegaan. Het antwoord is één zin HTML, en htmx zet die in `#antwoord`.
</Regel>

</CodeUitleg>

## Kijk wat er over de lijn gaat

Open het tabblad **Netwerk** zoals in [Kijken wat de browser doet](/docs/FastAPI/devtools-netwerk) en verstuur een bericht. Er komt één regel bij, en de pagina wordt niet opnieuw geladen:

<DevtoolsPaneel tab="Netwerk">
  <NetwerkTabel rijen={[{ naam: 'gastenboek', status: 200, type: 'xhr', grootte: '61 B' }]} />
</DevtoolsPaneel>

Het type is `xhr`: een verzoek dat een script stuurde, geen pagina die de browser opvroeg. Klik de regel aan. Bij **Reactie** staat alleen je zin, geen `<html>` en geen `<head>`. Bij **Headers** stuurde htmx `HX-Request: true` mee, zodat een server kan zien dat het verzoek van htmx komt.

In de terminal staat één regel, `POST /gastenboek 200 OK`. Geen omleiding, geen tweede GET.

## Testen

1. Download `htmx.min.js` naar `static/js/` en pas `gastenboek_form.html` aan
2. Verander de `return` in je POST-endpoint
3. Verstuur een bericht: de zin verschijnt onder het formulier, de pagina verspringt niet en de adresbalk blijft `/gastenboek`
4. Ga naar `/berichten`: het bericht staat in de lijst

:::danger[Gaat er iets mis?]
Verschijnt na het versturen een hele pagina onder je formulier, met een kop erin? Dan geeft je endpoint nog een omleiding terug; htmx zet alles wat binnenkomt in het doel. Verspringt de pagina en komt er `?naam=` in de adresbalk? Dan is htmx niet geladen: kijk in Netwerk of `htmx.min.js` een 200 kreeg. Bekijk de [troubleshooting pagina](/docs/troubleshooting) voor meer oplossingen.
:::

## Opdrachten

### Opdracht 1: Predict - Zonder doel

Je haalt `hx-target` van het formulier af, zodat er alleen `hx-post="/gastenboek"` staat, en verstuurt een bericht.

**Vraag:** waar komt de zin terecht?

<details>
<summary>Tip</summary>

htmx moet het antwoord ergens kwijt. Als jij geen plek aanwijst, kiest het de plek die het al kent.

</details>

<details>
<summary>Antwoord</summary>

In het formulier zelf. Zonder `hx-target` zet htmx het antwoord in het element waar het attribuut op staat, en dat is de `<form>`. De invoervelden en de knop zijn weg; er staat een zin voor in de plaats. Het endpoint deed niets fout, de HTML kwam alleen op de verkeerde plek.

</details>

### Opdracht 2: Run

Bouw het voorbeeld na en verstuur drie berichten achter elkaar. Kijk bij elk bericht in de terminal en in Netwerk.

### Opdracht 3: Investigate - De omleiding terugzetten

Zet in het POST-endpoint de oude regel terug, `return RedirectResponse(url="/berichten", status_code=303)`, en verstuur een bericht.

<details>
<summary>Antwoord</summary>

Je hele berichtenpagina verschijnt in de `<p>` onder het formulier, met kop en al. htmx volgt de omleiding net als de browser, krijgt daardoor de complete pagina van `/berichten` terug, en zet die netjes in het doel. Een endpoint dat voor htmx werkt geeft een stukje terug, nooit een omleiding.

</details>

### Opdracht 4: Make - Leeg formulier

Na het versturen blijft je tekst in de velden staan. Zorg dat het formulier leeg is zodra het antwoord binnen is.

<details>
<summary>Tip</summary>

htmx stuurt na elk verzoek een gebeurtenis `after-request`. Met `hx-on::after-request="..."` koppel je daar één regel aan, en een formulier maak je leeg met `reset()`.

</details>

<details>
<summary>Antwoord</summary>

```html
<form hx-post="/gastenboek" hx-target="#antwoord" hx-on::after-request="this.reset()">
```

`this` is het formulier zelf, en `reset()` zet alle velden terug naar hun beginwaarde. Dit is de enige regel JavaScript in deze les, en hij staat in de HTML.

</details>

### Opdracht 5: Make - Tel mee

Laat de zin ook zeggen hoeveel berichten er nu in het gastenboek staan: "Bedankt, Sam. Er staan nu 4 berichten in het gastenboek."

<details>
<summary>Tip</summary>

Binnen het `with`-blok weet je hoeveel sleutels de database heeft: `len(db)`. Bewaar dat in een variabele voordat het blok sluit.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.post("/gastenboek")
async def gastenboek_opslaan(naam: str = Form(...), bericht: str = Form(...)):
    with SqliteDict("gastenboek.db") as db:
        db[f"bericht_{time.time_ns()}"] = {"naam": naam, "bericht": bericht}
        db.commit()
        aantal = len(db)
    return HTMLResponse(f"Bedankt, {naam}. Er staan nu {aantal} berichten in het gastenboek.")
```

Het getal komt van de server, dus het klopt ook als iemand anders intussen een bericht stuurde.

</details>
