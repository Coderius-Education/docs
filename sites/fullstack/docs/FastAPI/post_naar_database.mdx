Wat een bezoeker in een formulier invult, zet je nu in een database. Dan staat het er nog als je de server stopt. Eerst bewaar je één naam, daarna bouw je een gastenboek dat alle berichten bewaart.

## Voorbeeld: Naam opslaan

### Formulier (`static/pages/naam_opslaan.html`):

```html
<!DOCTYPE html>
<html>
    <body>
        <h1>Bewaar je naam</h1>
        <form method="post" action="/opslaan">
            <input type="text" name="naam" required>
            <button type="submit">Opslaan</button>
        </form>
    </body>
</html>
```

### Endpoints (`main.py`):

Zet bij je imports bovenaan:

```python
from sqlitedict import SqliteDict
```

En onder je andere endpoints:

<CodeUitleg>

```python showLineNumbers
@app.get("/opslaan")
async def naam_formulier():
    return FileResponse("static/pages/naam_opslaan.html")

@app.post("/opslaan")
async def naam_opslaan(naam: str = Form(...)):
    with SqliteDict("namen.db") as db:
        db["laatste_naam"] = naam
        db.commit()

    return {"bericht": f"'{naam}' opgeslagen!"}
```

<Regel n={5} tot={6}>
Het POST-endpoint uit [Een formulier versturen (POST)](/docs/FastAPI/forms): `naam` komt uit het formulier.
</Regel>

<Regel n={7} tot={9}>
Nieuw is wat je ermee doet. Binnen het `with`-blok open je de database, zet je de naam onder de sleutel `laatste_naam` en schrijf je hem weg met `commit()`. Elke nieuwe naam overschrijft de vorige, want de sleutel is steeds dezelfde.
</Regel>

<Regel n={11}>
Het antwoord komt ná het `with`-blok: de database is dan al netjes gesloten.
</Regel>

</CodeUitleg>

## Data terug lezen

<CodeUitleg>

```python showLineNumbers
@app.get("/toon_naam")
async def toon_naam():
    with SqliteDict("namen.db") as db:
        naam = db.get("laatste_naam", "Nog niets opgeslagen")
    return {"naam": naam}
```

<Regel n={4}>
`db.get(sleutel, standaard)` geeft de standaardwaarde terug als de sleutel nog niet bestaat, in plaats van te crashen. Zo werkt de pagina ook vóór de eerste keer opslaan.
</Regel>

</CodeUitleg>

## De naam testen

1. Ga naar `http://127.0.0.1:8000/opslaan`
2. Vul een naam in en klik Opslaan
3. **Stop de server** en start opnieuw
4. Ga naar `http://127.0.0.1:8000/toon_naam`. Je naam staat er nog: hij is bewaard in `namen.db`.

## Meer dan één bericht: het gastenboek

<details>
<summary>Voorspel: je slaat eerst "Jan" op, dan "Sarah". Wat staat er in de database?</summary>

Alleen "Sarah". Allebei gaan ze onder de sleutel `laatste_naam`, en een nieuwe waarde onder dezelfde sleutel overschrijft de oude.

</details>

Voor een gastenboek wil je elk bericht bewaren. Dan heeft elk bericht een eigen sleutel nodig. `time.time_ns()` geeft het aantal nanoseconden sinds 1970: bij elk bericht een ander getal, dus een nieuwe sleutel. Dit gastenboek bouw je in de volgende lessen verder uit, dus maak het echt.

### Formulier (`static/pages/gastenboek_form.html`):

```html
<!DOCTYPE html>
<html>
    <body>
        <h1>Gastenboek</h1>
        <form method="post" action="/gastenboek">
            <input type="text" name="naam" placeholder="Je naam" required>
            <input type="text" name="bericht" placeholder="Je bericht" required>
            <button type="submit">Verstuur</button>
        </form>
    </body>
</html>
```

### Endpoints (`main.py`, onder de endpoints van de naam):

Zet `import time` bovenaan je `main.py`, bij de andere imports.

<CodeUitleg>

```python showLineNumbers
@app.get("/gastenboek")
async def gastenboek_form():
    return FileResponse("static/pages/gastenboek_form.html")

@app.post("/gastenboek")
async def gastenboek_opslaan(naam: str = Form(...), bericht: str = Form(...)):
    with SqliteDict("gastenboek.db") as db:
        sleutel = f"bericht_{time.time_ns()}"
        db[sleutel] = {"naam": naam, "bericht": bericht}
        db.commit()
    return {"bericht": "Bedankt voor je bericht"}

@app.get("/berichten")
async def berichten():
    with SqliteDict("gastenboek.db") as db:
        alle_berichten = list(db.values())
    return {"berichten": alle_berichten}
```

<Regel n={8}>
Zo krijgt elk bericht een nieuwe sleutel, zoals `bericht_1767225600123456789`, en overschrijven twee berichten elkaar niet meer.
</Regel>

<Regel n={9}>
De waarde is een dictionary met beide velden. Zo blijft bij elkaar wat bij elkaar hoort.
</Regel>

<Regel n={16}>
`db.values()` geeft alle waarden, zonder sleutels, maar haalt ze pas op als iets erdoorheen loopt. `list()` doet dat meteen, binnen het `with`-blok. Zonder `list()` loopt FastAPI er pas doorheen als hij de JSON maakt, en dan is de database al dicht: je krijgt `AttributeError: 'NoneType' object has no attribute 'select'`.
</Regel>

</CodeUitleg>

:::caution
Gebruik `time.time_ns()` (nanoseconden) en niet `int(time.time())` (hele seconden). Twee berichten die binnen dezelfde seconde binnenkomen, krijgen anders dezelfde sleutel, en dan overschrijft het tweede het eerste.
:::

## Het gastenboek testen

1. Ga naar `http://127.0.0.1:8000/gastenboek` en verstuur twee berichten.
2. Ga naar `http://127.0.0.1:8000/berichten`. Je ziet ze allebei, als JSON.
3. Stop de server, start hem opnieuw en kijk nog een keer: ze staan er nog.

:::danger[Gaat er iets mis?]
Blijft je data niet bewaard? Kijk dan of je `db.commit()` niet bent vergeten. Meer oplossingen staan op [Er gaat iets mis](/docs/troubleshooting).
:::

## Opdrachten

### Opdracht 1: Predict - Hoeveel berichten?

Iemand haalt `time.time_ns()` weg en schrijft `sleutel = "bericht"`. Daarna verstuurt iemand drie berichten. Wat laat `/berichten` zien?

<details>
<summary>Tip</summary>

Hoeveel verschillende sleutels zijn er dan?

</details>

<details>
<summary>Antwoord</summary>

Eén bericht: het laatste. Alle drie gaan onder de sleutel `bericht`, dus elk nieuw bericht overschrijft het vorige.

</details>

### Opdracht 2: Run

Maak de naam en het gastenboek uit deze les. Test of de berichten bewaard blijven door de server te stoppen en opnieuw te starten.

### Opdracht 3: Investigate - Wat staat er echt in?

Laat `/berichten` ook de sleutels zien: vervang `list(db.values())` door `list(db.items())`. Wat verandert er in de JSON?

<details>
<summary>Antwoord</summary>

Elk bericht wordt een paar: eerst de sleutel, dan de dictionary, zoals `["bericht_1767225600123456789", {"naam": "Sam", "bericht": "Hoi"}]`. Aan de getallen zie je in welke volgorde de berichten binnenkwamen. De sleutel heb je later nodig om één bericht aan te wijzen.

</details>

### Opdracht 4: Make - Score opslaan

Maak een formulier met een number input voor een game score. Sla de score op in `scores.db` en maak een endpoint om de score te bekijken.

<details>
<summary>Tip</summary>

Gebruik `<input type="number" name="score">` in je HTML en `score: int = Form(...)` in Python. Maak een apart GET endpoint dat `db.get("score", 0)` teruggeeft.

</details>

<details>
<summary>Antwoord</summary>

`static/pages/score_form.html`:
```html
<!DOCTYPE html>
<html>
    <body>
        <h1>Game Score</h1>
        <form method="post" action="/score">
            <input type="number" name="score" required>
            <button type="submit">Opslaan</button>
        </form>
    </body>
</html>
```

```python
@app.get("/score")
async def score_form():
    return FileResponse("static/pages/score_form.html")

@app.post("/score")
async def score_opslaan(score: int = Form(...)):
    with SqliteDict("scores.db") as db:
        db["score"] = score
        db.commit()
    return {"bericht": f"Score {score} opgeslagen!"}

@app.get("/toon_score")
async def toon_score():
    with SqliteDict("scores.db") as db:
        score = db.get("score", 0)
    return {"score": score}
```

</details>

### Opdracht 5: Make - Hoeveel berichten

Maak een endpoint `/aantal` dat teruggeeft hoeveel berichten er in het gastenboek staan: `{"aantal":3}`.

<details>
<summary>Tip</summary>

`len(db)` geeft het aantal sleutels in de database, net als bij een dictionary.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.get("/aantal")
async def aantal():
    with SqliteDict("gastenboek.db") as db:
        hoeveel = len(db)
    return {"aantal": hoeveel}
```

</details>

Je berichten staan nu in de database, maar `/berichten` geeft ze nog als JSON terug. In [Alles tonen: een for-lus in je template](/docs/FastAPI/lijst_tonen) zet je ze op een echte pagina.
