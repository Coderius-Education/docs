# Verwijderen zonder herladen

In [Terug naar de lijst](/docs/FastAPI/redirect) verwijderde je een bericht met een formulier, een POST en een omleiding. Met htmx verdwijnt het bericht ter plekke, na een bevestiging, en gebruik je het werkwoord dat ervoor bedoeld is.

## Het werkwoord DELETE

GET haalt op, POST stuurt in. HTTP kent meer werkwoorden, en **DELETE** zegt precies wat het doet. Een formulier zonder htmx kan alleen GET en POST; htmx kan ze allemaal. Het endpoint:

<CodeUitleg>

```python showLineNumbers
from fastapi.responses import HTMLResponse

@app.delete("/bericht/{sleutel}")
async def bericht_verwijderen(sleutel: str):
    with SqliteDict("gastenboek.db") as db:
        if sleutel not in db:
            raise HTTPException(status_code=404, detail="Dit bericht bestaat niet")
        del db[sleutel]
        db.commit()
    return HTMLResponse("")
```

<Regel n={3}>
`@app.delete` in plaats van `@app.post`. De sleutel komt uit het pad, zoals bij [Eén bericht tonen](/docs/FastAPI/detailpagina).
</Regel>

<Regel n={6} tot={7}>
Bestaat het bericht niet meer, dan is het antwoord een 404, net als op de detailpagina. Wat htmx daarmee doet zie je bij de opdrachten.
</Regel>

<Regel n={10}>
Het antwoord is leeg, en dat is de bedoeling: htmx zet "niets" op de plek van het bericht.
</Regel>

</CodeUitleg>

## De knop

In `templates/berichten_lijst.html` krijgt elk bericht een id en een knop:

```html
<li id="bericht-{{ sleutel }}">
    <a href="/bericht/{{ sleutel }}">{{ bericht.naam }}</a>: {{ bericht.bericht }}
    <button hx-delete="/bericht/{{ sleutel }}"
            hx-target="#bericht-{{ sleutel }}"
            hx-swap="outerHTML"
            hx-confirm="Dit bericht verwijderen?">Verwijderen</button>
</li>
```

Drie attributen die je nog niet had. **`hx-delete`** stuurt een DELETE naar het pad. **`hx-swap`** zegt hoe het antwoord in het doel komt: standaard is dat `innerHTML`, alles bínnen het doel vervangen; `outerHTML` vervangt het doel zelf. Met een leeg antwoord verdwijnt zo het hele `<li>`. **`hx-confirm`** laat de browser eerst de vraag stellen; klik je op Annuleren, dan gaat er geen verzoek.

## Testen

1. Maak het endpoint en de knop
2. Klik op Verwijderen en bevestig: het bericht is weg, de rest van de lijst staat er nog, de pagina is niet herladen
3. Druk op F5: het bericht is echt weg, want de server heeft het uit de database gehaald
4. Kijk in Netwerk: een regel `bericht_...` met type `xhr` en status 200

:::danger[Gaat er iets mis?]
Gebeurt er niets na het bevestigen? Kijk in Netwerk. Een rode regel met 404 of 500 betekent dat je endpoint een fout gaf, en htmx zet een foutantwoord nooit in de pagina. Krijg je 405? Dan staat er `@app.post` waar `@app.delete` moet staan. Bekijk de [troubleshooting pagina](/docs/troubleshooting) voor meer oplossingen.
:::

## Opdrachten

### Opdracht 1: Predict - Zonder hx-swap

Je haalt `hx-swap="outerHTML"` van de knop af en verwijdert een bericht.

**Vraag:** wat blijft er op de pagina staan?

<details>
<summary>Tip</summary>

Zonder `hx-swap` vervangt htmx wat er bínnen het doel staat. Het doel is het `<li>`.

</details>

<details>
<summary>Antwoord</summary>

Een leeg opsommingsteken. De naam, het bericht en de knop zijn weg, want die stonden binnen het `<li>`, maar het `<li>` zelf blijft staan. In de database is het bericht wel verwijderd; alleen de pagina laat een leeg puntje achter.

</details>

### Opdracht 2: Run

Bouw het endpoint en de knop. Verwijder een bericht en controleer met F5 dat het echt weg is.

### Opdracht 3: Investigate - Twee keer verwijderen

Open `/berichten` in twee tabbladen. Verwijder hetzelfde bericht in het ene tabblad, en daarna in het andere.

<details>
<summary>Antwoord</summary>

In het tweede tabblad gebeurt niets: het bericht blijft staan. In Netwerk staat een rode regel met 404, want je endpoint zei "Dit bericht bestaat niet". htmx laat de pagina met rust bij een fout, dus de bezoeker ziet een bericht dat er niet meer is, tot hij op F5 drukt. Dat is de keerzijde van niet herladen: de pagina kan achterlopen op de server.

</details>

### Opdracht 4: Make - Alles wissen

Maak een knop "Alles wissen" die het hele gastenboek leegt, na een bevestiging.

<details>
<summary>Tip</summary>

Een DELETE-endpoint op `/berichten` dat alle sleutels weghaalt. Het doel is de hele lijst, en het antwoord is de lijst-template, die dan "Nog geen berichten" toont.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.delete("/berichten")
async def alles_wissen(request: Request):
    with SqliteDict("gastenboek.db") as db:
        for sleutel in list(db.keys()):
            del db[sleutel]
        db.commit()
    return templates.TemplateResponse(request, "berichten_lijst.html", {"berichten": []})
```

```html
<button hx-delete="/berichten" hx-target="#berichten-lijst" hx-confirm="Alle berichten verwijderen?">Alles wissen</button>
```

De `list()` om `db.keys()` is nodig: je mag niet uit een database verwijderen terwijl je er nog doorheen loopt.

</details>

### Opdracht 5: Make - Het aantal klopt weer

Heb je in [Zonder herladen met htmx](/docs/FastAPI/htmx) het aantal berichten boven de lijst gezet? Verwijder dan een bericht en kijk naar dat getal.

<details>
<summary>Tip</summary>

Het getal staat in `berichten_lijst.html`, maar verwijderen vervangt alleen één `<li>`. Laat het endpoint de hele lijst teruggeven en richt de knop op `#berichten-lijst`.

</details>

<details>
<summary>Antwoord</summary>

```python
@app.delete("/bericht/{sleutel}")
async def bericht_verwijderen(request: Request, sleutel: str):
    with SqliteDict("gastenboek.db") as db:
        if sleutel not in db:
            raise HTTPException(status_code=404, detail="Dit bericht bestaat niet")
        del db[sleutel]
        db.commit()
        alle_berichten = list(db.items())
    return templates.TemplateResponse(
        request,
        "berichten_lijst.html",
        {"berichten": alle_berichten}
    )
```

```html
<button hx-delete="/bericht/{{ sleutel }}" hx-target="#berichten-lijst" hx-confirm="Dit bericht verwijderen?">Verwijderen</button>
```

De `hx-swap` mag weg, want je vervangt nu de inhoud van de lijst. Dit is de afweging bij elk htmx-endpoint: een klein stuk terugsturen is zuinig, een groter stuk houdt alles wat erin staat kloppend.

</details>
