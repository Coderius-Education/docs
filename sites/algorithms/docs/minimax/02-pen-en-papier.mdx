# Doe het met pen en papier

**Leerdoel:** je voert minimax zelf uit op twee voorbeelden — een
abstracte boom met cijfers, en dan een echt tic-tac-toe eindspel waarvan
je de hele boom tekent en doorloopt. Geen Python.

## Deel 1 — een abstracte boom

We beginnen makkelijk: een boom waar de bladeren al cijfers hebben (de
uitkomst is gegeven). Wij rekenen alleen de MIN- en MAX-knopen uit.

```
                 ▲ MAX
              ╱    │    ╲
             A     B     C
             │     │     │
            ▼MIN  ▼MIN  ▼MIN
            ╱╲    ╱╲    ╱╲
           3  5  2  9  6  0
```

MAX heeft drie keuzes: tak `A`, `B` of `C`. Onder elk staat MIN met
twee opties. De cijfers onderaan zijn utilities (hoger = beter voor MAX,
lager = beter voor MIN).

### Stap 1 — reken **van onderop** elk MIN-niveau uit

Een MIN-knoop kiest het **laagste** kind:

- Tak `A`: `min(3, 5)` = **3**
- Tak `B`: `min(2, 9)` = **2**
- Tak `C`: `min(6, 0)` = **0**

De boom wordt:

```
                 ▲ MAX
              ╱    │    ╲
              3    2    0
```

### Stap 2 — MAX kiest het **hoogste** kind

`max(3, 2, 0)` = **3**.

Beste zet voor MAX: **tak `A`**. Eindwaarde van het spel bij optimaal
spel: **3**.

### Wat had je verwacht?

> Op het eerste gezicht lijkt tak `B` aantrekkelijk: daar staat de
> **9**, het hoogste blad van de hele boom. Maar MIN zou daar nooit voor
> kiezen — die pakt de **2**. Alleen tak `A` garandeert MAX een uitkomst
> van 3.

Pas op: het kind dat MIN kiest, is niet het "hoge" maar het "lage".
Daarom is het hoogste blad misleidend.

## Deel 2 — de boom van een echt eindspel

Nu echt. Een positie waar nog drie vakjes leeg zijn. **X is aan zet.**

```
 X | X | O
-----------
 O | O | X
-----------
 . | . | .          (. = leeg)
```

Posities op het bord — we gebruiken `(rij, kolom)`-coördinaten met (0,0)
linksboven. De drie lege vakjes zijn `(2,0)`, `(2,1)` en `(2,2)`.

Kijk eerst even goed. O heeft twee stenen op de diagonaal van
rechtsboven naar linksonder: `(0,2)` en `(1,1)`. Eén O op `(2,0)` en O
wint. Onthoud dat, maar reken het níét als regel mee: minimax kent geen
"blokkeren". Het rekent alleen.

X heeft als doel `+1` (X-win), O-win is `-1`, een vol bord zonder
winnaar is `0`.

### Stap 1 — teken de boom

Bovenaan staat het bord van nu, met X aan zet: een MAX-knoop. Elke tak
eronder is een zet van X. Onder elke zet komt O aan zet: een MIN-knoop
met twee takken. Daaronder is nog één vakje over, dus X's laatste zet
ligt vast. Zo ziet de lege boom eruit, nog zonder waardes:

```
                        ▲ MAX   X aan zet
             ╱             │             ╲
        X→(2,0)         X→(2,1)         X→(2,2)
          ▼MIN            ▼MIN            ▼MIN
         ╱    ╲          ╱    ╲          ╱    ╲
     O→(2,1) O→(2,2) O→(2,0) O→(2,2) O→(2,0) O→(2,1)
        │       │       │       │       │       │
       ...     ...     ...     ...     ...     ...
```

Elke `...` is een bord waar het spel klaar is, of waar X nog precies
één vakje kan vullen. Die borden werk je zo uit.

### Stap 2 — loop de linkertak af: X speelt `(2,0)`

```
 X | X | O
 O | O | X
 X | . | .
```

Geen drie op een rij. **O is aan zet** (MIN). O heeft twee opties.

O speelt `(2,1)`. Dan blijft alleen `(2,2)` over, en X moet daar spelen:

```
 X | X | O
 O | O | X
 X | O | X
```

Geen drie op een rij, bord vol → **remise**, utility **0**.

O speelt `(2,2)`. X vult `(2,1)`:

```
 X | X | O
 O | O | X
 X | X | O
```

Weer geen drie op een rij, bord vol → utility **0**.

MIN kiest het laagste van `0` en `0`: **0**. De tak `X→(2,0)` is dus
**0** waard.

### Stap 3 — de middentak: X speelt `(2,1)`

```
 X | X | O
 O | O | X
 . | X | .
```

O is aan zet. O speelt `(2,0)`:

```
 X | X | O
 O | O | X
 O | X | .
```

Diagonaal `(0,2) (1,1) (2,0)` is `O O O` — **O wint**. Terminal,
utility **-1**. Geen verdere zetten.

O speelt `(2,2)`. X vult `(2,0)`:

```
 X | X | O
 O | O | X
 X | X | O
```

Vol, geen winnaar → utility **0**.

MIN kiest `min(-1, 0)` = **-1**. De tak `X→(2,1)` is **-1** waard: als
X daar speelt, wint O.

### Stap 4 — de rechtertak: X speelt `(2,2)`

```
 X | X | O
 O | O | X
 . | . | X
```

O speelt `(2,0)`: diagonaal `O O O`, **O wint**, utility **-1**.

O speelt `(2,1)`. X vult `(2,0)`:

```
 X | X | O
 O | O | X
 X | O | X
```

Vol, geen winnaar → utility **0**.

MIN kiest `min(-1, 0)` = **-1**.

### Stap 5 — terug naar de wortel

Nu staan er waardes onder alle drie de takken. Vul ze in de boom in:

```
                        ▲ MAX   max(0, -1, -1) = 0
             ╱             │             ╲
        X→(2,0)         X→(2,1)         X→(2,2)
          ▼ 0            ▼ -1            ▼ -1
         ╱    ╲          ╱    ╲          ╱    ╲
        0      0       -1      0       -1      0
```

X kiest het hoogste:

| X-zet | MIN kiest daaronder | waarde van de tak |
|:---:|:---:|:---:|
| `(2,0)` | `min(0, 0)` | **0** |
| `(2,1)` | `min(-1, 0)` | **-1** |
| `(2,2)` | `min(-1, 0)` | **-1** |

X speelt **`(2,0)`** en de uitkomst bij perfect spel is **0**: remise.

Zie je wat er gebeurde? X "blokkeert" O's diagonaal, maar niet omdat
iemand die regel heeft geprogrammeerd. De boom wijst de blokkade
vanzelf aan: de twee andere zetten hebben een `-1` eronder hangen, en
MIN pakt die.

## Het recept in woorden

```
1. Begin onderaan met posities die "klaar" zijn (terminal).
2. Bereken voor elke terminal de utility: +1 / -1 / 0.
3. Ga één niveau omhoog:
   - Was MAX aan zet? → neem het hoogste kind.
   - Was MIN aan zet? → neem het laagste kind.
4. Herhaal tot je bij de wortel bent.
5. De zet die de waarde van de wortel opleverde, is de beste zet.
```

## Wat dit oplevert voor het coderen

In Python wordt dit een **recursieve** functie: `max_value(bord)` roept
`min_value` aan op elk kind, en die roept weer `max_value` aan, tot een
terminal bord. Dezelfde boom, in dezelfde volgorde: eerst de linkertak
helemaal naar beneden, dan de middentak, dan de rechter. Bij
[bouwsteen 8](./bouwen/14-helpers) loop je precies deze boom nog een
keer, maar dan met de code.
