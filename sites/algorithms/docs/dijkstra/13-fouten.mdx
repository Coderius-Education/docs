# Er gaat iets mis — top-3 fouten

**Leerdoel:** je herkent de drie klassieke valkuilen bij het bouwen van
Dijkstra.

## Edge maar één kant op zetten

Geen foutmelding — wél een **fout antwoord**. Sommige nodes blijven op
`inf` staan terwijl ze wel bereikbaar zijn.

**Oorzaak:** in een niet-gerichte graph moet elke verbinding **twee
keer** in de dict staan. Mis je er één, dan denkt het algoritme dat die
kant niet bestaat.

```python
# FOUT — A → B staat alleen onder A
graph = {
    'A': [('B', 4)],
    'B': [],            # ← B kan niet terug naar A
}

# GOED
graph = {
    'A': [('B', 4)],
    'B': [('A', 4)],
}
```

**Tip:** bouw de dict programmatisch op uit een **lijst van edges**, dan
kun je geen kant vergeten:

```python
edges = [('A', 'B', 4), ('A', 'C', 2), ('B', 'D', 1), ('C', 'D', 8)]
graph = {}
for u, v, w in edges:
    if u not in graph:
        graph[u] = []
    if v not in graph:
        graph[v] = []
    graph[u].append((v, w))
    graph[v].append((u, w))
```

## `bezocht.add()` vergeten — oneindige lus

Geen foutmelding — Python loopt **oneindig** door. De browser-tab bevriest,
en de Reset-knop reageert dan ook niet meer, want Python draait in dezelfde
tab als de les. Sluit de tab en open de les opnieuw. Je code ben je dan
kwijt, dus kopieer hem eerst naar een kladblok als je iets uitprobeert wat
mis kan gaan.

**Oorzaak:** zonder `bezocht.add(huidige)` blijf je dezelfde node steeds
opnieuw kiezen. De hoofdlus eindigt nooit.

```python
while True:
    huidige = kies_volgende(afstanden, bezocht)
    if huidige is None:
        break
    # bezocht.add(huidige) ← VERGETEN!
    for buur, gewicht in graph[huidige]:
        ...
```

**Oplossing:** markeer de node zodra je hem gekozen hebt, vóór je
opnieuw kiest:

```python
huidige = kies_volgende(afstanden, bezocht)
if huidige is None:
    break
bezocht.add(huidige)
for buur, gewicht in graph[huidige]:
    ...
```

Of de regel vóór of ná de relax-lus staat maakt niet uit — die lus kijkt
niet naar `bezocht`. Dat hij er staat wel.

## Negatieve gewichten gebruiken

Geen foutmelding — wél een **stilletjes verkeerd antwoord**.

**Oorzaak:** Dijkstra gaat ervan uit dat een node die "klaar" is zijn
afstand niet meer kan verbeteren. Een negatieve edge kan dat omgooien:
een node die al klaar was wordt alsnog korter, maar zijn buren zijn al
uitgerekend met de oude afstand.

Dit voorbeeld heeft eenrichtingswegen: elke edge staat maar aan één
kant in de dict. Dat moet wel, want een negatieve weg die je ook terug
mag nemen is een rondje dat elke keer goedkoper wordt, en dan bestaat
er geen kortste route.


`D` hoort 0 te zijn: `A → C → B → D` is 3 − 4 + 1 = 0. Dijkstra zegt 2.
Wat er gebeurde: `B` werd klaar verklaard op afstand 1 en `D` kreeg
1 + 1 = 2. Pas daarna kwam `C` aan de beurt en zakte `B` naar −1, maar
`B` was al klaar, dus niemand rekende `D` opnieuw uit.

</details>

**Oplossing:** voor negatieve gewichten gebruik je *Bellman-Ford*. Dat
is een ander algoritme, niet Dijkstra.

Voor typische routekaarten, vluchtkosten, of netwerkvertragingen zijn
alle gewichten positief — daar is Dijkstra perfect voor.
