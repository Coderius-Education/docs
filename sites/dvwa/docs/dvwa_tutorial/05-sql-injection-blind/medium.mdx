# SQL Injection (Blind) — Medium

Op het Medium level is het invulveld een dropdown geworden en zet de backend de waarde om naar een getal.

> **Labbeperking:** De echte Medium-aanval is *time-based* en leunt op `SLEEP()`, een MySQL-functie. Dit browser-lab draait op SQLite (dat geen `SLEEP()` kent) en zet de dropdown-waarde bovendien om naar een geheel getal. Je ziet hier dus de verdediging, maar de timing-aanval zelf voer je uit op een [lokale DVWA-installatie](/docs/dvwa_installatie).

## 1. Predict (Voorspel)

Soms meldt de applicatie niet eens "bestaat" of "bestaat niet" — de pagina ziet er in beide gevallen hetzelfde uit. Hoe stel je dán een ja/nee-vraag aan de server?

<details>

<summary>Antwoord</summary>

Met **Time-Based Blind SQL Injection**. Je laat de database *alleen als je bewering waar is* een paar seconden wachten voordat ze antwoordt. Krijg je direct antwoord, dan was de bewering onwaar; duurt het lang, dan was ze waar. De laadtijd is je enige signaal.

</details>

## 2. Run (Uitvoeren)

Start het lab en bekijk het formulier.

<DvwaLab module="sql_injection_blind" level="medium" />

Je ziet een dropdown waarin je niet vrij kunt typen. Kies ID `1` en klik op Controleren. De backend zet je keuze om naar een getal met `(int)`.

## 3. Investigate (Onderzoeken)

Bekijk in de broncode (**Bekijk broncode**) hoe de backend de invoer verwerkt.

**Vraag:** Wat doet `(int)$_POST['id']` met een payload als `1 AND SLEEP(5)`? Waarom is dat hier een probleem voor de aanvaller?

<details>

<summary>Antwoord</summary>

`(int)"1 AND SLEEP(5)"` levert gewoon `1` op: PHP leest het getal aan het begin en gooit de rest weg. Van jouw injectie blijft niets over. Deze cast is een echte verdediging: alleen een geheel getal komt in de query terecht. Op een echte DVWA (MySQL) ontbreekt die cast juist, en dáár slaagt de time-based aanval wel.

</details>

## 4. Modify & Make (Aanpassen & Maken)

Op een echte MySQL-DVWA zou je de aanval zo uitvoeren. Lees de stappen door; uitproberen doe je op je lokale installatie (zie de Labbeperking).

<details>

<summary>Tip</summary>

Als de backend de waarde niet naar een getal zou casten, kon je via F12 de `value` van een `<option>` veranderen in een payload met `SLEEP(5)`.

</details>

<details>

<summary>Antwoord</summary>

Verander via F12 een optie naar `<option value="1 AND SLEEP(5)">`, selecteer die en klik op Submit. Op een kwetsbare MySQL-server wacht de pagina dan 5 seconden — het bewijs dat je payload de query bereikt. In dit lab gebeurt dat niet, doordat de `(int)`-cast alleen de `1` doorlaat.

</details>

## 5. ✓ Wat moest je zien?

:::tip[Controle]
- In dit lab reageert de pagina altijd direct: de `(int)`-cast houdt je payload tegen.
- In de broncode zie je dat alleen een geheel getal in de query komt.
- Op een echte MySQL-DVWA (zonder die cast) zou `1 AND SLEEP(5)` de pagina juist 5 seconden laten wachten.
:::

## 6. Er gaat iets mis...

Je verwacht een lijst met data, zoals bij gewone SQL-injectie, maar die komt niet. Dat hoort zo: dit is *blinde* injectie. De pagina toont nooit data — je enige signaal is de reactie (bestaat/bestaat niet) of, bij de time-based variant, de laadtijd. Kijk dus naar het gedrag, niet naar de inhoud. En bedenk: in dit lab blokkeert de `(int)`-cast de injectie, dus verwacht hier geen vertraging.
