# SQL Injection — High

Op het hoge niveau probeert de applicatie de schade te beperken door de query af te kappen met `LIMIT 1`.

## 1. Predict (Voorspel)

De ontwikkelaar plakt jouw invoer nog steeds rechtstreeks in de query, maar zet er `LIMIT 1` achter in de hoop dat een aanval hooguit één rij kan lekken:

```php
$id = $_GET['id'];
$query  = "SELECT first_name, last_name FROM users WHERE user_id = '$id' LIMIT 1";
```

**Vraag:** Waarom dacht de ontwikkelaar dat dit veiliger was? Heeft hij gelijk?

<details>

<summary>Antwoord</summary>

Nee. De invoer komt nog altijd ongefilterd in de query, dus de injectie werkt gewoon. `LIMIT 1` beperkt alleen het aantal rijen dat terugkomt — het houdt de aanval niet tegen. Zolang jij de query-syntax kunt herschrijven, kun je ook die limiet weer weghalen.

</details>

## 2. Run (Uitvoeren)

Start het lab en vul een paar geldige ID's in.

<DvwaLab module="sql_injection" level="high" />

Vul achtereenvolgens `1`, `2` en `3` in en observeer telkens het resultaat.

## 3. Investigate (Onderzoeken)

Probeer nu je payload van het Low level: `1' OR '1'='1`.

**Vraag:** Hoeveel gebruikers zie je? Vergelijk dit met Low — wat is er anders, en wat in de query uit §1 veroorzaakt dat verschil?

<details>

<summary>Antwoord</summary>

Je ziet maar **1 gebruiker** in plaats van alle 5. De `LIMIT 1` aan het eind van de query kapt het resultaat af, ook al is de `OR`-conditie geldig.

De query wordt:
`SELECT ... WHERE user_id = '1' OR '1'='1' LIMIT 1`

De database vindt alle rijen, maar geeft er maar één terug. Hoe zorg je ervoor dat `LIMIT 1` genegeerd wordt? In SQL kun je de rest van een regel onzichtbaar maken voor de parser.

</details>

## 4. Modify & Make (Aanpassen & Maken)

Je weet dat `LIMIT 1` de output beperkt. Jouw doel: schakel `LIMIT 1` uit zodat alle gebruikers zichtbaar worden.

In SQL kun je alles na een bepaald teken laten negeren — vergelijkbaar met hoe `//` een commentaar start in JavaScript.

<details>

<summary>Tip</summary>

In SQLite (de database achter dit lab) start een commentaar met `-- ` — twee streepjes gevolgd door een spatie. Alles daarna op dezelfde regel wordt genegeerd. Zet dit aan het einde van je payload, zodat `LIMIT 1` buiten de query valt.

</details>

<details>

<summary>Antwoord</summary>

Vul in: `1' OR '1'='1' -- ` (let op de spatie achter de streepjes).

De database ziet dan:
`SELECT ... WHERE user_id = '1' OR '1'='1' -- ' LIMIT 1`

Alles vanaf `-- ` (inclusief het afsluitende quootje én `LIMIT 1`) wordt genegeerd. Alle 5 gebruikers verschijnen.

</details>

## 5. ✓ Wat moest je zien?

:::tip[Controle]
- Er verschijnt een lijst met **alle 5 gebruikers**, ondanks de `LIMIT 1`.
- Alles na `-- ` in jouw payload wordt door de database genegeerd — inclusief `LIMIT 1`.
- De `LIMIT 1` beperkte de output, maar de injectie zelf was er gewoon nog.

Zie je maar één resultaat? Controleer of je `-- ` mét de afsluitende spatie hebt getypt.
:::

## 6. Er gaat iets mis...

Je probeert `1' OR '1'='1' #` (met een hekje als commentaar) en krijgt geen resultaten of een SQL-fout.

Dat komt door de database. In **MySQL** start een commentaar met `#` óf met `-- `, maar dit lab draait op **SQLite**, en daar bestaat het `#`-commentaar niet. SQLite kent alleen `-- ` (twee streepjes + spatie). Het hekje blijft dus gewoon in de query staan en breekt de syntax.

Gebruik hier dus `1' OR '1'='1' -- `. De afsluitende spatie is belangrijk: zonder die spatie ziet SQLite geen commentaar. Omdat een spatie aan het einde van een invoerveld makkelijk wegvalt, controleer je die het beste nog even.
