# File Upload — Low

<LabBadge status="deels" />

<Ethiek />

Websites hebben vaak een functie om afbeeldingen te uploaden. Een slecht beveiligde upload is een van de snelste manieren voor een aanvaller om de server over te nemen.

<Voorkennis
  items={[
    {to: '/docs/http_leren', label: 'HTTP-headers en de Content-Type'},
  ]}
/>

> **Labbeperking:** Het lab simuleert de upload met twee velden (bestandsnaam en inhoud) en vertelt je wat de server met dat bestand zou doen. Het echt uitvoeren van een geüploade web shell — naar de URL navigeren en `whoami` zien — vraagt een [lokale DVWA-installatie](/docs/dvwa_installatie).

## 1. Predict (Voorspel)

Wanneer je op het Low level uploadt, doet de server dit:

```php
$target_path  = "../../hackable/uploads/";
$target_path .= basename( $_FILES[ 'uploaded' ][ 'name' ] );

move_uploaded_file( $_FILES[ 'uploaded' ][ 'tmp_name' ], $target_path );
```

**Vraag:** Dit script is bedoeld voor afbeeldingen. Wat gebeurt er als je een bestand `shell.php` met PHP-code erin uploadt? Wordt dat geweigerd?

<details>

<summary>Antwoord</summary>

Nee, de server weigert niets. Het script verplaatst elk bestand — ongeacht het type — naar een publiek toegankelijke map (`/hackable/uploads/`). Op een echte server voert de webserver jouw PHP-code uit zodra je naar `http://localhost/hackable/uploads/shell.php` navigeert. Met één bestand heb je een **web shell**.

</details>

## 2. Run (Uitvoeren)

Start het lab. Je typt een bestandsnaam en de inhoud; het lab simuleert de upload en toont wat de server ermee doet.

<DvwaLab module="file_upload" level="low" />

Vul als bestandsnaam `foto.jpg` in met wat tekst als inhoud en klik op Uploaden. Bekijk het pad in de melding waar het bestand "opgeslagen" wordt.

## 3. Investigate (Onderzoeken)

Vul nu `test.txt` in als bestandsnaam en klik opnieuw op Uploaden.

**Vraag:** Accepteert de server het tekstbestand? Wat zegt dat over de controles op het bestandstype?

<details>

<summary>Antwoord</summary>

Ja, de server accepteert elk bestand zonder controle. Het pad in de melding laat zien dat alle uploads in dezelfde publiek toegankelijke map belanden — of het nu een foto, tekstbestand of uitvoerbaar script is.

</details>

## 4. Modify & Make (Aanpassen & Maken)

Bied een kwaadaardig PHP-bestand aan de server aan.

<details>

<summary>Tip</summary>

Vul als bestandsnaam `shell.php` in en als inhoud:
`<?php echo system('whoami'); ?>`

</details>

<details>

<summary>Antwoord</summary>

1. Typ `shell.php` als bestandsnaam en `<?php echo system('whoami'); ?>` als inhoud.
2. Klik op Uploaden. Het lab accepteert het bestand en waarschuwt dat dit een PHP-bestand is dat op een echte server uitvoerbaar zou zijn, met de URL erbij.
3. Op een echte DVWA navigeer je naar die URL en zie je de accountnaam van de webserver — jouw code is dan uitgevoerd.

</details>

## 5. ✓ Wat moest je zien?

:::tip[Controle]
- Het lab accepteert `shell.php` zonder foutmelding.
- Bij een `.php`-bestand verschijnt een gele waarschuwing dat het op een echte server uitvoerbaar zou zijn, met de upload-URL.
- Er is geen enkele controle op het bestandstype: alles wordt geaccepteerd.

Zie je de waarschuwing niet? Controleer of je bestandsnaam echt op `.php` eindigt.
:::

## 6. Er gaat iets mis...

Je verwacht in het lab de output van `whoami` te zien, maar die komt niet. Dat klopt: het lab voert het bestand niet echt uit — het toont alleen dat de upload zou slagen en waar het bestand terecht zou komen. Het daadwerkelijk uitvoeren gebeurt pas op een echte server, wanneer je in je browser naar `/hackable/uploads/shell.php` navigeert. Let er dan op dat je de publieke URL gebruikt, niet het relatieve serverpad uit de melding.
